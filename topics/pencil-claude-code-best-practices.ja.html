pen.dev × Claude Code
ベストプラクティス実践全景ガイド

pen.dev はエディタ内に常駐する AI デザインキャンバス、Claude Code はターミナルで自律動作するコーディングエージェント。両者を MCP（Model Context Protocol）で接続することで、「デザインの文脈欠落ゼロ」の直結パイプラインが完成します。公式ドキュメントと現場の実践知見を統合した即戦力ガイドです。

はじめに 00

なぜ pen.dev + Claude Code なのか

解決する本質的課題：デザインとコードの断絶

従来の開発フローでは、デザイナーが Figma で作成したデザイン稿を開発者が目視でコードに書き起こしていました。マージンの微妙なズレ、フォントウェイトの誤解、未定義の hover 状態などにより、完成品が「デザイン稿と似て非なるもの」になりがちでした。

汎用 AI コーディングツールもこの問題を完全には解決できませんでした。個別のプロジェクト固有のデザインシステムやブランドカラー、余白ルールを把握できないため、Web上の一般的なパターンを継ぎ接ぎした「それっぽい」コードしか出力できなかったためです。

この組み合わせがもたらすブレイクスルーpen.dev はデザインファイルをコードと同じリポジトリ（.pen ファイル）で管理し、Claude Code は MCP 経由でキャンバス上の 正確な座標、トークン、階層構造 を直接読み取ってコードを生成します。画像からの推測ではなく、構造化データとしての読み込みです。自然言語で UI を生成 → Git で管理 → 一言でコードへ変換するこの新しい体験は「Vibe Design」と呼ばれています。

機能と役割の分担

ツール・要素提供される機能
pen.dev無限キャンバス、コンポーネント/変数/スロットシステム、Figma インポート、AI チャット、.pen 形式、ヘッドレス CLI
Claude Code自律型コーディングエージェント：複数ファイル読み書き、コマンド実行、Plan モード、Skills、MCP 拡張
MCPブリッジプロトコル：execute、get_app_state、get_screenshot、export_nodes、get_guidelines などのツール群を提供（詳細は pen.dev 公式ドキュメント を参照）

クイックスタート 01

環境構築の標準フロー

公式ドキュメントと DevelopersIO の実践チュートリアルに基づき、最も安定した導入手順を整理します（VS Code を例としますが、Cursor 等でも同様です）：

  1. Claude Code の導入とログイン: 公式推奨インストーラ curl -fsSL https://claude.ai/install.sh | bash を実行し、claude でブラウザ認証。トラブル時は 環境構築・認証トラブル急救マニュアル を参照。
  2. pen.dev 拡張機能のインストール: VS Code 拡張機能パネルで「pen.dev」（発行元: highagency.pencildev）を検索してインストール。
  3. pen.dev の起動: ステータスバー左下の鉛筆アイコンをクリック（表示されない場合は VS Code を再起動）。
  4. メールアドレス認証: 初回起動時にメールアドレスを入力し、受信した認証コードを入力してアクティベート。
  5. MCP 接続の確認: Claude Code を起動して /mcp を実行し、pencil が connected と表示されることを確認（設定は自動登録されます）。
  6. design.pen の作成: ワークスペースのルートディレクトリに配置し、コードと同一リポジトリで管理します。

.claude.json に自動生成される MCP 設定例：

"mcpServers": {
  "pencil": {
    "command": ".../highagency.pencildev-x.y.z/out/mcp-server-darwin-arm64",
    "args": ["--app", "visual_studio_code"],
    "type": "stdio"
  }
}
新規プロジェクト推奨フローdesign.pen を作成 → エディタで開く → アクティベート → コードと一緒にコミット。初回はキャンバスを右クリックして「Open Welcome File」でチュートリアルを一通り体験するのがおすすめです。
よくある3大注意点① AI機能の前提として claude のログインが必要です。② 自動保存機能は現在ないため、こまめに Cmd/Ctrl + S を押してください。③ Codex 利用時は config.toml のバックアップを推奨します。
クイックスタート 02

4大コアワークフロー

コミュニティの実践知見から、以下の4つの再利用可能なワークフローが確立されています：

WORKFLOW A
自然言語プロトタイピング (Vibe Design)

Claude Code に数行の要件を伝えるだけで、ページ全体のデザインを自動生成。キャンバス上で手動微調整を行います。旅行写真アルバム、ベーカリー注文画面、カフェ管理ダッシュボード、地域掲示板、社員ポータルの5画面で実用レベルの出力が確認されています。

要件入力 → AIが .pen 生成 → キャンバス微調整 → Git コミット
WORKFLOW B
デザイン → コード生成

キャンバスが完成したら、「このデザインから Next.js ページを生成して」と指示。Claude Code が正確な構造と Design Token を読み取ってコードを出力します。React/Vue/Tailwind/shadcn-ui などの技術スタックを指定すると最高精度の結果が得られます。

キャンバスデザイン → Cmd/Ctrl+K → スタック指定で生成 → レビュー & マージ
WORKFLOW C
コード → デザイン逆生成

既存の src/components/Button.tsx などのコードをキャンバス上にコンポーネントとして復元。「src/components の Button コンポーネントを再現して」と指示することで、レガシーコードからデザインドラフトを逆生成できます。

コード読み込み → キャンバスに再現 → ビジュアル改善 → コード書き戻し
WORKFLOW D
双方向同期 ＋ Git 単一信頼源 (SSOT)

CSS 変数と pen.dev の変数を双方向同期。「globals.css から pen.dev 変数を作成して」。コードと .pen を同一コミットで管理することで、実装とデザインの乖離（Drift）をゼロに抑えます。

変数同期 → デザイン & コード並行修正 → 1コミットで完了

Workflow A の実証サンプル

既存プロジェクトのリニューアル実践

  1. デザイン生成: Claude Code に「設定画面のデザインを作成：ホワイトカードフォーム、AI分析設定、モデル選択ラジオボタン...」と指示し、.pen を生成。
  2. デザイン適用: 「このデザインを適用して」と指示するだけで、プロジェクトの既存コードにデザインが反映されます。
実践 03

実践プロンプト集

「ページ種別 ＋ コンテンツ一覧 ＋ カラー/トーン」の3要素 を含めたプロンプトが最も高い精度を発揮します。

ページ全体生成（3要素テンプレート）

基本テンプレート
[ページ種別 / ターゲット層] をデザインしてください [機能とコンテンツ一覧: モジュール1, モジュール2, モジュール3...] [配色とトーン: カラーパレット + 雰囲気の形容詞]
実例 · ベーカリー注文ページ
コミュニティベーカリーのオンライン注文ページをデザインしてください。 本日の焼きたてパン写真のカルーセル、カテゴリメニュー、受取時間選択、カート機能を含めてください。 クリーム色とブラウンを基調とした温かみのあるトーンで構成してください。
実例 · 売上ダッシュボード
個人経営カフェの売上管理ダッシュボードをデザインしてください。 日次売上棒グラフ、人気メニューランキング、在庫アラート、本日の予約リストを含めてください。 落ち着いたウォームブラウン系のカラーパレットで作成してください。

デザイン → コード変換（技術スタック指定）

コンポーネント単位
このボタンの React コンポーネントを作成してください このフォームの TypeScript 型定義を生成してください このカードを再利用可能なコンポーネントとしてエクスポートしてください
ページ単位 + スタック指定
Next.js (App Router) + Tailwind CSS でコードを生成してください shadcn/ui コンポーネントを使用してレイアウトを組んでください アイコンには Lucide Icons を使用してください

コード → デザイン逆生成

既存コンポーネントのインポート
src/components/Button.tsx から Button コンポーネントをキャンバスに再現してください コードベース内の LoginForm をこのデザインにインポートしてください

変数と Design Tokens の同期

双方向同期
globals.css から pen.dev の変数を作成してください pen.dev の変数で globals.css を更新してください CSS と pen.dev のタイポグラフィ変数を同期してください
実践 04

デザインシステムエンジニアリング

単一ページの生成にとどまらず、pen.dev と Claude Code を デザインシステムの構築・保守パイプライン として活用する実践手法です。

5段階アプローチ (create-design-system Skill)

段階目的と内容主なアクション
① 要件定義対象ユーザー、コアワークフロー、MVP の境界を明確化プラットフォーム（Web/Mobile）、トーン、5〜7画面の特定
② スタイル探索ビジュアルの方向性を探索ムードやキーワードから2〜3の方向性を提示、参考画像の投入
③ ムードボード.pen 内に2〜3のムードボードを作成カラーパレット、タイポグラフィスケール、基本コンポーネントの選定
④ コンポーネント集確定した方向性に基づきコンポーネントライブラリを構築Design Tokens を定義後、Button、Input、Card、Nav 等を作成
⑤ 画面組み立てコンポーネントをインスタンス参照して各画面を構築ダミーテキストではなく実データに近い文言を使用し画面を完成

エンタープライズ実例：Lullabot ブランドライブラリ

Lullabot 社の Jerad Bitner は、ブランドシステム全体を1つの再利用可能なデザインライブラリ（56のカラー変数、フォントトークン、4pxグリッド余白、16の共通コンポーネント）にパッケージ化しました。以降の新規プロジェクトでは常にこのライブラリをインポートして開発をスタートしています。

実践 05

高効率プロンプトパターン

具体性の原則

❌ 曖昧で非効率「いい感じのデザインにして」「フォームを追加して」「ページを作って」
✅ 具体的で高精度「ボタンの余白を 16px に広げ、色をプライマリブルーに変更して」「ログインフォーム：Email、Password、Remember me、送信ボタン」「3要素指定：種別 + 内容 + トーン」

反復ピラミッド（公式推奨のリズム）

  1. 骨格を構築 — 「ダッシュボードの全体レイアウトを作成」
  2. 構造を具体化 — 「サイドバーにナビゲーション項目を追加」
  3. 状態を肉付け — 「各ナビゲーション項目に hover 状態を追加」
  4. 最終調整 — 「余白を 8px グリッドに厳格に整列」
応用 06

高度な活用法

pen.dev CLI：ヘッドレス自動化

GUI なしでスクリプトから直接デザイン生成や画像書き出しを実行できます：

# コマンド1発でデザインファイルを生成
pen --out login.pen --prompt "Create a modern login page with email, password, social login"

# 既存デザインを更新して2倍解像度でPNG出力
pen --in dashboard.pen --out dashboard-v2.pen --prompt "Add a sidebar navigation"
pen --in design.pen --export hero.png --export-scale 2

CI/CD パイプライン連携

GitHub Actions で .pen の変更を検知し、自動で PNG プレビューを生成して PR に添付するワークフローを構築できます：

name: pen.dev Design Preview
on:
  pull_request:
    paths:
      - '**/*.pen'
jobs:
  design-preview:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm install -g @pen.dev/cli
      - name: Export modified .pen to PNG
        env:
          PEN_CLI_KEY: ${{ secrets.PEN_CLI_KEY }}
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          mkdir -p design-previews
          for f in $(git diff --name-only "origin/${{ github.base_ref }}"...HEAD -- '*.pen'); do
            [ -f "$f" ] || continue
            name=$(echo "$f" | tr '/' '_' | sed 's/\.pen$//')
            pen --in "$f" --export "design-previews/${name}.png" --export-scale 2
          done
      - uses: actions/upload-artifact@v4
        with:
          name: design-previews
          path: design-previews/
応用 07

落とし穴チェックリスト

よくある失敗と対策

落とし穴対策
要素がキャンバス上に散らばり AI が認識できない必ず名前付き Frame の中に要素を配置する（MCP は Frame 単位で読み取り）
レイヤー名が「Group 47」等のままセマンティックな命名（PrimaryActionButton 等）を行うことで AI が意図を正確に理解
視覚情報以外のコンテキスト不足インタラクション、レスポンシブ要件、アクセシビリティをコメントや指示に明記
巨大プロンプトで一括生成しようとする小さな単位で設計 → 生成 → 確認 → 洗練のサイクルを回す
保存を忘れて作業が消えるこまめに Cmd/Ctrl + S を押し、大きな変更前に Git コミット
.pen の手動直接編集による構文破損.pen ファイルは手書きせず、必ずエディタまたは MCP ツール経由で編集する
