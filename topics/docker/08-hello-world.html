08. 第一行魔法背后的秘密

在所有编程语言里，第一课永远是打印 "Hello World"。在 Docker 的世界里也有这么一个仪式。但是，当你敲下这行命令时，背后发生的事情远比简单的 print("hello") 复杂和神奇得多。今天，我们就来用显微镜观察这第一行魔法。

一、运行！见证魔法时刻

打开你的终端，自信地敲下这行命令：

docker run hello-world

如果你是第一次运行，你会看到一长串极其经典的输出，仔细看这段终端输出：

Unable to find image 'hello-world:latest' locally
latest: Pulling from library/hello-world
c1ec31eb5944: Pull complete 
Digest: sha256:d000bc5694d4d8fc3bc09bf2cc72464161f5f3e790a6e30ebf0653df37ec42a8
Status: Downloaded newer image for hello-world:latest

Hello from Docker!
This message shows that your installation appears to be working correctly.

To generate this message, Docker took the following steps:
 1. The Docker client contacted the Docker daemon.
 2. The Docker daemon pulled the "hello-world" image from the Docker Hub.
 3. The Docker daemon created a new container from that image which runs the executable that produces the output you are currently reading.
 4. The Docker daemon streamed that output to the Docker client, which sent it to your terminal.

二、这 10 秒钟里，到底发生了什么？

其实，官方的这段欢迎词已经剧透了全过程。让我们用一张时序图来把这个“暗箱操作”剥光：

sequenceDiagram
    participant U as User (Client)
    participant D as Docker Daemon (引擎)
    participant R as Registry (远程仓库)
    
    U->>D: 1. 执行 docker run hello-world
    D-->>D: 2. 检查本地有没有这个镜像？(没有)
    D->>R: 3. 去远程仓库拉取(Pull)镜像
    R-->>D: 4. 返回 hello-world 镜像数据
    D-->>D: 5. 实例化镜像，创建并启动容器
    D->>U: 6. 容器里的程序运行，打印 Hello 文本到屏幕
    D-->>D: 7. 程序执行结束，容器自动退出(Exited)

拆解解析：

  1. 找货 (Unable to find locally)：Docker 首先会在你的电脑硬盘上找 hello-world 这个“安装包”（镜像）。因为你是第一次跑，所以没找到。
  2. 进货 (Pulling from library)：找不到怎么办？Docker 就会去云端的镜像源（Registry）下载。那行 c1ec31eb5944: Pull complete 代表下载了一层(Layer)数据。这里引出了 Docker 核心概念——镜像分层机制，以后我们会详细讲。
  3. 开箱运行 (Hello from Docker)：下载好镜像后，Docker 引擎用这个镜像创建了一个独立的“集装箱”（容器），并在里面运行了预设的程序（一个打印文本的 C 语言二进制程序）。程序把字打在屏幕上。
  4. 光荣下岗：打印完这段话，程序执行结束了，这个容器也就随之停止了运行，完成历史使命。

三、查户口：认识两个核心命令

魔法表演完了，我们怎么证明它真的来过？用下面两个命令。

1. 查看本地镜像：docker images

docker images
# 输出：
# REPOSITORY    TAG       IMAGE ID       CREATED        SIZE
# hello-world   latest    d2c94e258dcb   10 months ago  13.3kB
  • REPOSITORY: 镜像名。
  • TAG: 标签，类似版本号。latest 代表最新版。
  • IMAGE ID: 镜像的唯一身份证号。
  • SIZE: 惊人的 13.3kB！是的，这个镜像里没装完整的 Linux 系统，只有几行代码编译出的极小可执行文件。这也证明了容器极度轻量的特性。

2. 查看容器尸体：docker ps -a

docker ps -a
# 输出：
# CONTAINER ID   IMAGE         COMMAND    CREATED         STATUS                     PORTS     NAMES
# a1b2c3d4e5f6   hello-world   "/hello"   2 minutes ago   Exited (0) 2 minutes ago             clever_turing

注意必须要加 -a (all) 参数，因为 docker ps 默认只显示正在运行的容器，而 hello-world 打印完就退出了（Exited）。

  • CONTAINER ID: 容器的身份证号，和 IMAGE ID 不同！影分身（容器）和真身（镜像）各有各的 ID。
  • STATUS: Exited (0) 表示正常退出（0 是 Linux 的正常退出码）。
  • NAMES: Docker 很有意思，如果你不给容器起名字，它会自动用“形容词+著名科学家名字”给你随机生成一个名字，比如这里的 clever_turing（聪明的图灵）。
🎯 动手小测验：真正钻进一个容器

刚才的 hello-world 跑完就死了，不过瘾？试试启动一个真实的 Ubuntu 系统并进入交互模式：

docker run -it ubuntu bash

参数解释：-i (interactive) 保持输入流开启，-t (tty) 分配一个虚拟终端。bash 是要在容器里执行的命令。

敲下回车，你会发现你的终端提示符变了，比如变成 root@f8d2e8b1a3c4:/#。恭喜你，你已经钻进了一个完全隔离的 Ubuntu 世界！在这个黑盒子里你随便乱搞（比如 rm -rf /），都不会影响你自己的电脑。输入 exit 即可退出回城。

🚑 踩坑自救室
Q1: 为什么我又跑了一次 docker run hello-world，这次没有 "Unable to find..." 也没有拉取的过程了？
A: 因为第一次已经把镜像下载到本地了。Docker 非常聪明，第二次发现本地硬盘有货，直接就秒启动容器了。这正是容器“快”的体现。
Q2: 为什么我的镜像源配好了，还是报 "pull access denied" 或 "repository does not exist"？
A: 检查你敲的镜像名拼写对不对。如果你拼成了 helo-world，Docker 会去仓库找，找不到就会报不存在。如果是私有镜像，可能是你没执行 docker login 登录。
🌟
老鸟技巧：run = create + start 很多新手以为 docker run 是一个基础指令。其实它是一个复合指令（组合拳）。
它等价于：先执行 docker create [镜像]（造出一个停泊在港口的容器），再执行 docker start [容器ID]（点火启动它）。
如果在 run 的时候加上 --pull=always，甚至还能包含自动拉取最新镜像的动作。
