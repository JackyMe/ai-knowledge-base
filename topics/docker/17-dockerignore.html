第17集：.dockerignore 避坑指南

我们来讲个鬼故事：小明进公司的第一天，自信满满地敲下 docker build -t myapp .，然后去倒了杯水。回来一看，命令行还在疯狂滚动，终端提示：Sending build context to Docker daemon 12.5GB。小明傻眼了：“我这项目代码才 5 兆啊，怎么传了 12 个 G？”

经过排查，原来他本地有一个装满小电影的 temp/ 目录和 10GB 臃肿的 node_modules，全被 Docker 吸进去了！这就是没有 .dockerignore 的惨痛代价。

1. 什么是 Build Context（构建上下文）？

当你执行 docker build -t xxx . 时，那个点 . 指的就是上下文目录。因为 Docker 是由 C/S 架构组成的（你敲命令的 CLI 是客户端，真正在跑的 Docker 引擎是服务端），客户端在开始构建前，会把这整个目录打包，发送给 Docker 引擎。

如果你不加限制，它就会把 .git 历史、本地测试产生的海量日志、巨大的依赖文件夹全送过去，导致：

  1. 慢： 发送几十 GB 数据要半天。
  2. 大： 打出来的镜像变成了巨无霸。
  3. 险： 一不小心把包含密码的 .env 文件打进镜像，传到公网，底裤都被看穿。

2. 救星驾到：.dockerignore

它的用法和 Git 里的 .gitignore 一模一样。只要在 Dockerfile 同级目录下新建一个 .dockerignore 文件，把不要的东西写进去即可。

3. 语法解析：通配符与取反

里面支持简单的正则匹配：

  • *.log：忽略所有 .log 结尾的文件。
  • temp?：忽略 temp1、tempa，问号匹配单个字符。
  • **/*.md：忽略任意层级目录下的 markdown 文件。
  • !README.md：感叹号表示取反（白名单）。即使前面忽略了所有的 *.md，加上这一句，README.md 依然会被保留。
  • # 这是一行注释：井号开头是注释。

💡
老鸟技巧 (Pro-Tip)：强制不使用缓存

有时候你明明修改了代码，但 Docker 觉得文件没变，使用了缓存，导致你的改动没生效。除了排查 .dockerignore，你可以在构建时加上 --no-cache 参数强制重新拉取/编译所有东西：
docker build --no-cache -t myapp .

🚨 踩坑自救室
Q1: 为什么提示 `COPY failed: file not found`？
A: 99% 的可能性是你把需要的文件写进 .dockerignore 里了！比如你在 Dockerfile 里写了 COPY config/setting.json .，但在忽略文件里写了 config/。此时上下文里根本没有这个文件，Docker 找不着自然会报错。
Q2: 为什么我的 .env 里的数据库密码泄露了？
A: 你在 COPY . . 的时候，把 .env 文件也拷贝进镜像里了，并且推到了 Docker Hub 上。别人只要 pull 下来，启动容器或者查看镜像内容，密码就一览无余。务必把包含机密的本地配置文件加入 .dockerignore！运行时的配置应该通过环境变量 -e 或者后面讲的配置中心传入。
