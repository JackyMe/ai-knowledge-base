06. Mac & Linux 환경 구축 가이드

이전 레슨에서는 Windows 사용자를 위한 설치 가이드를 살펴보았습니다. 이번에는 실무 개발자들이 가장 많이 사용하는 양대 운영체제인 macOS와 Linux에서 Docker를 우아하게 구축하는 방법을 알아봅니다. 두 운영체제는 Docker와 태생적으로 친숙하지만(특히 Linux는 Docker의 홈그라운드입니다), 여전히 주의해야 할 함정들이 존재합니다.

1. Mac 사용자: 직관적이고 깔끔한 GUI 기반 설치

Mac 환경에서는 Docker 엔진뿐만 아니라 직관적인 GUI 대시보드와 경량 Linux VM이 함께 패키징된 Docker Desktop for Mac을 사용하는 것이 정석입니다.

🟢 방법 1: 공식 웹사이트 다운로드 (가장 권장)

1. Docker 공식 사이트에 접속하여 자신의 Mac 칩셋 아키텍처에 맞는 패키지를 정확히 선택합니다.

  • M1/M2/M3/M4 등 Apple 실리콘 탑재 Mac: Mac with Apple silicon 선택.
  • 구형 Intel CPU 탑재 Mac: Mac with Intel chip 선택.

주의: 칩셋을 잘못 선택하면 Rosetta 에뮬레이션으로 인해 CPU 점유율이 비정상적으로 치솟거나 구동되지 않습니다. Mac 화면 좌측 상단 애플 마크 -> '이 Mac에 관하여'에서 칩 종류를 확인하세요.

2. 다운로드된 .dmg 파일을 열고, Docker 아이콘을 Applications(응용 프로그램) 폴더로 드래그 앤 드롭합니다.

3. 런치패드에서 Docker를 실행하고 사용권 계약에 동의합니다. 상단 메뉴바에 고래 아이콘이 나타나고 애니메이션이 멈추며 초록색 "Docker Desktop is running" 상태가 되면 완료됩니다.

🟡 방법 2: Homebrew 패키지 매니저로 설치 (CLI 애호가 추천)

터미널 작업에 익숙하고 이미 Homebrew를 사용 중이라면 명령어 한 줄로 설치할 수 있습니다.

brew install --cask docker

설치 후 최초 1회는 응용 프로그램 폴더에서 Docker 앱을 직접 클릭하여 초기 보안 권한 부여를 완료해야 합니다.

💡
실무 팁: Mac 성능 최적화 핵심 설정 상단 메뉴바의 고래 아이콘 -> Settings(설정) -> Resources(리소스) 메뉴에서 다음을 조정하세요.
1. Memory (메모리): 기본 2GB에서 4GB~8GB 정도로 넉넉히 할당하여 대규모 빌드 시 멈춤 현상을 방지합니다.
2. Virtual disk limit (가상 디스크 크기): Mac 본체 저장공간 여유에 맞춰 60GB~120GB 수준으로 설정합니다.
3. VirtioFS 활성화: General 설정에서 파일 공유 메커니즘을 VirtioFS로 선택하면 호스트-컨테이너 간 파일 입출력(I/O) 성능이 획기적으로 향상됩니다.

2. Linux 사용자: 네이티브 커널의 압도적 성능

Linux는 Docker 엔진이 탄생한 본진이므로 하드웨어 가상화 계층 없이 커널을 직접 호출하여 최고의 성능을 발휘합니다. 하지만 초보자들이 가장 많이 저지르는 실수가 있습니다.

⚠️
주의: OS 기본 저장소 패키지를 직접 설치하지 마세요! sudo apt install docker 또는 sudo yum install docker 명령을 그대로 실행하면 안 됩니다. 배포판 공식 기본 저장소에 포함된 Docker 버전은 수년 전 구형 버전인 경우가 많아 최신 Dockerfile 문법과 보안 패치가 누락되어 있습니다.
🔥 권장 방식: 공식 자동화 원클릭 스크립트

Ubuntu, Debian, CentOS, Rocky Linux 등 다양한 배포판에서 최신 안정화 버전을 자동으로 인식하여 설치해 주는 공식 스크립트를 사용합니다.

# 1. 공식 설치 스크립트 다운로드
curl -fsSL https://get.docker.com -o get-docker.sh

# 2. 루트 권한으로 스크립트 실행
sudo sh get-docker.sh

약 1~2분 후 최신 Docker Engine - Community 버전 설치가 자동으로 완료됩니다.

설치 직후 반드시 실행해야 하는 필수 2단계 설정

Linux에서 설치를 마친 후 일반 사용자로 docker ps를 실행하면 permission denied 에러가 발생합니다. 보안상 Docker 데몬 소켓(/var/run/docker.sock)은 기본적으로 root 권한으로만 접근할 수 있기 때문입니다.

# 1. 현재 로그인된 사용자를 docker 사용자 그룹에 추가 (sudo 생략 설정)
sudo usermod -aG docker $USER

# 2. 시스템 부팅 시 Docker 데몬 자동 시작 등록 및 즉시 실행
sudo systemctl enable docker
sudo systemctl start docker

중요: 사용자 그룹 추가 후에는 반드시 SSH 세션을 로그아웃했다가 다시 로그인하거나 su - $USER를 실행해야 그룹 권한 변경 사항이 셸에 적용됩니다.

🚑 트러블슈팅 구조대: Linux 환경 단골 오류
Q1: "permission denied while trying to connect to the Docker daemon socket" 에러 발생
A: 사용자 계정이 docker 그룹에 포함되지 않았거나, 그룹 추가 후 재로그인하지 않은 상태입니다. sudo usermod -aG docker $USER 실행 후 재접속하세요.
Q2: "Cannot connect to the Docker daemon at unix:///var/run/docker.sock" 에러 발생
A: Docker 백그라운드 서비스가 구동되지 않은 상태입니다. sudo systemctl status docker로 상태를 확인하고 sudo systemctl start docker로 기동하세요. 만약 기동 실패 시 sudo journalctl -u docker.service로 설정 파일(daemon.json 등)의 문법 오류 로그를 확인하세요.
Q3: WSL2 내부에서 systemctl 명령어 실행 시 "System has not been booted with systemd" 에러가 뜹니다.
A: 구버전 WSL2는 systemd 대신 init 시스템을 사용합니다. sudo service docker start 명령을 사용하거나, /etc/wsl.conf 파일에 [boot]\nsystemd=true 설정을 추가하세요.

심화 팁: 엔터프라이즈 환경의 대안 도구 Podman RHEL이나 CentOS 계열 기업 환경에서는 데몬리스(Daemonless) 및 루트리스(Rootless) 아키텍처를 지원하는 Podman도 널리 활용됩니다. CLI 명령어가 Docker와 100% 호환되므로(alias docker=podman 가능) 보안 요건이 엄격한 금융/공공 인프라에서 유용한 선택지가 될 수 있습니다.
