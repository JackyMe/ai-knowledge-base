32. 护城河：.env保护密码

设想一个毛骨悚然的场景：

周五晚上，你写完了酷炫的 docker-compose.yml，里面明晃晃地写着 POSTGRES_PASSWORD=my_super_secret_pwd_123。你顺手 git push 到了开源的 GitHub 仓库。三小时后，国外的爬虫机器人扫描到了你的密码，连上你的数据库，删光了所有数据，留下一张勒索比特币的勒索信。周末泡汤了。

绝对、永远、不要在代码仓库里提交明文密码！ 今天，我们就来修建这道安全护城河——.env 文件。

一、什么是 .env 文件？它在哪？

.env 就是一个简单的文本文件，里面全是键值对（Key-Value）。当你在 docker-compose.yml 所在的目录下运行 docker compose up 时，Docker Compose 会像吸尘器一样自动把 .env 文件里的变量全吸进来。

我们把刚才的 docker-compose.yml 改造一下：

# docker-compose.yml 的一部分
services:
  db:
    image: postgres:14-alpine
    environment:
      - POSTGRES_USER=${DB_USER}
      - POSTGRES_PASSWORD=${DB_PASS}
      - POSTGRES_DB=${DB_NAME:-default_db} # 带默认值的语法

然后在同级目录创建一个 .env 文件：

# .env 文件内容
DB_USER=admin
DB_PASS=S3cr3t!2024
DB_NAME=myapp_prod
💡
变量替换的花式语法
  • ${VAR}: 普通替换。找不到就为空。
  • ${VAR:-default}: 如果 VAR 没设置，就用 default 兜底。
  • ${VAR:?err_msg}: 强制要求。如果没设置，Compose 直接报错并显示 err_msg，拒绝启动。防止你忘配密码！

二、最关键的一步：.gitignore

光分离出来没用，如果你把 .env 也 git push 上去，那不等于把钥匙挂在门把手上吗？

立刻、马上，在你的项目根目录的 .gitignore 文件里加上这一行：

# .gitignore
.env

这样 Git 就会装作看不见这个文件。那别人拉下代码不知道要配什么环境变量怎么办？

业界标准做法：创建一个 .env.example 文件，里面写上假数据提交到 Git：

# .env.example (提交到Git)
DB_USER=root
DB_PASS=your_password_here
DB_NAME=test_db

新同事把代码拉下来，只要 cp .env.example .env，填上他自己的密码就能跑了。

三、多环境：开发、测试与生产

如果有多个环境怎么办？我们可以建多个环境文件，比如 .env.dev 和 .env.prod。

启动的时候，通过 --env-file 参数来指定你要吸哪个文件：

# 用生产环境配置启动
$ docker compose --env-file .env.prod up -d
⚔️ 环境变量的“排位赛” (优先级)

如果到处都配了同一个变量，听谁的？优先级从高到低排列：

  1. 最高：你在终端执行命令时临时加的 DB_PASS=123 docker compose up
  2. 第二：Compose 文件里的 environment: 写死的值
  3. 第三：被指定的 .env 文件里的值
  4. 最低：Dockerfile 里面 ENV 指令写的值

四、验证：到底读进去没有？

启动后，想检查容器里到底是不是这个密码？别去猜，直接用放大镜看：

# 查看指定服务的真实环境配置
$ docker compose exec db env | grep POSTGRES

# 或者用底层命令看容器的配置
$ docker inspect myapp-db-1 -f "{{.Config.Env}}"
🚑 踩坑自救室
Q1: 密码里有特殊的符号，比如 $ 或者 #，解析出错了？
在 .env 文件中，如果你有 $，Compose 可能会以为是变量。解决办法是：1. 用单引号引起来 DB_PASS='my$pwd'。2. 把 $ 转义写成 $$。另外，# 号开头的会被当成注释！
Q2: 已经改了 .env 文件，但重启不生效？
如果你只用了 docker compose restart，环境变量是不会重新计算的！你必须使用 docker compose up -d，Compose 发现环境变量变了，才会自动帮你重建容器。

老鸟技巧 (Pro-tip)：在真正严肃的金融级生产环境中（比如用 Docker Swarm 或 Kubernetes），连 .env 文件都不够安全。我们会使用 Docker Secrets 或外部密钥管理库（如 AWS Secrets Manager / HashiCorp Vault），变量在内存里直接挂载为只读文件，黑客把整个机器磁盘抱走也拿不到密码！
