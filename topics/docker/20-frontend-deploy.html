第20集：优雅上线 Vue / React

无数前端新人学会了用 npm run serve 或 npm start 跑起项目，于是他们把这个习惯带到了 Docker 里，写出这样的 Dockerfile：

FROM node:18
WORKDIR /app
COPY . .
RUN npm install
CMD ["npm", "run", "serve"]  # ❌ 灾难！

大错特错！开发服务器包含了热更新代码、未压缩的源码、几十兆的调试模块。这不仅会导致镜像巨大（轻松突破 1.2 GB），而且在生产环境下性能极差、极不安全。真正的生产环境部署，我们需要使用多阶段构建 + Nginx 静态托管。

1. 黄金标准流程

  1. 构建阶段：在有 Node.js 环境的容器里，执行 npm run build，把 Vue/React 源码编译成普通的 HTML/CSS/JS 静态文件（通常在 dist 或 build 目录下）。
  2. 运行阶段：把编译好的那一点点静态文件，拷进一个干净轻量的 Nginx 服务器容器里。丢弃几百兆的 Node 环境和 node_modules。

结果：你的镜像体积会从 1.2GB 断崖式下跌到 25MB！

2. Vue / React 完美 Dockerfile 模板

利用 Docker 的“多阶段构建”（Multi-stage Build），我们可以在同一个文件里写两个 FROM。

📄 前端标准 Dockerfile (适用于 Vue/React)
# ==============================
# 阶段 1：构建环境 (命名为 builder)
# ==============================
FROM node:18-alpine AS builder
WORKDIR /app

# 优秀缓存写法：先装依赖
COPY package*.json ./
RUN npm ci 

# 拷入源码并编译打包
COPY . .
RUN npm run build 
# 注意：Vue 生成 dist 目录，React 生成 build 目录。请根据实际情况修改下面

# ==============================
# 阶段 2：生产运行环境
# ==============================
FROM nginx:alpine

# 把阶段1 (builder) 编译好的 dist 目录，拷到 nginx 默认的网页存放目录下
COPY --from=builder /app/dist /usr/share/nginx/html

# (可选) 拷贝自定义的 nginx 配置以支持前端路由
# COPY nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

3. 拯救前端路由：解决刷新 404 惨案

SPA（单页应用，如 Vue Router 的 history 模式）有一个通病：你访问 /about 路由时，如果不做配置，Nginx 会真的去硬盘上找 about.html，找不到就直接给你报 404。

解法：我们需要提供一个 nginx.conf，告诉 Nginx：找不到文件时，一律把入口的 index.html 扔给浏览器，让前端 JS 自己去解析路由。

📄 nginx.conf (支持 SPA 路由)
server {
    listen       80;
    server_name  localhost;

    location / {
        root   /usr/share/nginx/html;
        index  index.html index.htm;
        
        # 魔法指令：如果找不到文件，就回退到 index.html
        try_files $uri $uri/ /index.html;
    }

    # 可选：开启 gzip 压缩加速加载
    gzip on;
    gzip_min_length 1k;
    gzip_comp_level 6;
    gzip_types text/plain application/javascript application/x-javascript text/css application/xml text/javascript;
}

把这个文件放在 Dockerfile 同级目录，取消掉 Dockerfile 阶段2里 COPY nginx.conf ... 那行的注释即可。

老鸟技巧 (Pro-Tip)：前端环境变量注入

很多新手问：“怎么在 Docker 里把后端的 API 地址 VUE_APP_API_URL 动态传给前端？”。这是个伪命题！

因为前端代码最终是在用户的浏览器里运行的，不是在容器里。容器里的环境变量 ENV 浏览器根本看不见。正确的做法有三种：

  1. 构建时注入：在执行 npm run build 时传入，写死在静态文件里（推荐）。
  2. 通过 Nginx 反向代理：前端代码一律请求 /api/xxx，Nginx 配置 location /api/ { proxy_pass http://后端真实IP; }。彻底解决跨域和动态后端地址问题。
  3. 全局挂载 config.js：在 public 目录下放一个单独的 js 配置文件，运行时通过 Volumes 挂载覆盖它。
🚨 踩坑自救室
Q1: 部署后打开白屏，看浏览器控制台报 JS 文件找不到？
A: 通常是你的 Vue/React 项目配置（如 publicPath 或 base 属性）配错了。如果你的项目不部署在根域名（比如部署在 domain.com/myapp），必须在代码的打包配置里明确指定相对路径 ./ 或具体的子目录名。
Q2: 后端接口报错 CORS 跨域问题？
A: 强烈建议利用 Nginx 的同源策略反向代理来解决。前端不用再改跨域配置，直接把 nginx.conf 里加一段代理规则指向后端服务即可。
