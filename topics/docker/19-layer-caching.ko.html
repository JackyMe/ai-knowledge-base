제19레슨: 그림으로 보는 레이어 캐시의 마법 (매우 중요!)

어떤 개발자의 docker build는 단 2초 만에 끝나는데, 왜 다른 사람의 빌드는 5분이나 걸릴까요? 그 핵심 비밀은 바로 Dockerfile을 제대로 작성하여 Docker의 "레이어 캐시 메커니즘"을 우아하게 활용하고 있는가에 있습니다.

이 내용은 Docker 중급자로 도약하는 과정에서 가장 중요한 핵심 레슨 중 하나입니다.

1. 이미지의 레이어(Layer) 구조란 무엇인가?

제18레슨 빌드 로그에서 본 것처럼 빌드는 각 단계(Step 1/7 등)별로 차례대로 실행됩니다. Docker 이미지는 마치 크레이프 케이크처럼 얇은 층들이 차곡차곡 쌓여 있는 구조입니다. Dockerfile 내의 단순 메타데이터 설정을 제외하고, RUN, COPY, ADD와 같은 명령어가 실행될 때마다 새롭고 독립된 레이어가 생성됩니다.

2. 캐시 무효화의 연쇄(스노우볼) 효과

Docker는 매우 지능적이어서 빌드 시 각 레이어를 검사합니다. "이 레이어의 명령어와 입력 파일이 이전과 완전히 동일한가?"를 확인하여 변경사항이 없다면(예: COPY 대상 파일 내용이 바뀌지 않음) 해당 단계를 재실행하지 않고 이전에 빌드된 기존 레이어를 그대로 재사용합니다(로그에 CACHED 표시).

🚨 하지만 치명적인 철칙이 있습니다: 특정 레이어에서 캐시가 무효화되면(파일 수정 등), 그 레이어를 포함한 이후의 모든 하위 레이어의 캐시가 전부 무효화되어 처음부터 다시 실행됩니다!

3. 잘못된 작성법 vs 모범적인 작성법

❌ 잘못된 작성법: 초보자가 자주 범하는 실수
FROM node:24-alpine
WORKDIR /app
# 전체 소스코드와 package.json을 한 번에 통째로 복사
COPY . .
# 그 후 의존성 패키지 설치
RUN npm install
CMD ["node", "server.js"]

치명적인 결과: 오늘 server.js 파일에서 문구 한 줄만 수정했더라도, COPY . . 레이어에서 파일 변경이 감지되어 캐시가 깨집니다. 그 결과 바로 뒤에 오는 RUN npm install의 캐시도 연쇄적으로 무효화되어, 인터넷에서 수십 MB의 node_modules를 매번 다시 다운로드하느라 몇 분씩 시간이 낭비됩니다!

✅ 모범적인 작성법: 단계별 분할 복사 기법
FROM node:24-alpine
WORKDIR /app
# 1단계: 패키지 정의 파일만 먼저 복사
COPY package.json .
# 2단계: 의존성 패키지 설치
RUN npm install
# 3단계: 나머지 비즈니스 소스코드 복사
COPY . .
CMD ["node", "server.js"]

짜릿한 경험: server.js를 수정하더라도 package.json에는 아무런 변화가 없습니다. 따라서 1단계 COPY와 2단계 RUN npm install 모두 완벽하게 캐시를 탑니다! 오직 3단계 COPY . .에서만 코드 차이점이 복사되므로 단 0.1초 만에 빌드가 끝납니다. 빌드 시간이 5분에서 2초로 획기적으로 단축됩니다!

4. 레이어 수 최적화: RUN 명령어의 체이닝 기법

앞서 설명했듯이 RUN 명령어를 작성할 때마다 새로운 레이어가 생성되며 이미지 크기가 증가합니다. 시스템 패키지를 설치할 때는 && 연산자로 명령어를 하나로 연결하고, 마지막에 반드시 캐시 파일(예: apt 캐시)을 정리해 주세요. 다음 레이어에서 rm을 실행하더라도 이전 레이어에 기록된 용량은 줄어들지 않기 때문입니다(Git 커밋 기록과 동일한 원리입니다).

# 완벽한 한 줄 설치 모범 예시
RUN apt-get update \
    && apt-get install -y --no-install-recommends vim curl net-tools \
    && rm -rf /var/lib/apt/lists/*
💡
프로의 팁 (Pro-Tip): BuildKit과 캐시 마운트

npm, pip, Maven과 같은 패키지 매니저는 레이어를 아무리 잘 구성해도 다른 서버 머신에서는 첫 빌드 시 전체 다운로드가 필요합니다. Docker의 차세대 빌드 엔진인 BuildKit은 캐시 마운트를 지원합니다: RUN --mount=type=cache,target=/root/.npm npm install. 이를 사용하면 다운로드된 패키지 캐시가 전용 보안 영역에 보존되어 다음 빌드 시 상상을 초월하는 속도로 완료됩니다!

🚨 트러블슈팅 응급실
Q1: 코드를 전혀 수정하지 않았는데도 왜 COPY 단계에서 캐시가 깨질까요?
A: 파일의 속성과 타임스탬프를 확인해 보세요. Docker는 내용 해시(Hash)뿐만 아니라 일부 환경에서는 권한이나 타임스탬프 변화도 감지합니다. 더 흔한 원인은 호스트에서 생성된 로그 파일이나 임시 파일이 .dockerignore에 등록되지 않아 무관한 파일 변경이 캐시를 무효화시키는 경우입니다.
