Lesson 18: Hands-on: Packaging a Web App

No matter how much theory you read, nothing beats hands-on practice. Today, we will write a minimalist Node.js API from scratch, package it into a Docker image, run it, and finally push it to the cloud.

1. Prepare Code Files

Create a new folder named my-web-api on your computer, and create the following 4 files inside it:

📄 1. package.json
{
  "name": "my-web-api",
  "version": "1.0.0",
  "dependencies": {
    "express": "^4.18.2"
  }
}
📄 2. server.js
const express = require('express');
const app = express();
const PORT = 3000;

app.get('/', (req, res) => {
  res.send('Hello Docker World! Version 1');
});

app.listen(PORT, () => {
  console.log(`Server is running on port ${PORT}`);
});
📄 3. .dockerignore
node_modules/
npm-debug.log
📄 4. Dockerfile
FROM node:24-alpine
WORKDIR /app
COPY package.json ./
RUN npm install --production
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]

2. Casting the Spell: Building the Image

Open your terminal, navigate to the my-web-api directory, and execute the build command. Here we name our image my-web-api and tag it with v1.

docker build -t my-web-api:v1 .

You will see line-by-line output in the terminal similar to this, where each step represents Docker executing a layer instruction:

Once completed, run docker images, and you'll see your freshly minted image. Thanks to Alpine Linux, it weighs only around 180MB.

3. Running the Container

Now that the image is ready, let's spin it up into a running container:

docker run -d -p 8080:3000 --name webapp my-web-api:v1

Open your browser and navigate to http://localhost:8080, or test it with curl in your terminal:

curl http://localhost:8080
# Response: Hello Docker World! Version 1

Success! 🎉

4. Iterations and Image History

Now, let's edit server.js to change the greeting to Hello Docker World! Version 2. Then re-build:

docker build -t my-web-api:v2 .

Use a handy command to inspect how this image was assembled layer by layer:

docker image history my-web-api:v2

You will see the command executed and the disk space consumed for each layer.

5. Pushing to Docker Hub

To share your creation with the world, you only need three steps:

  1. Login: docker login (enter your Docker Hub credentials)
  2. Tag properly (must include your Docker Hub username): docker tag my-web-api:v2 xiaoming/my-web-api:v2
  3. Push: docker push xiaoming/my-web-api:v2

Now, anyone across the globe can run your web service with a single command: docker run -p 8080:3000 xiaoming/my-web-api:v2! That's the power and charm of Docker.

💡
Pro-Tip: Image Tagging Strategies

In enterprise production, arbitrary names like v1 or v2 are rarely used. Here are two recommended practices:

  • Use Git Commit SHA: docker build -t myapp:a1b2c3d . (Highly rigorous, pinpointing issues directly to code commits).
  • Use Timestamps: docker build -t myapp:20231015-1430 . (Intuitive and chronologically ordered).
  • latest is merely a convention: Tagging with latest does not automatically make it the newest build—it's just a default tag name prone to ambiguities. Never deploy latest in production!
🚨 Pitfall Rescue Room
Q1: What should I do if the build gets stuck on npm install with network timeout errors?
A: By default, the container cannot access host-level proxies. You can temporarily switch to a local npm mirror prior to installation:
RUN npm config set registry https://registry.npmmirror.com && npm install --production
