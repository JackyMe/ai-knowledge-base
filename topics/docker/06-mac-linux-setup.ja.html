06. Mac & Linux 環境構築プレイブック

前回のレッスンでは Windows での導入手順を解説しました。今回は、多くのソフトウェアエンジニアに愛用されている macOS と Linux でのスマートな構築手順を紹介します。両者とも Unix の系譜に連なり、特に Linux はコンテナ技術の故郷ですが、環境構築にあたっては見落としがちな注意点や落とし穴が存在します。

一、Mac ユーザー：洗練された GUI 派の導入

Mac ユーザーの標準的な選択肢は Docker Desktop for Mac です。Docker Engine、GUI ダッシュボード、そして macOS 上で Linux コンテナを動かすための極めて軽量な仮想化レイヤーがオールインワンで提供されています。

🟢 方法1：公式インストーラー（推奨）

1. Docker 公式サイトにアクセスします。お使いの CPU アーキテクチャを正しく選択してください！

  • Apple Silicon 搭載 Mac（M1, M2, M3, M4 等）：Mac with Apple silicon を選択。
  • 従来の Intel 製 Mac：Mac with Intel chip を選択。

※アーキテクチャを間違えると、CPU エミュレーションによる極端な性能低下や起動失敗の原因になります。不明な場合は、画面左上の Apple メニュー →「この Mac について」でチップ/プロセッサを確認してください。

2. ダウンロードした .dmg ファイルを開き、Docker アイコンを Applications（アプリケーション）フォルダにドラッグ＆ドロップします。

3. Launchpad から Docker を起動し、利用規約に同意します。macOS の上部メニューバーにクジラのアイコンが現れ、アニメーションが停止して緑色の「Docker Desktop is running」になれば準備完了です！

🟡 方法2：Homebrew Cask（コマンド派）

ターミナルでのパッケージ管理を好む開発者は、Homebrew を使って1行でインストールできます。

brew install --cask docker

インストール後、初回のみ Launchpad から Docker アプリを起動してシステムの権限設定を完了させてください。

💡
プロの知恵：Mac でのパフォーマンス最適化 高負荷なコンパイルや開発を行う場合、Docker Desktop のリソース設定を調整しておくと快適です。メニューバーのクジラアイコン → Settings → Resources を開きます：
1. Memory（メモリ）：4GB〜8GB を推奨。少なすぎるとコンテナ内のビルド時にフリーズや OOM が発生します。
2. Virtual Disk Limit（ディスク上限）：デフォルトは 60GB。内蔵 SSD の空き容量に応じて調整してください。
3. VirtioFS：General 設定で VirtioFS が有効になっていることを確認してください。macOS とコンテナ間のバインドマウントのファイル I/O 速度が劇的に向上します！

二、Linux ユーザー：ネイティブな最高パフォーマンス

Linux は Docker の母体であり、仮想化レイヤーを介さない純粋なベアメタル性能を享受できます。しかし、初学者が陥りがちな落とし穴があります。

⚠️
OS 標準リポジトリの古いパッケージを避ける！ 安易に sudo apt install docker や sudo yum install docker を実行してはいけません。ディストリビューション標準のリポジトリには数年前の化石のような古いバージョンが含まれていることが多く、最新の BuildKit 機能が使えなかったりセキュリティ脆弱性が残っている危険性があります。
🔥 推奨：公式自動インストールスクリプト（迅速・確実）

Ubuntu、Debian、CentOS/RHEL を問わず、Docker 公式のセットアップスクリプトを使用するのが最も安全で確実です。

# 1. 公式セットアップスクリプトをダウンロード
curl -fsSL https://get.docker.com -o get-docker.sh
# 2. インストーラーを実行（sudo 権限が必要）
sudo sh get-docker.sh

1〜2分待つと、最新の Docker Engine Community 版のインストール完了ログが出力されます。

# Executing docker install script, commit: 7cae5f34...
+ sh -c apt-get update -qq >/dev/null
+ sh -c DEBIAN_FRONTEND=noninteractive apt-get install -y -qq ...
...
Client: Docker Engine - Community
 Version:           24.0.5

スクリプトの直接実行が制限されているセキュリティ環境では、Docker 公式ドキュメントの手順に従い、公式 APT/RPM リポジトリと GPG 鍵を手動で登録してください。

装完必做：Linux インストール後の必須2大設定

Linux では、インストール直後に docker ps を実行すると permission denied エラーが発生します。デフォルトでは root ユーザーのみが Docker デーモンの UNIX ソケットとの通信権限を持っているためです。

# 1. 現在のユーザーを docker グループに追加（sudo なしで実行可能にする）
sudo usermod -aG docker $USER

# 2. システム起動時の自動起動を有効化し、サービスを起動
sudo systemctl enable docker
sudo systemctl start docker

重要： グループを追加した後は、グループ所属を反映させるために一度ログアウトして再ログインするか、ターミナルで su - $USER を実行してください！

🚑 トラブル救護室：Linux 編
Q1: docker ps を実行すると "permission denied while trying to connect to the Docker daemon socket" と出る
A: 典型的な権限不足です。アカウントが docker グループに追加されていないか、usermod 実行後にログアウト＆再ログインを行っていません。一時的には sudo docker ps で動きますが、通常の開発のためにグループ設定を完了させてください。
Q2: "Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?" と出る
A: Docker サービスが停止しています。sudo systemctl status docker で状態を確認し、sudo systemctl start docker で起動してください。起動に失敗する場合は sudo journalctl -u docker.service で詳細ログを確認します（/etc/docker/daemon.json の構文エラーがよくある原因です）。
Q3: Windows 上の WSL2 で systemctl を打つと "System has not been booted with systemd" と怒られる
A: 従来の WSL2 は init を使用しています。sudo service docker start で起動するか、/etc/wsl.conf で systemd を有効化してください。
🌟
プロの知恵：Linux でのデーモンレスな代替選択肢「Podman」 エンタープライズの Linux 環境（RHEL、Rocky Linux、Fedora 等）では、Podman の採用が急速に広がっています。Podman は Docker と 100% の CLI 互換性を持ち（alias docker=podman が可能）、バックグラウンドデーモンが不要で、一般ユーザー権限（Rootless）で安全にコンテナを実行できる特徴があります。本コースでは標準の Docker で解説しますが、現代的な選択肢として知っておくと役立ちます。
