第34レッスン：本番の鉄則：root 実行の絶対禁止と権限制御

Dockerfile の記述方法と Compose の連携を習得し、本番環境へのデプロイを目前に控えているあなたへ。本番へ移行する前に、必ず知っておかなければならない重大なセキュリティ事例があります。

ある企業で Node.js サービスを Docker で稼働させていた際、使用していたライブラリに重大な脆弱性（RCE）が発覚しました。攻撃者はこの脆弱性を突いてコンテナ内に侵入。コンテナが Root 権限のまま稼働していたため、攻撃者はホストディレクトリのマウント脆弱性を悪用して「コンテナエスケープ（脱獄）」に成功し、物理サーバー全体の最高管理者権限を掌握してしまいました。

1. なぜデフォルトは Root なのか？その危険性とは

デフォルト状態の Dockerfile でビルドされたイメージは、すべてコンテナ内の最高権限者である root（UID 0）として実行されます。開発時にはファイル権限エラーを気にせず済むため便利ですが、本番環境では極めて危険です。

「コンテナ内の root は、本質的にホスト OS 上の root（UID 0）と同一」です（Namespaces で視界を制限されているに過ぎません）。脆弱性を突かれてサンドボックスを突破された場合、ホストシステム全体が危険に晒されます。業界における絶対の鉄則は「本番で動かす業務コンテナは、必ず一般ユーザー権限へ降格させて実行すること」です。

2. アプリケーションに制約をかける：USER 命令の実装

Dockerfile 内で USER 命令を使用し、一般ユーザーを作成して実行権限を切り替えます。Node.js アプリケーションにおけるベストプラクティスです：

# 標準的な権限降格 Dockerfile
FROM node:24-alpine

# 1. 一般ユーザーグループとユーザーを作成
RUN addgroup -S appgroup && adduser -S appuser -G appgroup

WORKDIR /app

# 2. ファイルをコピーし、所有権 (Owner) を appuser に付与
COPY --chown=appuser:appgroup package*.json ./
RUN npm install

# 3. ソースコードのコピー時も chown を指定
COPY --chown=appuser:appgroup . .

# 4. 最重要：これ以降のプロセスは一般ユーザー appuser として実行！
USER appuser

EXPOSE 8080
CMD ["node", "server.js"]
💡
動作確認コマンド 起動中のコンテナで docker exec -it <コンテナID> whoami を実行し、出力が appuser であれば安全に降格できています！

3. 権限降格時に発生する代表的な課題と解決策

一般ユーザーに切り替えると、初期段階で Permission denied エラーに遭遇することがあります：

🔒 権限エラーのパターンと対処法
  1. 特権ポートのバインド失敗： Linux では 1024 未満のポート（80, 443 等）は root のみバインド可能です。
    解決策： アプリは 8080 や 3000 番などの高位ポートをリッスンさせ、手前のリバースプロキシ（Nginx）や Docker のポートフォワーディングで 80 番から転送します。
  2. ログ・一時ファイル書き込みエラー： /var/log 等への書き込み権限が不足します。
    解決策： USER appuser より前の root 段階で、RUN mkdir -p /var/log/app && chown appuser:appgroup /var/log/app を実行してあらかじめディレクトリ所有権を付与しておきます。
  3. グローバルパッケージのインストール失敗： npm install -g などは失敗します。
    解決策： すべてのビルド・パッケージインストール処理は USER appuser より上部に記述します。

4. 本番セキュリティを極限まで高める追加設定

金融系や医療系など高セキュリティが求められるシステムでは、Compose に以下の保護レイヤーを追加します：

# docker-compose.yml でのセキュリティ強化設定
services:
  api:
    image: my-secure-api
    # 1. コンテナのルートファイルシステムを完全読み取り専用化 (改ざん防止)
    read_only: true
    # 2. 一時ファイル書き込み用にメモリマウント領域を提供
    tmpfs:
      - /tmp
    # 3. Linux の全カーネル特権機能を剥奪
    cap_drop:
      - ALL
    # 4. 子プロセスの権限昇格を禁止
    security_opt:
      - no-new-privileges:true
🚨 トラブルシューティング救急室
Q: distroless や scratch などの極小イメージには adduser コマンドがありません。
A: マルチステージビルドの前段（builder 段階）でユーザーと /etc/passwd を作成してコピーするか、単純に数値の UID を直接指定（例: USER 1000:1000）してください。数値 UID の指定であればシェルや管理コマンドが存在しない極小イメージでも正常に動作します。

プロの知恵 (Pro-tip)： CI/CD パイプライン内で docker scout cves [イメージ名] やオープンソースの脆弱性スキャナ Trivy を組み込み、デプロイ前にイメージの CVE 脆弱性を自動スキャンして高リスクな問題を未然にブロックするのが現代の標準です。
