04. 図解：コア3要素のアーキテクチャ

Dockerを学び始めた人の多くは、呪文のようにコマンドを打ち込んですぐに動かせるようになります。しかし、予期せぬエラーが発生したときや面接で内部構造を問われたとき、途端に言葉に詰まってしまいます。脱初心者を目指すなら、Dockerの伝統的な「コア3要素のアーキテクチャ（Client, Daemon, Registry）」を正確に把握しておくことが不可欠です。

Docker は Client-Server（C/S）アーキテクチャのシステム

MySQL や Redis と同様に、Docker も「クライアント」と「サーバー（デーモン）」に分離されています。普段ターミナルで実行しているコマンドは、バックグラウンドで動くエンジンに指示を出す「リモコン」に過ぎません。

3大コアコンポーネントの分かりやすい解説

1. リモコン役：Docker Client (CLI)

ユーザーが docker build や docker run などのコマンドを打ち込むインターフェースです。その役割は非常にシンプルで、入力されたコマンド引数を解析して HTTP REST API 形式に変換し、バックグラウンドの Daemon に送信するだけです。Client自身は重い処理を一切行いません。

レストランに例えるなら、Client は「注文を取るフロアのウェイター」です。客の注文を伝票に書き、厨房へ通す役割を果たします。

2. 厨房の総料理長：Docker Daemon (dockerd)

ホスト上で常駐稼働しているバックグラウンドサービスです。Client から送られてきた API リクエストを受け取り、イメージのダウンロード、Linux Namespaces による空間分離、仮想ネットワークの構築とIP割り当て、ボリュームマウント、Cgroups によるリソース制限など、すべての実務をこなします。厨房で腕を振るう「総料理長」にあたります。

3. スーパーマーケットの棚：Docker Registry

料理を作るには食材が必要です。料理長の手元（ローカルイメージ保管庫）に mysql イメージがない場合、Daemon は外部のスーパー（Registry）に接続してイメージをダウンロード（pull）してきます。

世界最大の公開スーパーマーケットが、公式の Docker Hub（hub.docker.com）です。誰でも自分がビルドしたイメージを世界中の開発者に向けて公開・共有できます。

🌟
プロの知恵：安全で信頼できるイメージの選び方

Docker Hub で検索すると、似た名前のコミュニティイメージが無数に見つかります。本番採用時は以下の2つのバッジを確認しましょう。
1. Official Image: 青い盾マークの公式イメージ。開発元とDocker社のセキュリティチームが共同保守しています。
2. Verified Publisher: Docker社に認証された公式企業アカウント。
素性のわからない個人アカウントのイメージは、マイニングスクリプトやバックドアが仕込まれているリスクがあるため、本番環境での安易な利用は厳禁です。

実況中継：docker run を実行した数秒間に何が起きているのか？

定番の docker run -d nginx コマンドを実行したときの裏側の動きをX線で覗いてみましょう。

docker run -d nginx
  1. Client がコマンドを解析し、ローカルの Docker Daemon ソケットへ HTTP POST リクエストを発行する。
  2. Daemon がローカルの保管庫を確認：「手元に nginx:latest のイメージはあるか？」
  3. ローカルに存在しない場合、Daemon は HTTPS 経由で Docker Hub に接続：「最新の nginx 公式イメージレイヤーをください！」
  4. ダウンロードが完了すると、イメージレイヤーがローカル保管庫に登録される。
  5. Daemon がイメージのマニフェストを読み取り、Linux Namespaces（プロセス、マウント、ネットワーク、IPC等）を初期化し、Cgroups リソース制限を設定してコンテナのエントリポイントプロセスを起動する。
  6. 最後に Daemon は一意の64文字のコンテナIDを Client に返す。これでコンテナがバックグラウンド（-d）で完全に立ち上がりました！
⚠️ トラブル救護室
Q: "Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?" の原因は？
A: これは Docker 初心者が最もよく遭遇するエラーです！ レストランの例えで言えば「ウェイター（Client）が厨房（Daemon）に行ったら鍵が閉まっていて誰もいなかった」状態です。
原因：バックグラウンドで Docker デーモンが起動していません。macOS や Windows なら Docker Desktop アプリを起動し、Linux なら sudo systemctl start docker を実行してデーモンを立ち上げてください。
