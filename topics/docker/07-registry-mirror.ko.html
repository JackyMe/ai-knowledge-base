07. 미러 사이트 설정: 느린 다운로드 속도 탈출

Docker 설치를 마치고 기대에 부풀어 첫 번째 이미지 docker pull ubuntu를 실행했는데, 30분이 지나도록 진행률 표시줄이 한 자리 수에서 멈춰있다가 결국 Timeout 에러가 발생한 적이 있으신가요? 이는 개인 네트워크의 문제라기보다는 해외 원격 레지스트리와의 네트워크 지연 및 라우팅 병목으로 인해 발생하는 전형적인 현상입니다.

1. 왜 다운로드 속도가 느리거나 중단되는가?

Docker 엔진은 기본적으로 해외에 위치한 공식 Docker Hub (hub.docker.com) 서버에서 이미지를 내려받습니다. 지리적 거리로 인한 RTT(왕복 지연 시간) 증가 및 특정 지역의 국제망 트래픽 제약으로 인해 다운로드 속도가 급격히 저하되거나 연결이 끊어질 수 있습니다.

비유하자면: 해외 직구 서적을 주문했을 때 매번 미국 본사에서 배편으로 배송받는 것과 같습니다. 반면 레지스트리 미러(Registry Mirror)를 설정하는 것은 국내 또는 인접한 클라우드 CDN 거점 캐시 저장소에서 당일 직배송으로 물건을 받는 것과 동일한 효과를 냅니다.

2. 고속 미러 및 가속 저장소 추천

엔터프라이즈 및 개발 환경에서 널리 활용되는 주요 클라우드 및 공공 가속 엔드포인트 목록입니다 (안정성을 위해 여러 개를 예비로 등록하는 것을 권장합니다):

  • 클라우드 개인 전용 가속기 (가장 안정적): AWS ECR 퍼블릭 갤러리 미러, 또는 클라우드 콘솔에서 발급받은 전용 가속 URL.
  • 글로벌/아시아 지역 공용 미러: https://registry-1.docker.io 캐시 프록시 및 클라우드 CDN 미러.
  • 사내 프라이빗 레지스트리 (Harbor): Docker Hub의 Proxy Cache 프로젝트 기능을 활성화하여 내부망에 구축한 캐시 서버.

3. 실전 적용: 미러 엔드포인트 등록하기

💻 Mac / Windows (Docker Desktop 사용자)

1. 상단 메뉴바 또는 시스템 트레이의 '고래' 아이콘 클릭 -> Settings (설정) 메뉴로 진입합니다.

2. 좌측 메뉴에서 Docker Engine 탭을 선택합니다.

3. 우측에 표시되는 JSON 설정 편집기에서 registry-mirrors 키 배열을 추가합니다 (표준 JSON 문법에 맞게 콤마 및 쌍따옴표 작성에 주의):

{
  "builder": {
    "gc": {
      "defaultKeepStorage": "20GB",
      "enabled": true
    }
  },
  "experimental": false,
  "registry-mirrors": [
    "https://mirror.gcr.io",
    "https://your-mirror-address.com"
  ]
}

4. 우측 하단의 Apply & restart 버튼을 눌러 데몬을 재시작합니다.

🐧 Linux 사용자

Linux 환경의 Docker 데몬 구성 파일은 /etc/docker/daemon.json에 위치합니다. 파일이 없다면 새로 생성합니다.

# 1. 디렉터리 생성 및 daemon.json 파일 작성
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<-'EOF'
{
  "registry-mirrors": [
    "https://mirror.gcr.io",
    "https://your-mirror-address.com"
  ]
}
EOF

# 2. systemd 설정 리로드 및 Docker 데몬 재시작
sudo systemctl daemon-reload
sudo systemctl restart docker

4. 설정 적용 여부 확인 (검증)

데몬 재시작 후 설정이 정상적으로 로드되었는지 확인하기 위해 다음 명령어를 실행합니다.

docker info

출력되는 시스템 정보의 하단 부분에서 다음과 같이 등록한 미러 주소가 정상 표시되는지 확인합니다.

Registry Mirrors:
  https://mirror.gcr.io/
  https://your-mirror-address.com/
Live Restore Enabled: false

Registry Mirrors 아래에 등록한 주소가 나타난다면 설정이 성공한 것입니다. 이제 docker pull ubuntu를 실행하여 훨씬 빨라진 다운로드 속도를 경험해 보세요!

🚑 트러블슈팅 구조대: 네트워크 문제 해결
Q1: "dial tcp: lookup registry-1.docker.io on x.x.x.x:53: no such host" 에러가 납니다.
A: 로컬 DNS 서버의 도메인 질의 실패입니다. 호스트 머신의 /etc/resolv.conf에 공용 신뢰 DNS(예: nameserver 8.8.8.8 또는 1.1.1.1)를 추가하거나, Docker Desktop의 DNS 설정을 직접 지정하세요.
Q2: daemon.json 수정 후 Docker 데몬이 시작되지 않습니다 ("unable to configure the Docker daemon").
A: 99%의 확률로 JSON 문법 오류입니다! 마지막 항목 뒤에 불필요한 콤마(,)가 붙었거나 닫는 괄호 누락, 단일 따옴표(') 사용 여부를 꼼꼼히 점검하세요.
Q3: 사내 폐쇄망 환경에서 외부 미러에 접근할 수 없습니다.
A: 기업 프라이빗 레지스트리(Harbor, Nexus 등)를 구축하여 내부에 이미지를 캐싱하거나, Docker Desktop 프록시 설정(Settings -> Resources -> Proxies)에 기업 HTTP/HTTPS 프록시 서버 주소를 지정해야 합니다.
💡
실무 팁: 기업 네트워크 프록시 (Proxy Fallback) 설정 사내 보안망을 거쳐야 하는 환경이라면 미러를 찾는 대신 프록시를 설정하는 것이 가장 확실합니다. Docker Desktop의 [Settings] -> [Resources] -> [Proxies]에서 'Manual proxy configuration'을 켜고 로컬 또는 사내 프록시(예: http://proxy.company.com:8080)를 지정하면 모든 다운로드 트래픽이 프록시 터널을 통해 고속으로 우회 처리됩니다.
