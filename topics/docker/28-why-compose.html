28. 为什么需要 Compose？告别千行命令噩梦

通过前面 27 章的修炼，你已经能够熟练使用 docker run 启动各种花里胡哨的容器了。挂载数据卷、映射端口、配置网络，你样样精通。但是，现实世界往往是残酷的...

一、长长的命令，深深的绝望

假设你要部署一个稍微像样点的现代化博客系统。你需要一个 Web 前端、一个 Node 后端、一个 Redis 做缓存、一个 MySQL 做存储。用 docker run 的话，你得写出一个长长的脚本：

# 1. 创建专用网络
docker network create blog-net

# 2. 启动数据库
docker run -d --name blog-db --network blog-net -v db-data:/var/lib/mysql -e MYSQL_ROOT_PASSWORD=123456 mysql:8

# 3. 启动缓存
docker run -d --name blog-redis --network blog-net redis:alpine

# 4. 启动后端 (还要考虑顺序，得等DB先起)
docker run -d --name blog-api --network blog-net -p 3000:3000 -e DB_HOST=blog-db my-backend:v1

# 5. 启动前端
docker run -d --name blog-web --network blog-net -p 80:80 my-frontend:v1

这就很难受了兄弟。每次更新、迁移、或者新同事想在本地跑一套这个环境，你都得把这坨脚本发给他。如果环境变量里还包含各种机密 token，整个命令可能长达十几行，敲错一个空格就集体罢工。

二、救世主：Docker Compose 登场

Docker Compose 简直就是为了拯救这种局面而诞生的。它的核心思想是：不要手敲命令去一步步“做”（命令式），而是写一份声明书，告诉 Docker 我“要什么”（声明式）。

你可以把那个长长的 shell 脚本，变成一个优雅优雅极其优雅的文本文件：docker-compose.yml。

flowchart LR
    File[docker-compose.yml
(声明式配置)] -->|docker compose up| Engine{Docker Engine}
    Engine --> C1[Web 容器]
    Engine --> C2[API 容器]
    Engine --> C3[DB 容器]
    Engine --> Net[专用网络]
    Engine --> Vol[数据卷]

有了它，你只需要在这个文件所在的目录敲一个命令：

docker compose up -d

世界清静了。Docker Compose 会自动按正确的顺序帮你创建网络、挂载存储卷、拉取镜像、启动容器。一切尽在掌控。

三、Compose 带来的核心价值

💎 1. 一键启停，项目即插即用

新人入职？克隆代码库，敲一句 docker compose up -d，立刻得到一个和生产环境一模一样的本地开发环境。下班了？docker compose down 瞬间全部销毁收工。

💎 2. 基础设施即代码 (IaC)

所有的配置（环境变量、挂载目录、端口映射）都在 .yml 文件里，这意味着它可以被 Git 追踪。谁修改了哪个端口，谁加了什么环境变量，翻翻 commit 记录一清二楚。

💎 3. 自动隔离的作用域

当你在目录 my-blog 里执行 compose up 时，Compose 默认会自动根据目录名创建一个叫 my-blog_default 的网络。你的容器全部跑在这个小世界里，和宿主机上其他项目完全隔离。

四、历史的小插曲：docker-compose vs docker compose

📚
少了个横杠的区别

如果你在网上搜教程，肯定会看到有人用 docker-compose，有人用 docker compose。这不是写错了！

  • v1 版本： 叫 docker-compose（有横杠）。它是用 Python 写的独立小工具，需要单独安装。现在已经废弃停更。
  • v2 版本： 叫 docker compose（没有横杠，作为空格子命令）。它是用 Go 重写的，现在已经作为插件内置在 Docker 引擎里了。装了 Docker 就有它！

所以从现在起，请忘记横杠，拥抱 docker compose！

⚠️ 踩坑自救室
Q: 执行 compose 报错 "version is obsolete" 是怎么回事？
A: 在以前的 Compose V1 时代，yml 文件开头必须写 version: '3.8' 这样的声明。但在最新的 Compose V2 规范中，version 字段已经被官方废弃并忽略了。把这行删掉，清爽上阵即可。
