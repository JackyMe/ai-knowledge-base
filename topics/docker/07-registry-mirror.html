07. 换源提速：告别蜗牛网速

装好了 Docker，你正兴致勃勃地准备拉取第一个镜像 docker pull ubuntu，结果等了半个小时，进度条还在个位数缓慢爬行，最后直接甩给你一个大大的 Timeout。别怀疑人生，这不是你的网不好，而是因为“距离产生痛”。

一、为什么下载这么慢？

Docker 默认会去官方的 Docker Hub (hub.docker.com) 下载镜像。这个服务器在遥远的海外。加上某些众所周知的网络防火墙（GFW）原因，不仅慢，而且经常直接被阻断（尤其是在 2024-2025 年期间，Docker Hub 域名经常处于无法直连的状态）。

打个比方：你想买本外国书，Docker 默认是派人坐船去美国总部给你买，还要过海关盘查。而“换源”（配置 Registry Mirror），就是在国内找个大型代理仓库，直接在国内发货，次日达！

二、国内可用镜像源推荐

由于各种合规原因，国内的镜像源经常会有变动。以下是几个常用的高质量镜像源（建议多配置几个作为备用）：

  • 阿里云（最稳定）：需要登录阿里云控制台 -> 容器镜像服务 -> 镜像工具 -> 镜像加速器，获取你个人的专属加速地址（如 https://xxxxx.mirror.aliyuncs.com）。
  • 网易云：https://hub-mirror.c.163.com
  • 百度云：https://mirror.baidubce.com
  • 腾讯云：https://mirror.ccs.tencentyun.com

注意：像以前常用的中科大、清华源等，目前对外部公网的访问常常有限制，建议优先使用云厂商的源。

三、实战配置：如何换源？

💻 Mac/Windows (Docker Desktop 用户)

1. 点击系统托盘的“小鲸鱼”图标 -> 选择 Settings（或 Preferences）。

2. 在左侧菜单找到 Docker Engine。

3. 你会看到一个 JSON 格式的配置文件。在里面添加 registry-mirrors 数组，修改后如下（注意逗号和双引号，这是严格的 JSON 格式）：

{
  "builder": {
    "gc": {
      "defaultKeepStorage": "20GB",
      "enabled": true
    }
  },
  "experimental": false,
  "registry-mirrors": [
    "https://你的专属前缀.mirror.aliyuncs.com",
    "https://hub-mirror.c.163.com"
  ]
}

4. 点击右下角的 Apply & restart，等待 Docker 重启完毕。

🐧 Linux 用户

Linux 下 Docker 的守护进程配置文件位于 /etc/docker/daemon.json。默认可能不存在这个文件。

# 1. 创建并编辑配置文件
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<-'EOF'
{
  "registry-mirrors": [
    "https://你的专属前缀.mirror.aliyuncs.com",
    "https://hub-mirror.c.163.com"
  ]
}
EOF

# 2. 重新加载配置并重启 Docker 服务
sudo systemctl daemon-reload
sudo systemctl restart docker

四、见证奇迹：验证配置是否生效

配置完成后，一定要用命令验证一下 Docker 是否真的吃到了这个配置。在终端运行：

docker info

在输出的最后几行，你应该能找到类似这样的内容：

Registry Mirrors:
  https://xxxxx.mirror.aliyuncs.com/
  https://hub-mirror.c.163.com/
Live Restore Enabled: false

看到 Registry Mirrors 下面有你配置的地址，就说明大功告成！现在再去 docker pull ubuntu，体验飞一般的感觉吧！

🚑 踩坑自救室：网络还是不行怎么办？
Q1: 报错 "dial tcp: lookup registry-1.docker.io on x.x.x.x:53: no such host"
A: 典型的 DNS 解析失败。说明你虽然配了镜像，但 Docker 在解析某些元数据时依然尝试连官方库且 DNS 被污染。解决办法：修改宿主机的 /etc/resolv.conf，增加可靠的 DNS 如 nameserver 223.5.5.5 或 8.8.8.8；或者考虑使用全局代理。
Q2: 重启 Docker 失败，systemctl status 显示 "unable to configure the Docker daemon with file /etc/docker/daemon.json"
A: 99% 的可能性是你写的 JSON 格式不对！可能是少了个逗号，或者多了个逗号（JSON 不允许最后一个元素有逗号），或者单双引号用错了（JSON 必须是双引号）。用工具校验一下你的 JSON 内容。
Q3: 如果所有公开的镜像源都挂了（2024年常态）怎么办？
A: 终极方案有两个：1. 使用自建的镜像仓库（比如用 Harbor 在海外服务器反代或者公司内网搭建）。2. 让 Docker 走代理。在 systemd 中为 Docker 服务配置 HTTP_PROXY 环境变量（创建 /etc/systemd/system/docker.service.d/http-proxy.conf）。
💡
Pro-tip：代理配置 (Proxy Fallback) 如果你有稳定的魔法网络工具，比起四处找镜像源，直接给 Docker Engine 配置代理一劳永逸。 在 Docker Desktop 中：Settings -> Resources -> Proxies，开启 Manual proxy configuration，填入你的本地代理地址（例如 http://127.0.0.1:7890）。注意：给 Docker 用的代理地址，往往需要开启“允许局域网连接”（Allow LAN）。
