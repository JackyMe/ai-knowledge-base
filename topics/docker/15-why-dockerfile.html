15. 告别人工配环境

😭 “在我的电脑上是好的啊！”

小明是个开发，花了三天时间把项目环境配置好，跑通了代码。他把代码传给新来的同事小红，小红折腾了一下午，怎么也跑不起来，报错缺各种库。

小明不服气，走到小红电脑前，一通 npm install、改环境变量，最后还是跑不起来。小明只能祭出那句经典台词：“这真是见鬼了，在我的电脑上明明是好的啊！”

为了解决这个问题，小明学会了 Docker。他开了一个 Ubuntu 容器，进去手动 apt-get 装环境、拉代码，搞定后用 docker commit 把它打包成一个大镜像发给小红。小红一运行，果然跑起来了！

好景不长，一个月后项目要升级 Node.js 版本。小明看着那个毫无注释的“黑盒镜像”，彻底懵了：“我当时在这个镜像里到底执行了哪些命令来着……？”

一、告别黑盒操作：Dockerfile 登场

像小明那样，进入容器手动敲命令，然后 docker commit 打包镜像的方式，是 Docker 界的绝对反模式 (Anti-pattern)！因为这种方式打出来的镜像是一个不透明的黑盒，无法追溯、无法复现、更无法版本控制。

为了解决这个问题，Docker 引入了 Dockerfile。

Dockerfile 是什么？它就是一个普通的文本文件（连后缀名都没有，名字就叫 Dockerfile）。里面一行一行地写满了“构建配方”。当交给你 Docker 引擎时，它会像一个不知疲倦的机器厨师，严格按照配方，全自动地把镜像熬制出来。

二、基础设施即代码 (IaC) 的降维打击

使用 Dockerfile，我们实现了开发界梦寐以求的理念：Infrastructure as Code（基础设施即代码）。它的优势是毁灭性的：

  • 可阅读性： 环境是怎么配的，看代码一目了然，再也不用靠记忆。
  • 版本控制： Dockerfile 和代码放一起提交到 Git。回滚代码的同时，环境也跟着回滚了！
  • 极致复现： 任何人在任何机器上，拿着这套 Dockerfile 构建，得到的镜像都是 100% 一模一样的。
  • 分层缓存： Docker 会聪明地缓存每一行指令的结果，下次构建只要改动点之后的步骤重做，极速秒级构建（后续专门讲）。

三、手工敲命令 vs 写 Dockerfile

让我们对比一下配置一个 Python Web 环境的两种姿势：

❌ 刀耕火种 (手工敲)

# 1. 下载基础镜像
docker pull python:3.9-slim

# 2. 跑一个临时容器进去
docker run -it python:3.9-slim bash

# 3. 在容器里狂敲命令
mkdir /app
cd /app
# (手动把代码拷进去)
pip install -r requirements.txt
python app.py

# 4. 退出来手动打包
docker commit container_id my-app

✅ 现代工业 (Dockerfile)

# 创建名为 Dockerfile 的文件

FROM python:3.9-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install -r requirements.txt

COPY . .

CMD ["python", "app.py"]

四、从代码到镜像的飞跃之路

写好了配方，怎么变成镜像？只需要在 Dockerfile 所在的目录下，执行一条大招：

# -t 给镜像打标签起名字
# 最后的 . 代表当前目录 (这就是传说中的“构建上下文”)
docker build -t my-python-app:v1 .

🚑 踩坑自救室
Q1: 为什么我在 build 时，COPY 报 “no such file or directory” 错误？明明绝对路径是对的！
A: 这是一个非常经典的坑。命令最后的那个 . 叫做“构建上下文”。Docker Client 会把这个目录下的所有文件打包发送给后端的 Docker Daemon 来构建。你只能 COPY 构建上下文目录（及其子目录）里的文件！ 如果你在 Dockerfile 里写 COPY /Users/apple/Desktop/file.txt /app，那是绝对找不到的，因为桌面不在你发送的上下文中。
🚀
Pro-tip / 老鸟技巧：千万别泄露机密！

既然 Docker build 会把你当前目录所有的文件（构建上下文）都发给引擎，如果你目录里有 .git 文件夹，几百兆的垃圾也会被传过去，甚至你的 .env 密码文件也会被不小心 COPY 进镜像里，成为严重的安全漏洞！
怎么避免？下一章我们将会揭秘 Dockerfile 的最佳拍档——.dockerignore 文件，敬请期待！
