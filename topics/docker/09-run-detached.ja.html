09. バックグラウンドで動かす Nginx

前回のレッスンで動かした hello-world は、挨拶を出力して瞬時に終了する使い捨てのプロセスでした。しかし、実際のサーバー運用では Web サーバーやデータベースのように、24時間365日バックグラウンドで常駐稼働し続けるサービスが必要です。今回は、世界で最も広く使われている高性能 Web サーバー Nginx を実際に動かしてみましょう。

※補足：Nginx（エンジンエックス）は、現在世界で最も普及しているオープンソースの Web サーバーです。フロントエンドの知識がなくても、Docker の検証ツールとして最適です。

一、フォアグラウンド実行の不便さ

まずは最もシンプルな形で起動してみます：

docker run nginx

実行すると、すぐに2つの問題に直面します：

  1. イメージ取得後、ターミナルがフリーズ（占有）してしまい、新しいコマンドが打てなくなる。
  2. ブラウザで http://localhost にアクセスしても、接続拒否（Connection Refused）で何も表示されない。

これはコンテナがフォアグラウンド（前面）で実行され、コンテナの標準出力が現在のターミナルセッションを占有しているためです。慌てて Ctrl+C（割り込みシグナル）を押すと、ターミナルは戻ってきますが、コンテナ自体も強制停止してしまいます。

バックグラウンドで静かに常駐させ、外部からアクセスできるようにするにはどうすればよいでしょうか？

二、神オプション -d と -p の活用

プロのエンジニアは以下のようにコンテナを立ち上げます：

docker run -d -p 8080:80 --name my-web nginx

Enter を押すと、ターミナルには長いハッシュ文字列（コンテナID）が1行だけ出力され、すぐに操作が手元に戻ってきます。この短いコマンドには3つの重要なオプションが含まれています。順を追って分解しましょう：

1. -d：バックグラウンド実行（Detached モード）

-d フラグは Docker に「このコンテナをバックグラウンドで動かせ。ターミナルを占有するな」と指示します。Nginx はコンテナ内部で静かにリクエストを待ち受け、ターミナルを閉じたり Ctrl+C を押しても停止しなくなります。

2. -p 8080:80：ポートマッピング（Port Publishing）

これは初学者が最もつまずきやすいポイントです。黄金則を覚えてください：-p ホスト側ポート:コンテナ側ポート（コロンの左が外側のホストOS、右が内側のコンテナです）。

なぜマッピングが必要なのでしょうか？ コンテナは完全に隔離されたブラックボックスだからです。内部の Nginx は確かに 80 番ポートで待機していますが、外側のホストマシン（Mac/Windows/Linux）から直接そこへ到達する経路がありません。ドアも窓も閉め切った防音室の中で誰かが叫んでいるような状態です。-p 8080:80 を指定することで、コンテナの壁に穴を開け、ホストマシンの 8080 番ポート宛ての通信をコンテナ内の 80 番ポートへ転送するパイプを通すことができます。

3. --name my-web：分かりやすい名前をつける

前回のレッスンで見たように、名前を指定しないと clever_turing のようなランダムな名前が付いてしまいます。--name my-web と名付けておけば、後で停止するときも docker stop my-web と打つだけで済み、長いコンテナIDを調べる手間が省けます。

三、奇跡の瞬間：Web サイトにアクセスする

それでは、ブラウザを開いて http://localhost:8080（または http://127.0.0.1:8080）にアクセスしてみましょう。

画面に大きく "Welcome to nginx!" と表示されたはずです！ おめでとうございます。あなたはわずか10秒足らずで、世界水準の Web サーバーを構築・公開することに成功しました。

👀 稼働状況を確認する：docker ps
docker ps

出力例：

CONTAINER ID   IMAGE   COMMAND                  CREATED         STATUS         PORTS                  NAMES
f9a2b3c4d5e6   nginx   "/docker-entrypoint.…"   2 minutes ago   Up 2 minutes   0.0.0.0:8080->80/tcp   my-web

PORTS 列に注目してください：0.0.0.0:8080->80/tcp。これはホストの全ネットワークインターフェース（0.0.0.0）の 8080 番ポートに届いた TCP 通信が、コンテナの 80 番ポートへ正しくルーティングされていることを示しています。

🚑 トラブル救護室：ポート競合と名前の衝突
Q1: "Bind for 0.0.0.0:8080 failed: port is already allocated" または "address already in use" と出る
A: 典型的なポート競合エラーです。ホスト側の 8080 番ポートが、別のアプリケーション（Tomcat や開発サーバー、停止し忘れた別コンテナなど）によって既に使用されています。解決策： コロンの左側のポート番号を変更してください（例: -p 8888:80 や -p 9090:80）。右側の 80（Nginxのデフォルト待機ポート）は絶対に変更してはいけません！
Q2: "Conflict. The container name /my-web is already in use" とエラーが出る
A: コンテナ名の重複です。過去に作成した同名の my-web コンテナが（停止状態であっても）残っています。解決策： docker rm my-web で古いコンテナを削除するか、別の名前（--name web2 など）を指定して起動してください。
🌟
プロの知恵：使い捨てコンテナ (--rm) と ランダムポートマッピング (-P) 1. 使い捨てコンテナ --rm：動作確認や一時的なテストで動かす際、停止後に手動で docker rm を打つのは面倒です。--rm オプションを付与（例: docker run --rm nginx）しておけば、コンテナが停止した瞬間に自動的にファイルシステムごと綺麗に削除されます！
2. ランダムポートマッピング -P（大文字）：空いているホスト側ポートを気にしたくない場合、大文字の -P（例: docker run -d -P nginx）を使います。Docker がホスト側の空いている高位ポート（例: 32768 等）を自動で割り当ててくれます。割り当てられたポートは docker ps で確認できます。
