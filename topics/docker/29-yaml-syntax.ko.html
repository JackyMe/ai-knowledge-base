제29레슨: YAML 문법 초고속 마스터: 들여쓰기의 예술

Docker Compose를 사용하기로 결정했다면 그 기반이 되는 설정 파일 포맷인 YAML을 반드시 이해해야 합니다. 많은 입문자들이 처음에 YAML의 엄격한 들여쓰기 규칙 때문에 혼란을 겪곤 합니다. 오늘 단 5분 만에 YAML의 핵심 규칙을 완벽하게 마스터해 보겠습니다.

1. 왜 하필 YAML인가?

YAML은 "YAML Ain't Markup Language"의 재귀적 약자입니다. 설계의 최우선 목표는 사람이 읽고 쓰기에 가장 직관적이고 편안해야 한다는 것입니다.

동일한 서버 설정을 JSON으로 작성하면 화면 전체가 중괄호 {}와 큰따옴표 ""로 도배되고, 마지막 줄의 쉼표(trailing comma) 하나 때문에 구문 에러가 발생하기 일쑤입니다. 반면 YAML은 이러한 모든 문장 부호의 노이즈를 제거하고, 오직 공백 들여쓰기(Indentation)만으로 깔끔하게 계층 구조를 표현합니다.

2. YAML 핵심 문법의 3대 철칙

철칙 1: 들여쓰기는 오직 '스페이스(공백)'만 사용, Tab 키 절대 금지!

이것은 YAML에서 발생하는 오류의 80% 이상을 차지하는 가장 중요한 규칙입니다. 같은 파일 안에서 스페이스와 Tab 키를 혼용하면 파서가 즉시 파싱 에러를 일으킵니다.

베스트 프랙티스: VS Code나 사용하는 에디터 설정에서 Tab 키를 눌렀을 때 자동으로 2개의 스페이스로 치환되도록 설정하세요. 계층이 깊어지더라도 항상 일관되게 2칸 들여쓰기를 유지합니다.

철칙 2: Key-Value의 콜론(:) 뒤에는 반드시 공백이 있어야 한다!
# ❌ 잘못된 작성법 (콜론 뒤 공백 없음)
image:nginx:latest

# ✅ 올바른 작성법
image: nginx:latest
철칙 3: 리스트(배열) 항목은 하이픈과 공백(- )으로 작성한다

JSON의 배열 ["80:80", "443:443"]은 YAML에서 다음과 같이 우아하게 작성됩니다:

ports:
  - "80:80"
  - "443:443"

3. 실전 비교: JSON vs YAML

중첩 구조와 배열이 포함된 동일한 Docker 서비스 설정을 비교해 보면 YAML의 뛰어난 가독성을 체감할 수 있습니다:

🤮 장황한 JSON

{
  "services": {
    "web": {
      "image": "nginx",
      "ports": [
        "80:80"
      ],
      "environment": {
        "DEBUG": true
      }
    }
  }
}

😍 깔끔한 YAML

services:
  web:
    image: nginx
    ports:
      - "80:80"
    environment:
      DEBUG: true

4. 문자열과 불리언 값 작성 시 주의사항

  • 문자열은 일반적으로 따옴표를 붙이지 않습니다. 특수문자(콜론, 별표 등)가 포함된 경우에만 따옴표로 감싸줍니다.
  • 포트 번호는 항상 큰따옴표를 권장합니다. 예를 들어 - 80:80을 따옴표 없이 적으면 YAML 파서에 따라 60진수 시간 값으로 잘못 해석될 여지가 있으므로 항상 - "80:80"처럼 문자열로 명시하는 것이 안전합니다.
  • 불리언 값은 소문자 true / false만 사용합니다. 과거 YAML 사양의 yes/no, on/off는 혼란을 유발할 수 있으므로 표준 true / false를 사용하세요.
💡
프로의 팁: 여러 줄 문자열 작성법 긴 스크립트나 다중 라인 텍스트를 YAML 안에 넣을 때는 파이프 | 기호를 사용하여 줄바꿈 포맷을 그대로 보존할 수 있습니다: 
script: |
  echo "서버 실행 시작..."
  npm install
  npm start
🚨 트러블슈팅 응급실
Q1: "mapping values are not allowed here" 오류의 원인은 무엇인가요?
A: 99.9% 확률로 들여쓰기 공백 칸 수가 맞지 않거나, 콜론 뒤에 띄어쓰기를 빠뜨린 경우입니다. 에디터의 "보이지 않는 공백 표시(Render Whitespace)" 기능을 켜고 각 계층의 스페이스 개수가 정확히 정렬되었는지 확인하세요.
