08. 最初のコマンドに隠された仕組み

あらゆるプログラミング言語の第1歩が「Hello World」を出力することであるように、Docker にも同様の入門儀式が存在します。しかし、この1行のコマンドを実行した裏側で起きていることは、単なる print("hello") よりもはるかに精緻で興味深い仕組みです。今回は、この最初の1行の魔法を徹底解剖します。

一、実行！ 魔法の瞬間を目撃する

ターミナルを開き、以下のコマンドを実行してみましょう。

docker run hello-world

初回実行時には、以下のような詳細なログメッセージが出力されます：

Unable to find image 'hello-world:latest' locally
latest: Pulling from library/hello-world
c1ec31eb5944: Pull complete 
Digest: sha256:d000bc5694d4d8fc3bc09bf2cc72464161f5f3e790a6e30ebf0653df37ec42a8
Status: Downloaded newer image for hello-world:latest

Hello from Docker!
This message shows that your installation appears to be working correctly.

To generate this message, Docker took the following steps:
 1. The Docker client contacted the Docker daemon.
 2. The Docker daemon pulled the "hello-world" image from the Docker Hub.
 3. The Docker daemon created a new container from that image which runs the executable that produces the output you are currently reading.
 4. The Docker daemon streamed that output to the Docker client, which sent it to your terminal.

二、この10秒間に一体何が起きたのか？

出力されたメッセージは一連の流れを要約しています。シーケンス図を使って、背後で発生したイベントを正確に追ってみましょう。

sequenceDiagram
    participant U as ユーザー (Client CLI)
    participant D as Docker デーモン (Engine)
    participant R as レジストリ (Docker Hub)
    
    U->>D: 1. docker run hello-world を実行
    D-->>D: 2. ローカルディスク確認: イメージがあるか? (なし)
    D->>R: 3. リモートレジストリからイメージレイヤーを取得
    R-->>D: 4. hello-world イメージデータを返却
    D-->>D: 5. イメージからコンテナを実体化して起動
    D->>U: 6. バイナリを実行し Hello メッセージを端末へ出力
    D-->>D: 7. プロセス終了、コンテナは Exited 状態へ遷移

各ステップの詳細解説：

  1. ローカルキャッシュ探索（Unable to find image locally）：Docker はまずローカルストレージ内に hello-world というイメージの設計図が存在するか確認します。初回実行時は存在しないため、外部取得へ進みます。
  2. レイヤーのダウンロード（Pulling from library）：Docker は HTTPS 経由で Docker Hub に接続してイメージを取得します。c1ec31eb5944: Pull complete はダウンロードされたストレージ層（Layer）を表しています。これは Docker の根幹アーキテクチャである分層ファイルシステム（OverlayFS）に関わっており、第4フェーズで詳しく学びます。
  3. コンテナの実体化と実行（Hello from Docker）：イメージ取得後、Docker Engine は隔離されたコンテナ空間を構築し、組み込まれた実行ファイル（静的にコンパイルされた極小のC言語バイナリ）を起動します。プログラムが出力した文字列が標準出力へ送られます。
  4. プロセスの正常終了：メッセージを出力し終えると主プロセスの任務が完了し、コンテナは自動的に停止状態（Exited）へ遷移してライフサイクルを終えます。

三、状態確認：知っておくべき2大基本コマンド

Docker がシステム上に何を作成したのかを確認するために、以下の2つの検出コマンドを使います。

1. ローカルイメージ一覧を確認：docker images

docker images
# 出力例:
# REPOSITORY    TAG       IMAGE ID       CREATED        SIZE
# hello-world   latest    d2c94e258dcb   10 months ago  13.3kB
  • REPOSITORY：イメージ名。
  • TAG：バージョンタグ（latest はデフォルトの最新版を意味します）。
  • IMAGE ID：イメージを一意に識別するハッシュ値。
  • SIZE：驚きの 13.3 kB！ 完全な Linux OS を丸ごと積んでいるわけではなく、最小限のバイナリのみで構成されているため、これほど極小サイズで済むのです。

2. コンテナの履歴を確認：docker ps -a

docker ps -a
# 出力例:
# CONTAINER ID   IMAGE         COMMAND    CREATED         STATUS                     PORTS     NAMES
# a1b2c3d4e5f6   hello-world   "/hello"   2 minutes ago   Exited (0) 2 minutes ago             clever_turing

-a（all）オプションに注目してください。これを付けないと docker ps は現在実行中のコンテナしか表示しません。hello-world は実行後すぐに終了したため、Exited 状態として履歴に残っています。

  • CONTAINER ID：このコンテナインスタンス固有のID（イメージの IMAGE ID とは別物です）。
  • STATUS：Exited (0) は正常終了コードを表します（Unix 系では 0 が正常終了）。
  • NAMES：--name で名前を指定しなかった場合、Docker が自動的に「形容詞＋著名な科学者・エンジニアの苗字」（例: clever_turing）をランダムに命名します。
🎯 実践演習：対話型コンテナへの潜入

一瞬で終わるコンテナを体験した後は、実際に操作できる完全な対話型 Ubuntu コンテナを起動してみましょう：

docker run -it ubuntu bash

パラメータ解説：-i（Interactive、標準入力を開いたままにする）、-t（擬似端末 TTY を割り当てる）、bash（コンテナ内で起動するシェルコマンド）。

プロンプトが root@f8d2e8b1a3c4:/# のような表示に切り替わります。これであなたは完全に隔離されたサンドボックス Ubuntu 環境の中にいます！ ホストマシンに影響を与えることなく自由に実験（rm -rf / のような危険なコマンドさえも）できます。終了するには exit と入力します。

🚑 トラブル救護室
Q1: 2回目に docker run hello-world を実行したとき、Unable to find... やダウンロードが出ないのはなぜ？
A: 1回目の実行でイメージがすでにローカルにキャッシュされたためです。Docker はローカルキャッシュを検知し、数ミリ秒で即座にコンテナを起動します。
Q2: "pull access denied" や "repository does not exist" とエラーが出る
A: イメージ名のスペルミス（例: helo-world）を確認してください。プライベートレジストリの非公開イメージの場合は、事前に docker login による認証が必要です。
🌟
プロの知恵：docker run = docker create + docker start 初心者の多くは docker run を単一のコマンドと思いがちですが、実際には複合コマンドです：
1. docker create [image] → イメージからコンテナを生成（未起動状態）
2. docker start [container_id] → コンテナのプロセスを起動
さらに docker run --pull=always を指定すると、起動前に必ずリモートレジストリの最新ダイジェストを問い合わせて更新する挙動になります。
