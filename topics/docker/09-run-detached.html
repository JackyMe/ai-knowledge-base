09. 后台跑一个 Nginx 网站

上一节的 hello-world 虽然神奇，但它只是个“一波流”的短命鬼——打印完一句话就去世了。但在真实的服务器环境中，我们需要程序（比如网站服务、数据库）7x24 小时一直运行。今天，我们就来真正跑一个实用的服务：Nginx。

科普：Nginx（发音为 Engine X）是目前全球使用最广泛的高性能 Web 服务器。哪怕你不懂前端开发，它也是最好的测试利器。

一、前台运行的尴尬

我们先用最基础的方式跑一下：

docker run nginx

你会发现两件事：

  1. 下载完镜像后，你的终端卡住了！光标在那儿闪，什么命令也输不了。
  2. 你去浏览器访问 http://localhost，发现啥也打不开（拒绝连接）。

这很正常，因为你把它跑在了前台（Foreground），容器的输出直接接管了你的终端。这时你习惯性地按下 Ctrl+C（中断信号），完了，终端是退出了，但容器也被你无情地杀死了。

怎么能让它“默默在后台奉献”呢？

二、祭出 -d 和 -p 神器

真正的老手都是这样启动服务的：

docker run -d -p 8080:80 --name my-web nginx

敲下回车，终端只会打印出一长串哈希字符（如 c2b3... 容器ID），然后立刻把控制权还给你。这串短平快的命令里，藏着三个极其重要的参数，我们逐一拆解：

1. -d：后台运行 (Detached mode)

-d 参数告诉 Docker：“把这个容器送到后台去跑，别占用我的终端终端”。此时，Nginx 就在容器内部默默监听请求了，不会被 Ctrl+C 干扰。

2. -p 8080:80：端口映射 (Port publishing)

这是新手最容易迷糊的地方。记住一个黄金法则：-p 宿主机端口:容器内端口（冒号左边是外面，右边是里面）。

为什么需要映射？因为容器是一个隔离的黑盒，里面的 Nginx 确实启动在了 80 端口，但你的宿主机（Mac/Windows）根本不知道。就像房间里的人在喊叫，门窗全关着外面听不到一样。-p 8080:80 相当于在黑盒上打个洞，把宿主机的 8080 端口和容器的 80 端口连了一根管子。

3. --name my-web：起个响亮的名字

上节课我们看到 Docker 会随机起类似 clever_turing 这样的名字。为了好记，用 --name 给它命名为 my-web。以后你想停掉它，直接 docker stop my-web 就行，不用去记那一长串 ID 了。

三、见证奇迹：访问你的网站

现在，打开你的浏览器，地址栏输入 http://localhost:8080 （或者 http://127.0.0.1:8080）。

Boom！你看到了经典的 "Welcome to nginx!" 页面！恭喜你，你在不到 10 秒钟的时间里，部署了一个世界级的 Web 服务器。

👀 看看它在干嘛：查看运行状态
docker ps

输出如下：

CONTAINER ID   IMAGE   COMMAND                  CREATED         STATUS         PORTS                  NAMES
f9a2b3c4d5e6   nginx   "/docker-entrypoint.…"   2 minutes ago   Up 2 minutes   0.0.0.0:8080->80/tcp   my-web

重点看 PORTS 这一列：0.0.0.0:8080->80/tcp。这就直观地展示了流量是如何从外部任何 IP (0.0.0.0) 的 8080 端口，流入内部的 80 端口的。

🚑 踩坑自救室：端口被占用了！
Q1: 报错 "Bind for 0.0.0.0:8080 failed: port is already allocated" 或 "address already in use"
A: 典型的新手翻车现场。这说明你宿主机的 8080 端口已经被别的程序（比如 Tomcat，或者你之前跑的一个没关掉的容器）占用了。解决办法：换个左边的端口，比如改成 -p 8888:80 或者 -p 9090:80。右边的 80 绝对不能动，那是 Nginx 代码里写死的！
Q2: 报错 "Conflict. The container name /my-web is already in use"
A: 名字冲突了。你之前可能跑过一次叫 my-web 的，虽然可能退出了，但尸体还在。解决办法：用 docker rm my-web 把旧的删掉，或者换个名字 --name web2。
🌟
老鸟技巧：阅后即焚(--rm) 与 随机端口(-P) 1. 阅后即焚 --rm：平时测试跑容器，测试完还得手动去 docker rm 删掉垃圾，很烦。如果在 run 时加上 --rm 参数（例如 docker run --rm nginx），只要容器一停止，Docker 就会自动清理掉它的尸体，不留痕迹！
2. 随机端口大写 -P：如果你懒得想宿主机端口，可以用大写的 -P（例如 docker run -d -P nginx）。Docker 会自动在宿主机挑一个没有被占用的高位端口（比如 32768）映射给容器。你可以用 docker ps 看它到底分了哪个端口给你。
