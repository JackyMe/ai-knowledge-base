30. 终极之战(上)：Web+缓存的 Compose 狂欢

铺垫了这么多理论，到了拔剑的时刻了！今天我们要用 Docker Compose 跑一个真实场景的小项目：一个带 Redis 页面浏览统计的 Node.js Web 应用。咱们要用一个 yml 文件统管代码构建、拉取镜像、网络配置，一气呵成！

一、项目结构准备

新建一个文件夹 my-counter，在里面创建三个文件：

📜 app.js - 我们的业务代码
const express = require('express');
const redis = require('redis');

const app = express();
// 注意看这里！连接地址写的是服务名 'redis-server'
const client = redis.createClient({ url: 'redis://redis-server:6379' });

client.connect().then(() => console.log('Redis connected!'));

app.get('/', async (req, res) => {
    // 每次访问，缓存数字+1
    const visits = await client.incr('visits');
    res.send(`Hello Docker Compose! 页面已被访问：${visits} 次。`);
});

app.listen(8081, () => console.log('Web server is running on 8081'));
📜 Dockerfile - 把应用打包成镜像
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install express redis
COPY . .
EXPOSE 8081
CMD ["node", "app.js"]

二、核心主角：docker-compose.yml 登场

在这个文件里，我们将定义两个服务(Service)：一个是我们的 Node Web，一个是 Redis。

services:
  web-app:                 # 服务1的名字 (可随意起)
    build: .               # 告诉Compose去当前目录找Dockerfile自动构建镜像
    ports:
      - "8080:8081"        # 将宿主机8080映射到容器内的8081
    depends_on:
      - redis-server       # 告诉Compose，必须先启动下面那个缓存服务

  redis-server:            # 服务2的名字 (代码里根据这个名字连数据库！)
    image: "redis:alpine"  # 这个服务不用自己构建，直接拉取官方镜像
    restart: always        # 即使挂了也会自动重启
🧠
看懂了没？这里的魔法在于： 由于它们在同一个 Compose 文件中，Compose 会自动帮它们创建一个虚拟子网。所以我们的 Node 代码里，直接通过 redis://redis-server:6379 这个主机名就能解析到 Redis 容器的 IP，完全不用担心 IP 地址的变化！

三、见证奇迹：一键启动

在终端来到这个目录下，只需敲下这句神谕：

docker compose up -d --build
  • up：启动整个项目
  • -d：后台运行，不霸占终端界面
  • --build：强制重新根据 Dockerfile 打包最新的代码。如果在开发阶段频繁改代码，这个参数必加！

你会看到终端里唰唰唰输出一堆日志，Compose 正在运筹帷幄：创建网络 my-counter_default，构建 web-app 镜像，拉取 redis 镜像，然后按顺序启动它们。

等到绿色的 Started 出现，打开浏览器访问 http://localhost:8080，疯狂按 F5 刷新，你会看到访问次数在不断飙升，缓存生效了！

四、日常运维常用命令

只要你在这个目录下，管理项目就如同探囊取物：

# 查看当前这组容器的运行状态
docker compose ps

# 查看所有服务的滚动日志 (非常适合排错！)
docker compose logs -f

# 只查看 web-app 这一个服务的日志
docker compose logs -f web-app

# 下班收工！一键停止并删除这组容器和自动创建的网络
docker compose down
⚠️ 踩坑自救室
Q: 为什么日志里报错，Node.js 连不上 Redis？
A: 虽然我们用了 depends_on，但 Docker Compose 只保证容器启动的顺序（先启动 Redis 容器，再启动 Web 容器），它并不知道 Redis 软件内部是否已经完全就绪可以接受连接了。如果 Web 启动太快而 Redis 还在初始化，就会连接失败。解决办法：给 Node.js 增加重试机制，或者使用第三方健康检查工具等待端口监听就绪。
