12. 侦探视角：怎么查日志

🕵️‍♂️ 凌晨三点的崩溃

凌晨三点，老板打来电话：“小明啊，我们的网站崩了，赶紧看看！”

你揉着惺忪的睡眼，连上服务器输入 docker ps，却发现那个叫做 payment-service 的容器不见了！加上 -a 一看，它的状态变成了 Exited (1) 2 hours ago。

容器已经死了，你没法 docker exec 进去看报错。这时候，你唯一的线索，就是它生前留下的“遗言”——日志。

一、时光倒流：基础日志查看

获取容器日志最简单的命令，就是 docker logs 加上容器的名字或 ID：

docker logs payment-service

如果这个容器跑了很久，这行命令会把它从出生到死亡的所有日志像瀑布一样刷在你的屏幕上，让你瞬间看花眼。

1. 只看最后的遗言 (--tail)

通常我们只关心崩溃前最后发生了什么。用 --tail 参数可以只看最后 N 行：

# 只看最后 50 行日志
docker logs --tail 50 payment-service

2. 案发时间的精确过滤 (--since / --until)

如果你知道大老板是昨晚 2 点反馈的问题，你可以只看那段时间的日志：

# 查看过去 2 小时内的日志
docker logs --since 2h payment-service

# 或者指定具体的 ISO 时间
docker logs --since "2023-10-01T01:50:00" --until "2023-10-01T02:10:00" payment-service

3. 让每条日志都有时间戳 (-t / --timestamps)

有些程序的日志自己不带时间打印，这就很让人抓狂。Docker 贴心地提供了一个参数，给每行日志强行打上容器系统时间：

docker logs -t payment-service
# 输出效果：2023-10-01T02:05:11.123456789Z Exception in thread "main"...

二、盯盘模式：实时追踪日志 (-f)

如果容器还在运行，你想实时看着日志来排查刚上线的 Bug，你需要加上 -f (follow) 参数。这和 Linux 里的 tail -f 是一样的感觉：

docker logs -f --tail 20 payment-service

屏幕会停住，每当程序打印一行新日志，屏幕就会实时刷出一条。按 Ctrl + C 可以退出这种盯盘模式。

三、底层揭秘：日志去哪了？

很多新手会有个疑问：“我的程序明明是把日志写在屏幕上 (stdout) 的，Docker 关在后台跑，这些日志存哪了？”

在 Docker 默认配置下，它使用了 json-file 日志驱动。容器里所有输出到 stdout (标准输出) 和 stderr (标准错误) 的内容，都会被 Docker 截获，并悄悄存在宿主机的一个隐藏 JSON 文件里。

⚠️
严重警告：日志撑爆硬盘！

Docker 默认是不会自动清理日志的！如果你的程序日志输出极快（比如高并发网关），几天时间那个 JSON 文件就能膨胀到几十上百 GB，把宿主机硬盘彻底撑爆，导致整个服务器宕机！

防撑爆指南：设置日志轮转策略

在运行容器时，一定要养成加上 --log-opt 参数限制日志大小的好习惯：

docker run -d   --log-opt max-size=10m   --log-opt max-file=3   --name safe-app my-app

这表示：每个日志文件最大 10MB，最多保留 3 个滚动文件。再也不用担心半夜被“Disk Full”警报叫醒了。

四、除了查日志，还能怎么“查房”？

1. 查“户口本”：docker inspect

想看容器到底分配了哪个 IP？挂载了哪个目录？环境变量传对没？用 inspect 查它的元数据：

# 会输出一大串 JSON，建议配合 grep 使用
docker inspect my-app | grep "IPAddress"

2. 查“心电图”：docker stats

想看看是不是程序内存泄漏了？类似 Linux 的 top 命令，你可以实时查看所有容器的 CPU、内存、网络 IO 占用：

docker stats

3. 隔空看进程：docker top

不用进入容器，直接在宿主机上看容器里跑着什么进程：

docker top my-app
🚑 踩坑自救室
Q1: 为什么我用 docker logs 查出来的日志是空的？
A: 这通常是因为你的应用程序把日志写到了容器内的某个文件里（比如 /var/log/app.log），而不是输出到了终端 (stdout/stderr)。Docker 只能捕获到标准输出。解决办法是：要么改代码把日志打到终端，要么用挂载卷把那个日志文件挂载出来看。
🚀
Pro-tip / 老鸟技巧：结构化日志

如果你在做企业级微服务开发，千万不要让程序输出纯文本日志。建议输出 JSON 格式的结构化日志。
Docker 原生支持将日志直接发送到 Syslog、Fluentd 或 ELK 栈，当日志本身是 JSON 时，后续的自动化日志收集、分词、检索、报警都会变得如丝般顺滑。
