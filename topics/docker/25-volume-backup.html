25. 保险箱搬家：数据备份

现在，你的数据库已经用 Volume 保护起来了。但是，如果你的老板说：“小王，这台阿里云的服务器快到期了，周末把数据库完整迁移到腾讯云去。”

你一愣。Volume 是存储在 Docker 宿主机上的（/var/lib/docker/volumes/...），它不是一个普通的文件，我怎么把它整个打包带走呢？这时候，我们就需要用到 Docker 世界经典的“工具人容器 (Helper Container) 战术”了。

图解：工具人战术

我们的核心思想是：不直接去碰深层系统的 Volume 目录，而是临时启动一个小容器。把需要备份的 Volume 挂载给它，再把宿主机的当前目录也挂载给它。让这个工具人在内部执行 tar 打包命令，把压缩包扔到外面来。

flowchart TD
    subgraph 宿主机 Host
        A[需要备份的数据卷: db-data]
        B[当前目录 pwd]
        F(最终产物: backup.tar.gz)
    end
    
    subgraph 工具人容器 Ubuntu (临时启动, 用完即焚)
        C[挂载点 /volume-data]
        D[挂载点 /backup]
        E((执行 tar 命令))
    end
    
    A -.->|挂载 1| C
    B -.->|挂载 2| D
    
    C -->|读取数据| E
    E -->|写入压缩包| D
    D ===> F

实战一：备份出海 (Backup)

假设我们有一个名为 db-data 的数据卷，里面存着 MySQL 的身家性命。我们要把它打包成 backup.tar.gz 放到当前目录。

备份前置条件：下面的 tar 示例只适用于已停止写入的卷。数据库运行中应使用数据库原生的一致性备份方案；确认备份可恢复、数据库版本兼容后，再迁移。恢复到新的空卷，不覆盖唯一的数据副本。

docker run --rm   -v db-data:/volume-data   -v "$(pwd):/backup"   ubuntu   tar cvzf /backup/backup.tar.gz -C /volume-data .

保姆级拆解：

  • --rm: 完事后立马销毁这个工具人容器，不留痕迹。
  • -v db-data:/volume-data: 把需要备份的宝藏挂载到工具人的 /volume-data 目录。
  • -v "$(pwd):/backup": 把宿主机当前目录挂载到工具人的 /backup 目录，作为接应。
  • tar cvzf ...: 工具人干的活。把 /volume-data 里的所有内容压缩，保存到 /backup/backup.tar.gz 里。因为 /backup 映射到了外面，所以压缩包直接出现在你的宿主机当前目录！

服务器大迁徙

拿到压缩包后，你可以用 scp 命令把它传到腾讯云的服务器上：

scp backup.tar.gz root@tx-cloud-ip:/root/

实战二：浴火重生 (Restore)

现在我们来到了全新的腾讯云服务器。首先，我们需要提前建好一个新的保险箱，然后用同样的“工具人战术”，把压缩包解压进去。

🔄 恢复步骤

1. 创建空的数据卷：

docker volume create new-db-data

2. 召唤工具人解压（注意命令最后的 -xzf 变成了解压）：

docker run --rm   -v new-db-data:/volume-data   -v "$(pwd):/backup"   ubuntu   tar xvzf /backup/backup.tar.gz -C /volume-data

3. 启动新的数据库容器，挂载这个装满数据的卷：

docker run -d --name my-mysql -v new-db-data:/var/lib/mysql mysql:8.0
💡
老鸟技巧 (Pro Tip): 数据库专属备份 虽然 tar 备份 Volume 非常通用，但对于像 MySQL/PostgreSQL 这样的关系型数据库，最稳妥的做法其实是使用数据库自带的逻辑备份工具（如 mysqldump）。
例如：docker exec my-mysql mysqldump -uroot -p123456 my_db > backup.sql
这种方式可以在数据库运行时进行热备份，避免了文件系统的锁问题，跨版本恢复也更兼容。
🚑 踩坑自救室
Q: 我打包出来的 tar 文件解压后，里面嵌套了一层 /volume-data 目录，怎么回事？
A: 绝对是 tar 命令写错了！必须带上 -C /volume-data . 这个参数（注意最后的那个点）。-C 表示先 cd 进这个目录，然后再打包里面的内容 .，这样就不会把上一级目录的路径也一起打包进去了。
Q: 报错 Permission denied？
A: Volume 中的某些数据可能具有特殊的权限（比如属于特定的用户 id）。恢复时，必须确保 tar 保留了这些权限。默认情况下 root 用户解压会自动保留权限，但如果遇到麻烦，可以加上 --numeric-owner 参数进行解压。
