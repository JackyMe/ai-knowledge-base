33. Space Cleanup: Conquering "No space left on device"

Here is a classic developer story: You've been happily using Docker for two months—building images every day, pulling new bases, bringing up and tearing down Compose stacks. Suddenly, your terminal throws a blunt, red error:

ERROR: failed to register layer: no space left on device

You stare in disbelief: "My Mac has a 512GB SSD! How on earth is disk space already exhausted?" Today, we put on our cleaner overalls and give Docker a thorough deep-clean.

1. Who Ate My Disk Space?

Docker is a chronic digital hoarder. By default, it preserves everything:

  • Dangling Images: Every time you rebuild my-web:latest, the older image layers lose their tag and become untagged <none>:<none> images orphaned on disk.
  • Stopped Containers: Any container exited without the --rm flag remains on disk, along with all accumulated standard output/error log files.
  • BuildKit Cache: To accelerate subsequent builds, Docker hoards gigabytes of intermediate build cache layers.

Let's audit Docker's disk footprint:

# Inspect Docker disk space utilization
$ docker system df

The diagnostic breakdown is often eye-opening:

TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          42        12        15.8GB    12.4GB (78%)
Containers      18        4         2.1GB     1.8GB (85%)
Local Volumes   5         3         450MB     120MB (26%)
Build Cache     75        0         8.2GB     8.2GB

Look closely at the RECLAIMABLE column! That's tens of gigabytes of dead weight waiting to be reclaimed.

2. Targeted Pruning vs The Nuclear Option

Docker provides the built-in prune suite of commands for safe resource garbage collection.

1. Gentle Targeted Cleanups

Clean up specific resource types on demand:

# Remove dangling (<none>) untagged images
$ docker image prune

# Remove all stopped containers
$ docker container prune

# Remove build cache (often the biggest disk hog)
$ docker builder prune

2. The System-Wide Nuclear Command (Use with Care!)

To perform a comprehensive deep clean and return Docker to pristine condition:

# Cleans all stopped containers, unused networks, dangling images, and unreferenced images
$ docker system prune -a
⚠️
Never Blindly Append --volumes! If you execute docker system prune -a --volumes, Docker will not only delete unused images and containers, but will also permanently destroy all unused named volumes (including persistent database storage)! Always verify your volume backups before touching volume pruning flags.

3. Reclaiming Physical Disk Space in Docker Desktop (Mac/Windows)

On macOS and Windows, you might notice that running prune frees space inside Docker, but your host OS disk space doesn't increase.

The Mechanism: Docker Desktop operates within a virtual disk image (Docker.raw on Mac, or vhdx in WSL2). Like a balloon, virtual disks expand easily during high usage but rarely shrink automatically when data is deleted inside.

The Fix: Open Docker Desktop Settings -> Click the 🐛 Bug icon (Troubleshoot) in the top-right toolbar -> Click Clean / Purge data -> Select Disk image. This compacts or recreates the virtual disk file. Note: Local images will need to be re-pulled afterward.

🚑 Pitfall Rescue Room
Q1: `docker image rm` throws "image is being used by stopped container"?
The image layer is locked by an existing stopped container. Even in the `Exited` state, containers hold references. Delete the container first with `docker rm <container_id>`, then remove the image with `docker rmi <image_id>`.
Q2: How to prevent containers from generating tens of gigabytes of log files?
Do not manually delete raw files inside `/var/lib/docker/containers` (this can crash the Docker daemon). Instead, configure automated log rotation inside your `docker-compose.yml`:
`logging: driver: "json-file", options: { "max-size": "10m", "max-file": "3" }`

Pro-Tip: On continuous integration (CI) runners, build artifacts accumulate rapidly. Senior engineers configure an automated Cron job running nightly: docker system prune -f --filter "until=168h" (automatically clearing artifacts older than 7 days without prompting).
