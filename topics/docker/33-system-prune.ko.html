제33레슨: 디스크 대청소: "No space left on device" 에러 탈출기

Docker를 사용한 지 몇 달 동안 수없이 build하고, 새 이미지를 pull하고, 컨테이너를 up / down하며 즐겁게 개발하던 어느 날, 터미널에 갑자기 싸늘한 붉은색 에러가 나타납니다:

ERROR: failed to register layer: no space left on device (디바이스에 남은 공간이 없음)

512GB나 되는 최신 Mac/PC 하드디스크가 왜 벌써 꽉 찼을까요? 오늘 우리는 Docker 내부의 묵은 쓰레기를 말끔히 청소하는 법을 배웁니다.

1. 내 디스크 용량은 다 어디로 갔을까?

Docker는 개발 생산성을 위해 여러 데이터를 디스크에 차곡차곡 쌓아두는 습성이 있습니다:

  • 댕글링 이미지 (Dangling Images): my-web:latest 이미지를 새로 빌드하면 기존의 구버전 이미지는 이름이 지워져 <none>:<none> 태그의 유령 이미지로 디스크에 남습니다.
  • 정지된 컨테이너 (Stopped Containers): --rm 옵션 없이 실행 후 종료된 수많은 컨테이너들과 그 로그 파일들이 용량을 차지합니다.
  • 빌드 캐시 (Build Cache): 다음 빌드를 가속하기 위해 보관해 둔 엄청난 양의 중간 빌드 레이어 캐시입니다.

docker system df 명령어로 Docker의 디스크 점유 현황을 즉시 확인할 수 있습니다:

# Docker 디스크 사용량 분석
$ docker system df

실제 출력 결과 예시:

TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          42        12        15.8GB    12.4GB (78%)
Containers      18        4         2.1GB     1.8GB (85%)
Local Volumes   5         3         450MB     120MB (26%)
Build Cache     75        0         8.2GB     8.2GB

RECLAIMABLE(회수 가능) 열을 보면 수십 기가바이트의 쓸모없는 찌꺼기 용량이 방치되어 있음을 알 수 있습니다!

2. 안전한 부분 청소 vs 강력한 전체 청소

Docker는 prune(가지치기) 명령어를 통해 쓰레기 청소를 지원합니다.

1) 안전한 부분 청소

특정 유형의 리소스만 골라서 안전하게 청소합니다:

# 댕글링(<none>) 이미지 일괄 삭제
$ docker image prune

# 종료/정지된 모든 컨테이너 일괄 삭제
$ docker container prune

# 거대한 빌드 캐시 청소
$ docker builder prune

2) 강력한 시스템 일괄 대청소 (system prune)

모든 정지된 컨테이너, 미사용 네트워크, 댕글링 이미지, 실행 중이지 않은 빌드 캐시를 한 번에 정리합니다:

# 미사용 컨테이너, 네트워크, 미참조 이미지 일괄 청소
$ docker system prune -a
⚠️
주의: --volumes 플래그를 함부로 붙이지 마세요! docker system prune -a --volumes 명령어를 실행하면, 이미지뿐만 아니라 현재 실행 중인 컨테이너가 참조하지 않는 모든 데이터 볼륨(데이터베이스 영속 데이터)까지 완전히 삭제됩니다! 소중한 DB 데이터가 날아갈 수 있으므로 각별한 주의가 필요합니다.

3. Docker Desktop 가상 디스크 용량 회수 (macOS / Windows)

Mac이나 Windows의 Docker Desktop 사용자는 터미널에서 prune을 실행해도 컴퓨터 본체의 남은 디스크 용량이 늘어나지 않는 현상을 겪을 수 있습니다.

원인: Docker Desktop은 호스트 OS 안에 가상 디스크 파일(Docker.raw 또는 vhdx)을 두고 작동합니다. 풍선처럼 크기가 늘어나는 것은 쉽지만, 내부 파일을 지운다고 해서 가상 디스크 파일의 외형 크기가 자동으로 줄어들지는 않기 때문입니다.

해결법: Docker Desktop 설정 창 -> 상단 🐛 (Troubleshoot) 아이콘 -> Clean / Purge data -> Virtual disk image를 선택하여 가상 디스크를 리셋하고 물리 디스크 공간을 완전히 반환받을 수 있습니다.

🚨 트러블슈팅 응급실
Q1: docker image rm 실행 시 "image is being used by stopped container" 에러가 발생합니다.
A: 정지된 상태의 컨테이너가 해당 이미지를 여전히 참조하고 있기 때문입니다. docker rm <컨테이너ID>로 컨테이너를 먼저 삭제한 후 이미지를 삭제하세요.
Q2: 수십 기가바이트로 불어난 컨테이너 로그 파일은 어떻게 정리하나요?
A: 호스트의 /var/lib/docker/containers 내부 로그 파일을 직접 수동 삭제하면 Docker 데몬 오류가 발생할 수 있습니다. docker-compose.yml에 다음과 같이 로그 롤링 정책을 지정하는 것이 올바른 방법입니다:
logging: driver: "json-file", options: { "max-size": "10m", "max-file": "3" }

프로의 팁 (Pro Tip): 빌드가 빈번한 CI/CD 서버에서는 매일 새벽 Cron Job으로 docker system prune -f --filter "until=168h"(7일 이상 지난 미사용 객체 자동 삭제)을 등록하여 디스크 고갈을 원천 차단합니다.
