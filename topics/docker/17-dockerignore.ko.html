17. .dockerignore 함정 탈출 가이드

입사 첫날 신입 개발자 김 대리가 프로젝트 빌드를 위해 docker build -t myapp .을 실행했습니다. 잠시 후 터미널에 다음과 같은 메시지가 출력되며 끝없이 멈춰 있었습니다:
Sending build context to Docker daemon 12.5GB

"내 프로젝트 소스코드는 고작 5MB인데, 왜 12GB가 넘는 데이터가 전송되고 있지?"
원인을 파악해 보니 로컬 테스트용 temp/ 폴더와 10GB에 달하는 node_modules, 그리고 수 기가바이트의 .git 커밋 히스토리가 통째로 Docker 데몬으로 전송되고 있었던 것입니다. 이것이 바로 .dockerignore 파일이 없을 때 치르는 혹독한 대가입니다.

1. 빌드 컨텍스트(Build Context)의 이해

docker build -t xxx . 명령어 끝에 붙는 점 .은 빌드 컨텍스트 디렉터리를 가리킵니다. Docker는 클라이언트-서버(C/S) 아키텍처로 작동하기 때문에, CLI 클라이언트는 빌드를 시작하기 전에 현재 디렉터리의 모든 파일을 하나의 tar 아카이브로 묶어 백엔드 Docker 데몬 엔진에 전송합니다.

제외 목록을 지정하지 않으면 다음과 같은 3대 재앙이 발생합니다:

  1. 극심한 빌드 지연 (Slow): 수 기가바이트의 불필요한 데이터를 전송하느라 빌드 준비에만 수분이 소요됩니다.
  2. 이미지 비대화 (Bloated): 로컬 임시 파일까지 이미지 내부로 복사되어 수 GB짜리 거대 이미지가 탄생합니다.
  3. 치명적 보안 침해 (Vulnerable): 데이터베이스 접속 비밀번호나 API Key가 적힌 로컬 .env 파일이 이미지에 포함되어 외부에 유출됩니다.

2. 구원투수: .dockerignore

Git의 .gitignore와 정확히 동일한 방식으로 동작합니다. Dockerfile과 같은 디렉터리에 .dockerignore 파일을 생성하고 빌드 시 제외할 파일과 폴더 패턴을 작성하면 됩니다.

3. 패턴 문법: 와일드카드와 화이트리스트(예외 처리)

.dockerignore는 유연한 패턴 매칭을 지원합니다:

  • *.log: 확장자가 .log로 끝나는 모든 파일 제외.
  • temp?: temp1, tempa 등 단일 임의 문자 매칭.
  • **/*.md: 모든 하위 디렉터리에 존재하는 마크다운 문서 일괄 제외.
  • !README.md: 느낌표(!)는 예외(화이트리스트) 지정. 앞에서 *.md를 모두 제외했더라도 !README.md를 추가하면 README.md 파일만은 빌드 컨텍스트에 포함됩니다.
  • # 주석 내용: 샵 기호로 시작하는 줄은 주석 처리됩니다.

4. 적용 전후 비교 (Before vs After)

📊
.dockerignore 적용 전 (재앙): 
$ docker build -t bad-app .
Sending build context to Docker daemon  850.5MB
Step 1/5 : FROM node:18-alpine
...
(빌드 전송 대기 시간: 약 45초 소요)
.dockerignore 적용 후 (최적화): 
$ docker build -t good-app .
Sending build context to Docker daemon  2.15MB
Step 1/5 : FROM node:18-alpine
...
(빌드 전송 대기 시간: 0.2초 만에 완료!)
💡
실무 팁: 캐시 무효화 강제 빌드 (--no-cache)

로컬 소스코드를 수정했는데도 Docker가 파일 변경을 감지하지 못하고 이전 캐시 레이어를 그대로 재사용하는 경우가 있습니다. 이때는 빌드 시 --no-cache 옵션을 부여하여 모든 단계를 처음부터 새로 실행하도록 강제할 수 있습니다:
docker build --no-cache -t myapp .

🚨 트러블슈팅 구조대
Q1: Dockerfile에서 COPY 할 때 "COPY failed: file not found" 에러가 납니다. 로컬에는 파일이 분명히 있는데요?
A: 99% 확률로 해당 파일이나 폴더가 .dockerignore 규칙에 걸려 빌드 컨텍스트에서 제외되었기 때문입니다. Dockerfile의 COPY config/setting.json . 대상이 .dockerignore의 config/에 의해 차단되었는지 확인하세요.
Q2: 빌드된 이미지를 Docker Hub에 올렸는데 .env의 DB 비밀번호가 노출되었습니다.
A: COPY . . 명령이 실행될 때 로컬 .env 파일이 이미지 레이어에 포함되었기 때문입니다. .dockerignore 파일에 반드시 .env를 명시하여 이미지 패키징을 차단하세요! 런타임 환경변수는 배포 시 docker run -e나 --env-file 옵션을 통해 안전하게 주입해야 합니다.
