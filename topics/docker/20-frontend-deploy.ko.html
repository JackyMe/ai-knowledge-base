제20레슨: 우아한 Vue / React 프론트엔드 배포

수많은 프론트엔드 입문자들이 npm run serve나 npm start로 프로젝트를 실행하는 법을 배우고, 그 방식을 그대로 Dockerfile로 가져와 다음과 같이 작성하곤 합니다:

FROM node:24
WORKDIR /app
COPY . .
RUN npm install
CMD ["npm", "run", "serve"]  # ❌ 대참사!

이것은 완전히 잘못된 방식입니다! 개발 서버에는 핫 리로딩(HMR) 코드, 압축되지 않은 원본 소스코드, 수십 MB에 달하는 디버깅 모듈이 포함되어 있습니다. 이미지 용량이 1.2GB를 가볍게 돌파할 뿐만 아니라, 프로덕션 환경에서 성능이 극도로 떨어지고 보안상으로도 매우 취약합니다. 진정한 프로덕션 배포에는 멀티 스테이지 빌드 + Nginx 정적 호스팅 전략을 사용해야 합니다.

1. 골든 표준 워크플로우

  1. 빌드 단계: Node.js 환경 컨테이너에서 npm run build를 실행하여 Vue/React 소스코드를 일반 HTML/CSS/JS 정적 파일로 컴파일합니다(보통 dist 또는 build 디렉토리).
  2. 실행 단계: 컴파일된 순수 정적 파일들만 가볍고 빠른 Nginx 웹 서버 컨테이너로 복사합니다. 수백 MB에 달하는 무거운 Node 런타임과 node_modules는 깔끔하게 버립니다.

결과: 이미지 용량이 1.2GB에서 25MB로 압도적으로 다이어트됩니다!

2. Vue / React 표준 Dockerfile 템플릿

Docker의 "멀티 스테이지 빌드(Multi-stage Build)"를 활용하면 하나의 Dockerfile 안에서 두 개의 FROM을 정의할 수 있습니다.

📄 프론트엔드 표준 Dockerfile (Vue/React 공통)
# ==============================
# 단계 1: 빌드 환경 (builder로 명명)
# ==============================
FROM node:24-alpine AS builder
WORKDIR /app

# 캐시 최적화: 의존성 패키지 파일 먼저 복사
COPY package*.json ./
RUN npm ci 

# 소스코드 복사 및 프로덕션 빌드
COPY . .
RUN npm run build 
# 참고: Vue는 dist 디렉토리를 생성하고, React는 build 디렉토리를 생성합니다. 프로젝트에 맞게 수정하세요.

# ==============================
# 단계 2: 프로덕션 런타임 환경 (Nginx)
# ==============================
FROM nginx:alpine

# 1단계(builder)에서 빌드된 dist 디렉토리를 Nginx 기본 정적 파일 경로로 복사
COPY --from=builder /app/dist /usr/share/nginx/html

# (선택사항) SPA 라우팅 지원을 위한 커스텀 nginx.conf 복사
# COPY nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

3. 프론트엔드 라우팅 구출: 새로고침 시 404 참사 해결

SPA(단일 페이지 애플리케이션, Vue Router의 HTML5 History 모드 등)는 공통적인 문제가 있습니다. 사용자가 /about 경로로 직접 접속하거나 페이지를 새로고침할 때 별도 설정이 없으면, Nginx가 디스크에서 실제 about.html 파일을 찾으려다가 없어서 404 에러를 반환합니다.

해결책: Nginx 설정 파일(nginx.conf)을 작성하여, 요청한 정적 파일이 없을 경우 무조건 진입점인 index.html을 반환하도록 지정합니다. 그 후 브라우저의 프론트엔드 JS가 라우팅을 스스로 해석하게 됩니다.

📄 nginx.conf (SPA 라우팅 완벽 지원)
server {
    listen       80;
    server_name  localhost;

    location / {
        root   /usr/share/nginx/html;
        index  index.html index.htm;
        
        # 핵심 마법 지시문: 요청한 파일이 없으면 index.html로 폴백
        try_files $uri $uri/ /index.html;
    }

    # 선택사항: 로딩 속도 향상을 위한 gzip 압축 활성화
    gzip on;
    gzip_min_length 1k;
    gzip_comp_level 6;
    gzip_types text/plain application/javascript application/x-javascript text/css application/xml text/javascript;
}

이 파일을 Dockerfile과 같은 디렉토리에 배치하고, Dockerfile 2단계의 COPY nginx.conf ... 주석을 해제하면 적용됩니다.

💡
프로의 팁 (Pro-Tip): 프론트엔드 환경 변수 주입 전략

많은 입문자들이 "Docker 환경변수 VUE_APP_API_URL을 프론트엔드에 어떻게 동적으로 전달하나요?"라고 묻습니다. 이것은 대표적인 오해입니다!

프론트엔드 코드는 컨테이너 내부가 아니라 사용자의 브라우저에서 실행되기 때문입니다. 브라우저는 컨테이너 내부의 ENV 환경 변수를 절대 직접 읽을 수 없습니다. 올바른 3가지 해결법:

  1. 빌드 시 주입: npm run build 실행 시 환경 변수를 주입하여 정적 파일 번들에 포함 (가장 일반적인 권장 방식).
  2. Nginx 리버스 프록시 활용: 프론트엔드는 항상 동일 출처의 /api/xxx로 요청하고, Nginx 설정에서 location /api/ { proxy_pass http://backend-server; }로 전달 (CORS 및 동적 백엔드 주소 문제 완벽 해결).
  3. config.js 전역 마운트: public 디렉토리에 별도의 config.js를 두고 런타임에 Volume으로 덮어쓰기.
🚨 트러블슈팅 응급실
Q1: 배포 후 접속했더니 흰 화면(빈 페이지)만 나오고 콘솔에 JS 파일을 찾을 수 없다는 에러가 뜹니다.
A: 대개 Vue/React의 빌드 설정(publicPath 또는 base 속성) 문제입니다. 루트 도메인이 아닌 서브 디렉토리(예: domain.com/myapp)에 배포할 때는 빌드 설정에서 상대 경로 ./ 또는 해당 서브 디렉토리명을 정확히 지정해야 합니다.
Q2: 백엔드 API 호출 시 CORS(교차 출처 리소스 공유) 에러가 발생합니다.
A: Nginx의 동일 출처 기반 리버스 프록시 설정을 강력히 추천합니다. 프론트엔드 코드를 수정할 필요 없이 nginx.conf에 백엔드 프록시 규칙만 추가하면 깔끔하게 해결됩니다.
