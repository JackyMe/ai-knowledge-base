06. Mac & Linux 通关密码

在上一节中我们讲了 Windows 玩家的避坑指南，今天我们来看看对于开发者来说最主流的两个操作系统：macOS 和 Linux，到底该怎么优雅地安装 Docker。这两个系统虽然和 Docker 是“亲戚”（尤其是 Linux 本身就是 Docker 的宿主），但安装时依然有一些坑需要避开。

一、Mac 玩家：优雅的界面派

对于 Mac 用户来说，最推荐的方式就是使用 Docker Desktop，它不仅包含了 Docker 引擎，还带了一个非常友好的图形界面（GUI）和一个用于在 Mac 上运行 Linux 容器的轻量级虚拟机。

🟢 方式一：官方下载（最稳妥）

1. 访问 Docker 官网，注意一定要选对你的芯片架构！

  • 如果你是 M1/M2/M3 等苹果自研芯片，选择 Mac with Apple silicon。
  • 如果你是老的 Intel 芯片 Mac，选择 Mac with Intel chip。

选错了会导致极高的 CPU 占用或者无法启动！如果不确定，点击屏幕左上角苹果图标 -> 关于本机，查看“芯片”一栏。

2. 下载 .dmg 文件后，双击打开，把 Docker 图标拖进 Applications 文件夹。

3. 在启动台中打开 Docker，同意许可协议，然后你会在右上角菜单栏看到一个“小鲸鱼”图标。当小鲸鱼停止动画并且显示绿色的“Docker Desktop is running”时，就大功告成了！

🟡 方式二：Homebrew 安装（程序员最爱）

如果你是一个重度终端用户，早就装好了 Homebrew，那么只需一行命令：

brew install --cask docker

装完后，同样需要在启动台里手动点击一次 Docker 图标来完成初始化配置。

💡
Pro-tip：Mac 性能优化设置 Docker Desktop 默认的资源分配可能不适合你的机器。点击右上角小鲸鱼 -> Settings -> Resources：
1. Memory (内存)：建议分配 4GB-8GB，太少容易导致编译卡死。
2. Virtual disk limit (磁盘)：默认通常是 60GB，如果你的 Mac 存储吃紧，可以调小；同时建议更改 Disk image location 到外接硬盘。
3. VirtioFS：在 General 设置里，强烈建议开启 VirtioFS，这会极大提升 Mac 和 Docker 容器之间的文件同步性能！

二、Linux 玩家：回归原生

Linux 是 Docker 的老家，所以性能是最好的。但是，很多新手最容易犯的错误就是直接使用系统自带的包管理器安装：

⚠️
千万不要这么做！ 不要直接使用 sudo apt install docker 或者 sudo yum install docker。系统默认源里的 Docker 版本通常古老得像化石（比如 Ubuntu 自带的可能是几年前的版本）。老版本不仅不支持新特性，还有安全漏洞。
🔥 推荐方式：官方一键脚本（简单粗暴）

无论你是 Ubuntu, Debian 还是 CentOS，Docker 官方提供了一个智能脚本，自动识别系统并配置最新的源进行安装：

# 1. 下载安装脚本
curl -fsSL https://get.docker.com -o get-docker.sh
# 2. 执行安装（需要 sudo 权限）
sudo sh get-docker.sh

耐心等待两分钟，你会看到类似这样的输出：

# Executing docker install script, commit: 7cae5f34...
+ sh -c apt-get update -qq >/dev/null
+ sh -c DEBIAN_FRONTEND=noninteractive apt-get install -y -qq ...
...
Client: Docker Engine - Community
 Version:           24.0.5

如果你遇到网络问题无法使用脚本，就需要采用手动配置 APT 仓库的方法（作为备用，可参考 Docker 官方文档，需导入 GPG 密钥并添加 sources.list）。

装完必做的两件事（Post-install steps）

Linux 下装完 Docker，如果你直接运行 docker ps，大概率会看到刺眼的 permission denied。因为默认只有 root 用户能操作 Docker。

# 1. 把当前用户加入 docker 用户组（免 sudo 魔法）
sudo usermod -aG docker $USER

# 2. 设置开机自启
sudo systemctl enable docker
sudo systemctl start docker

注意：添加用户组后，你必须注销并重新登录（或者重启终端、执行 su - $USER），组权限才会生效！

🚑 踩坑自救室：Linux 安装常见问题
Q1: 运行 docker ps 报错 "permission denied while trying to connect to the Docker daemon socket"
A: 典型的新手坑。说明你没把当前用户加入 docker 组，或者加了之后没有重新登录。临时解决可以用 sudo docker ps，彻底解决请执行上面的 usermod 命令并重新登录。
Q2: 报错 "Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?"
A: Docker 服务没起来。执行 sudo systemctl status docker 查看状态。如果没启动，用 sudo systemctl start docker。如果启动失败，用 sudo journalctl -u docker.service 查看具体报错日志（多半是由于配置文件写错了，比如后面我们会讲的 daemon.json 格式错误）。
Q3: 我是 WSL2 (Windows 里的 Linux)，systemctl 提示 "System has not been booted with systemd"
A: 旧版 WSL2 默认不启用 systemd，用的是 init 系统。你需要执行 sudo service docker start 来启动。或者在 /etc/wsl.conf 中启用 systemd。
🌟
老鸟技巧：Linux 下的替代方案 Podman 在企业级 Linux（如 RHEL, CentOS）中，现在越来越流行使用 Podman 替代 Docker。Podman 与 Docker 命令 100% 兼容（你可以 alias docker=podman），最大优势是不需要后台 daemon 进程，且可以完全无 Root 权限运行，更加安全。对于入门阶段，我们依然以 Docker 为主，但你可以把 Podman 作为拓展了解。
