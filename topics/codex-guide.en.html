3. Selection Prism ②: Combining App, CLI, IDE & Cloud

✅ Recommended Pipeline (High Efficiency Practice)
  • Planning & Discovery: Run /plan in Desktop App or CLI to assess impact;
  • Core Implementation: Interactive coding in CLI or IDE with instant diff checks;
  • Heavy Refactoring / Mass Migration: Delegate to codex cloud exec --attempts 3;
  • Pre-Merge Gate: Trigger @codex review for automated double-checking.
❌ Common Anti-Patterns (Causes Fragility & Drift)
  • Asking regular Web Chat for long code blocks and copy-pasting manually;
  • Blocking your local CLI on a 30-minute massive migration task;
  • Letting the agent apply broad automated replacements on a dirty git working tree;
  • Guessing frontend interactions without real browser E2E verification.

Methodology 05

Core Methodology & 8 Anti-Patterns

1. The 4-Anchor Formula (Goal-Context-Constraints-Done)

  • Goal: Express exactly what needs to be delivered in one concise sentence;
  • Context: Pinpoint key files and relevant documentation using /mention;
  • Constraints: State files that must not be edited, forbidden dependencies, or backward-compatibility bounds;
  • Done-when: Define objective verification criteria (e.g. specific test suite passing).

2. Top 8 Newcomer Anti-Patterns

#Anti-PatternConsequenceDefense SOP
01Jumping straight into editing without a planBroad unrelated changes that break architectureEnforce /plan before any multi-file change
02Working on a dirty git working treeAgent edits blend with uncommitted work; rollback is impossibleAlways git stash or create a clean feat/xxx branch
03Assuming Ctrl+L starts a fresh conversationResidual context causes subtle hallucinationsAlways reset context via /new or /clear
04Chaining multiple unrelated tasks in one threadContext window fills up; reasoning quality degradesOne session per discrete goal; run /new upon completion
05Ignoring network restrictions when installing packagesworkspace-write blocks internet; package managers time outExplicitly approve network access or configure proxies
06Trusting verbal "Done" without viewing diffsSilent bugs and unwanted regressions slip throughAlways run /diff to review line by line
07Fixing bugs by guessing instead of testingAgent wraps errors in try/catch to suppress symptomsEnforce TDD: Write failing test first, then fix to green
08Using --yolo on your personal machineRisk of credential leakage or accidental system file deletionsReserve --yolo strictly for isolated disposable containers
Collaboration 06

Long Tasks & 4-Stage Separation

When dealing with complex tasks lasting over 30 minutes, rolling everything in one session leads to severe context pollution. Use Separation of Concerns:

  1. Discuss & Plan: In read-only mode, run /plan to produce a precise file list, design decisions, and risk assessments. Zero code modifications.
  2. Isolated Execution: In a fresh session with workspace-write, feed the approved plan and execute changes with incremental tests.
  3. Independent Review: In a fresh thread or via /review, audit the diffs from an outside perspective for security and edge cases.
  4. Closeout & Handover: Extract test evidence, update DECISIONS.md and AGENTS.md, and draft structured PR descriptions.
Memory 07

Task Closeout & Memory Loop

1. The 3-Step Closeout Protocol

  1. Gather Hard Evidence: Export test suite logs and capture E2E browser screenshots of UI changes.
  2. Record Decisions in DECISIONS.md: Document rationale behind architecture choices and known constraints.
  3. Incrementally Update AGENTS.md: Add newly discovered run commands or build requirements so future sessions don't need re-prompting.

Best Practices & Optimal Examples Library

To ensure you push Codex to its absolute limits, we've compiled the industry's universally recognized best techniques, standard command combinations, and the most bulletproof Prompt templates, making it easy for anyone to learn and replicate.

1. The Ultimate Prompt Template: Zero-Hallucination TDD

This is the task assignment template with the highest success rate in real-world enterprise projects. By enforcing strict constraints and acceptance criteria, it prevents the model from "freestyling":

> [Goal] Add Refresh Token sliding window renewal logic to src/auth/jwt.ts.
  [Context] Read docs/auth-flow.md and the current jwt.ts code.
  [Constraints]
  1. Only modify jwt.ts and corresponding test files. Do NOT touch the routes module.
  2. Keep the existing HMAC-SHA256 signature algorithm. Do not introduce new npm libraries.
  3. Beware of concurrent locks; prevent the same Token from being refreshed twice.
  [Acceptance]
  First, write 3 test cases in tests/auth/jwt.test.ts (including a concurrency test).
  Run the tests until they all pass green. Finally, show me the /diff.

ADV

Squeezing Membership Value: Independent Quotas & Cross-Platform Best Practices

Many developers buy ChatGPT Plus or Pro but use them as a single chatbox or a simple terminal tool, completely wasting "invisible and independent high-value quotas." OpenAI has fully embraced a "Surfaces" strategy, where Web, Workspaces, Image Generation, and the Codex terminal actually have isolated resources. Don't care about the specific numbers? Just want to know how to maximize value? Read on.

🚀 Core Strategy: Task Separation across Surfaces

Don't do everything inside Codex! Terminal context and tool usage are highly expensive. The best practice is: "Use the Web for Reconnaissance, Codex for Execution."

  • 1. Independent Quota: Web "Deep Research"
    The Web's Deep Research is an independent Agent built to scour and synthesize the internet, utilizing quotas separate from normal chat or fast Codex inference. When learning a brand-new framework (like React 20) or integrating multiple technical docs, trigger /Deepresearch on the Web. Have it write a hyper-detailed Architecture_and_API_Ref.md, then feed that Markdown file into your local Codex for implementation.
  • 2. Independent Quota: Image 2.0 / 2.5 Visual Pipeline
    Image generation (DALL-E 3 / Image 2.5) has isolated queues and quotas on the Web. Never ask Codex to hallucinate UI blindly in the terminal. Best Practice: Ask the Web UI to "generate a modern SaaS dashboard UI using Image 2.5 layout precision." Use Web Inpainting to tweak details. Once you have the perfect mockup, pass that image to Codex for Vision-to-Code implementation.
  • 3. Web "Projects" as your External Brain
    Plus members can create Web Projects. Upload dozens of API manuals and massive PRDs into a Web Project (which has dedicated caching and doesn't burn your local terminal token quota on every request). Digest the complex requirements into pseudo-code on the Web, then let Codex execute it locally.
  • 4. Sparingly Use "Thinking Mode"
    Flagship reasoning models (like o3 or Astra-Think) are incredibly powerful but heavily rate-limited. In Codex, for simple syntax errors or comments, instantly switch to a fast model via the Model Picker. Only unleash "Thinking" mode when facing complex, cross-module state machine corruption.
