개념 00

전체상: 프롬프트 엔지니어링에서 컨텍스트 엔지니어링으로

2023년에 널리 회자된 '프롬프트 엔지니어링(어떻게 질문할 것인가)'은 2026년 현재 컨텍스트 엔지니어링(모델에 노출되는 모든 정보를 어떻게 설계하고 관리할 것인가)으로 진화했습니다. 단발성 질의응답에서 '자율적인 작업 완수'로 AI의 역할이 전환되었기 때문입니다.

항목프롬프트 엔지니어링 (단발형)컨텍스트 엔지니어링 (에이전트 시대)
최적화 대상단일 지시문의 표현컨텍스트 윈도우 전체에 무엇을, 언제 넣고 언제 비울 것인가
주요 제약지시의 명확성Attention(주의 집중) 예산의 유한성: 과도한 토큰으로 인한 주의 분산
대표적 액션예시 추가, 출력 포맷 지정시스템 프롬프트 계층화, 도구 세트 최소화, 압축 및 메모리 분리
공식 정의최소한의 고신호 토큰 세트를 통해 목적하는 결과물을 얻을 확률을 극대화한다 (Anthropic Context Engineering 논문 발췌)
마인드셋과 엔지니어링의 역할 분담AI 활용 효율 맵 & 마인드셋이 "AI로 무엇을 할 수 있는가·어떻게 접근할 것인가(원칙)"를 다룬다면, 본 문서는 "구체적으로 어떻게 작성하고 정보를 전달할 것인가(구현)"를 다루는 실무 매뉴얼입니다.
기법 01

7대 기본 기법 (❌/✅ 대조)

1. 명확성과 구체성 (Be Clear & Direct)

❌ 모호한 지시"코드 좀 리팩토링해서 깔끔하게 만들어 줘"
✅ 구체적 지시"`calculateTotal` 함수 내부의 다중 중첩 if 문을 가드 절(Early Return)로 변경하고, 계산 로직을 순수 함수로 추출해 주세요"

2. Few-shot (구체적 입출력 예시 제시)

❌ 추상적 규칙 지시만 제공"사용자 피드백을 감성 분석해서 긍정/부정으로 분류해 줘"
✅ 2~3건의 입출력 예시 병기"입력: '동작은 빠른데 UI가 복잡함' → 출력: `{"sentiment": "mixed", "aspects": {"performance": "+", "ui": "-"}}`와 같은 포맷으로 출력"

3. 사고 과정 명시 (Chain of Thought / CoT)

❌ 즉시 정답 요구"이 알고리즘의 시간 복잡도를 구해 줘"
✅ 사고 단계 지정"먼저 각 루프의 실행 횟수를 수식화하고, 최악의 시나리오를 특정한 뒤, 최종 Big-O 표기법을 도출해 주세요"

4. 구조화 태그를 통한 컨텍스트 분리 (XML/Markdown Tags)

❌ 지시와 참고 자료 혼재"다음 기사 요약해 줘. 기사 내용: ..."
✅ 태그로 영역 구분"`<document>...</document>` 내부 자료를 기반으로, `<instructions>...</instructions>`에 따라 요약해 주세요"

5. 역할과 페르소나 정의 (Role & Persona)

❌ 일반론적 답변 유도"이 보안 아키텍처를 평가해 줘"
✅ 전문적 관점 부여"당신은 금융권 시스템의 수석 보안 아키텍트입니다. OAuth 2.0 PKCE 플로우의 토큰 탈취 위험성에 초점을 맞춰 리뷰해 주세요"

6. 네거티브 제약 (금지 사항의 명확화)

❌ 긍정 지시만 제공"React 컴포넌트를 작성해 줘"
✅ 금지 사항 병기"외부 라이브러리를 새로 설치하지 말고, CSS-in-JS 대신 반드시 CSS Modules를 사용해 주세요"

7. 출력 포맷 엄격 지정

❌ 자연어 줄글 출력"변경 사항 목록을 알려줘"
✅ 스키마나 Markdown 테이블 지정"`파일 경로 | 변경 종류 | 변경 이유` 3개 열의 Markdown 테이블 형식으로 출력해 주세요"
기법 02

구조화 출력 & 포맷 제어

프로그램에 의한 자동 처리를 구현할 때 JSON Mode나 Structured Outputs(Pydantic 스키마 등)를 활용하면 파싱 에러 발생률을 물리적으로 0에 가깝게 낮출 수 있습니다.

# Pydantic 스키마를 활용한 안전한 구조화 출력
class CodeAuditResult(BaseModel):
    has_vulnerability: bool
    severity: Literal["LOW", "MEDIUM", "HIGH", "CRITICAL"]
    cve_id: str | None = None
    remediation_steps: list[str]
기법 03

멀티모달 프롬프트 작성 요령

  • UI 스크린샷: 적절한 해상도를 유지하고, 핵심 영역을 빨간 테두리나 번호로 강조.
  • 설계서 및 PDF: 페이지 수가 많은 경우 해당 챕터만 추출하여 주입함으로써 Attention 분산 방지.
  • OCR 텍스트 병용: 이미지와 함께 추출 가능한 텍스트 데이터를 함께 넘기면 모델 인식률이 비약적으로 상승.
사용 사례 & 모델 비교 04

주요 대형 모델 프롬프트 특성 비교

모델프롬프트 특성최적의 지시 스타일
Claude (Anthropic)XML 태그(<context> 등) 인식력이 매우 우수하며 지시 준수율이 뛰어남.긴 문서를 태그로 구조화하고 세부 제약 사항을 명확히 전달.
OpenAI (GPT-4o / o3)System 프롬프트 민감도가 높고 JSON Mode 및 Tool Calling 연동이 견고함.시스템 롤에서 전제를 확정하고 함수 스키마를 엄격히 정의.
Gemini (Google)초대형 컨텍스트(2M) 횡단 추론 및 Context Caching에 강점.방대한 문서를 한 번에 주입하고 캐시를 활용하여 질의.
사용 사례 & 모델 비교 05

RAG 시나리오 프롬프트 설계

RAG(검색 증강 생성)에서는 검색된 컨텍스트를 모델이 '절대적 사실'로 우선하도록 프롬프트로 제어합니다:

<system>
반드시 아래 <sources>에 기재된 정보만을 근거로 답변하세요.
자료 내에 답변 근거가 존재하지 않는 경우, 일반적인 추측을 하지 말고 "제공된 자료에는 해당 내용이 없습니다"라고 명확히 밝히세요.
모든 주장 뒤에는 [1]과 같이 출처 번호를 표기하세요.
</system>
엔지니어링 06

컨텍스트 엔지니어링 핵심: 주의력은 희소 자원이다

"컨텍스트 윈도우가 크다고 해서 모든 것을 다 집어넣어도 된다는 뜻은 아닙니다." 컨텍스트 내의 정보량이 증가할수록 토큰당 Attention 집중도는 필연적으로 저하됩니다.

  • 고신호·저노이즈: 불필요한 빌드 결과물이나 무관한 코드는 철저히 제외.
  • 위치 편향 (Lost in the Middle): 중요한 지시나 규칙은 컨텍스트의 맨 앞이나 맨 뒤에 배치.
  • Context Caching 활용: 정적인 명세서나 리포지토리 정의는 캐싱하여 비용과 지연 시간 단축.
엔지니어링 07

에이전트 컨텍스트 관리 (장기 작업)

장시간 자율 작업을 수행하는 에이전트의 컨텍스트 비대화와 방향 상실을 방지하기 위한 설계입니다:

  • 서브에이전트 분할: 조사(Research), 계획(Plan), 구현(Coder)별로 독립된 컨텍스트 부여.
  • 중간 산출물 영속화: 사고 과정을 디스크 상의 Markdown(implementation_plan.md 등)에 기록하여 기억을 외부화.
  • 컨텍스트 정기 리프레시: 단일 세션에서 과도하게 반복하지 않고 적절한 시점에 새 세션 시작.

실전 11

실전 수정 사례집 (총 6선)

사례 01 · 개발

디버깅 프롬프트: '좀 봐줘'에서 근본 원인 규명으로

상황: API 엔드포인트에서 가끔 30초 타임아웃이 발생하여 원인을 찾고 싶은 경우.

❌ 수정 전 프롬프트
api/orders.ts에서 타임아웃 에러가 나는데 왜 이러는지 좀 봐줘.
✅ 수정 후 프롬프트
<error> TimeoutError: request timed out after 30000ms at fetchUserOrders (api/orders.ts:88) </error> 작업: 이번 타임아웃의 근본 원인을 파악하세요 (단순히 타임아웃 시간을 늘리는 임시방편 제외). Done-when: 1. 쿼리/네트워크/외부 의존성 중 구체적으로 어디서 지연되는지 증거(실행 계획, 시간 측정) 제시 2. 증상을 덮는 것이 아닌 근본 원인을 해결하는 수정안 제시 3. 당장 원인 특정이 어렵다면 임의 변경 대신 진단용 로깅 추가 먼저 조사 계획을 제시하고, 제 승인 후 코드를 수정하세요.

핵심: '좀 봐줘' 식의 지시는 모델이 임시방편(타임아웃 120초로 변경)을 선택하게 만듭니다. Done-when으로 근본 해결을 강제해야 합니다.

사례 02 · 데이터

데이터 분석 프롬프트: 암산 대신 코드로 정확한 계산

상황: 200행의 매출 명세표에서 지역별 전월 대비 성장률을 구하고 싶은 경우.

❌ 수정 전 프롬프트
<data>...(200행 데이터)...</data> 각 지역의 이번 달 매출 성장률을 계산해서 높은 순으로 정렬해 줘.
✅ 수정 후 프롬프트
<data>...(200행 데이터)...</data> 각 지역의 이번 달 매출 성장률을 계산하고 내림차순 정렬하세요. 요구사항: 1. 암산하지 말고 반드시 Python 코드를 작성하여 실제 실행하고, 코드와 결과를 함께 보여주세요. 2. 결측치나 형식 이상이 있다면 건너뛰지 말고 먼저 지적하세요.

핵심: LLM은 계산기가 아닙니다. 수치 연산은 반드시 '코드로 계산하라'고 지시해야 정확도를 담보할 수 있습니다.

사례 03 · 지식 작업

회의록 요약: 긴 문서 속 지시 누락 방지

상황: 40분 회의 녹취록에서 액션 아이템과 논의가 부족했던 결정을 추출하고 싶은 경우.

❌ 수정 전 프롬프트
회의 액션 아이템 정리해 줘: ...(3천 자 녹취)... 아 그리고 논의 부족했던 결정도 표시하고 담당자랑 기한도 적어줘.
✅ 수정 후 프롬프트
