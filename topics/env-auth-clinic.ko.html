방법론 00

증상별 빠른 진단 + 장애 분류 맵

⚡ 3줄 요약 해결 (문제의 70%는 여기서 즉시 해결) ① env | grep -iE 'anthropic|openai'로 세션을 가로채고 있는 환경 변수를 찾아 unset 처리;
② 깔끔한 재로그인: /logout 후 /login (Codex: codex logout && codex login);
③ 자격 증명 확인: /status 또는 codex login status로 정상 계정과 로그인 방식인지 확인.

4대 근본 원인 맵

근본 원인전형적인 증상발생 이유
① 복수 설치 경로 충돌버전이 제멋대로 바뀌거나 업데이트가 반영되지 않음공식 네이티브 설치, npm 글로벌, Homebrew, IDE 내장 바이너리가 공존하며 PATH 우선순위 충돌
② 자격 증명 소스 충돌"로그인했는데 Invalid API key가 뜸", 구독 계정인데 API 종량 과금됨환경 변수에 설정된 API Key가 브라우저 OAuth 구독 자격 증명보다 우선순위가 높기 때문
③ 설정 계층 오버라이드"설정을 바꿨는데 적용이 안 됨", 회사 PC에서 설정이 잠김Enterprise 정책 > CLI 인자 > 프로젝트 로컬 > 프로젝트 공유 > 사용자 전역 순으로 덮어씀
④ 네트워크 및 시스템 환경로그인 콜백 멈춤, TLS/인증서 오류, 다운로드 403기업 프록시, 사설 CA, 방화벽이 로컬 콜백 포트(Codex는 1455) 차단
방법론 01

5계층 진단법 + 원클릭 진단 스크립트

유일한 진단 원칙: 하위 계층부터 상위 계층으로 순차 확인하고, 한 층의 확인이 끝난 뒤 다음 층으로 넘어갈 것.

L1
바이너리 계층 —— 실제로 실행되는 프로그램은 무엇인가?

which -a claude / which -a codex로 PATH 내 중복 바이너리 확인; claude --version 확인.

L2
환경 변수 계층 —— 동작을 가로채는 변수가 있는가?

env | grep -iE 'anthropic|claude|codex|openai|proxy' 실행. 의도치 않은 ANTHROPIC_API_KEY 확인.

L3
자격 증명 계층 —— 현재 어느 계정으로 인증되어 있는가?

Claude Code 세션 내 /status 실행; Codex는 codex login status 확인.

L4
설정 계층 —— 어떤 계층의 설정이 적용 중인가?

Claude Code: claude doctor 및 /config; Codex: /debug-config 확인.

L5
네트워크 계층 —— API 서버와 정상 통신 가능한가?

curl -sI https://api.anthropic.com 또는 curl -sI https://api.openai.com 연결성 테스트.

원클릭 진단 스크립트 (읽기 전용)

#!/bin/bash
# ai-env-check.sh —— Claude Code / Codex 환경 원클릭 자가진단 (읽기 전용)
# 사용법: bash ai-env-check.sh
echo "═══ L1 바이너리 계층 ═══"
for c in claude codex; do
  if command -v "$c" >/dev/null 2>&1; then
    which -a "$c"; "$c" --version 2>/dev/null | head -1
  else echo "(미설치 또는 PATH에 없음: $c)"; fi
done

echo; echo "═══ L2 환경 변수 계층 ═══"
env | grep -iE 'anthropic|claude|codex|openai|https?_proxy|no_proxy' || echo "(깨끗함: 관련 환경 변수 없음)"

echo; echo "═══ L3/L4 설정 및 디렉토리 ═══"
[ -d ~/.claude ] && echo "Claude Home: ~/.claude (존재함)"
[ -d ~/.codex ] && echo "Codex Home: ~/.codex (존재함)"
echo "═══ 진단 완료 ═══"
Claude Code 02

Claude Code 인증 메커니즘과 우선순위

자격 증명 우선순위 (높은 순서대로)

  1. 환경 변수 ANTHROPIC_API_KEY: 이것이 설정되어 있으면 브라우저 OAuth 로그인을 완전히 무시하고 종량제 API Key로 동작합니다! (가장 흔한 과금 오류의 원인)
  2. 클라우드 프로바이더 환경 변수: CLAUDE_CODE_USE_BEDROCK=1 또는 CLAUDE_CODE_USE_VERTEX=1
  3. 브라우저 OAuth 구독 자격 증명: claude.ai 웹 OAuth 로그인 (macOS 키체인 또는 ~/.claude/.credentials.json)
Codex 05

Codex 인증 메커니즘과 저장 포맷

Codex는 ~/.codex/auth.json에 평문으로 OAuth 토큰을 저장합니다. 브라우저 로그인 시 로컬 http://localhost:1455로 콜백을 수신합니다. 포트가 차단되면 로그인이 멈추므로 방화벽을 확인해야 합니다.

시나리오 08

공용 PC / 타인 설정 인수인계 시 정화 절차

  1. 환경 변수 정화: ~/.zshrc, ~/.bashrc에서 이전 사용자의 export ANTHROPIC_API_KEY 또는 프록시 설정 제거;
  2. 자격 증명 삭제: rm -rf ~/.claude/.credentials.json ~/.codex/auth.json;
  3. 순수한 본인 계정으로 재로그인: claude 및 codex login 실행.
시나리오 10

SSH / Docker / CI 헤드리스 환경 인증

브라우저가 없는 원격 서버에서는 SSH 포트 포워딩을 이용하거나 터미널 출력 URL을 로컬 브라우저에서 열어 인증 코드를 붙여넣습니다:

# Codex 로컬 포트 포워딩 (콜백 수신용)
ssh -L 1455:localhost:1455 user@remote-server

# Claude Code 헤드리스 인증
claude login --no-browser   # 표시된 URL을 로컬에서 열고 코드를 터미널에 입력
만능 복구 12

만능 복구: 3단계 리셋 SOP

  1. 1단계 소프트 리셋 (Soft Reset): 세션 내 /logout 후 /login;
  2. 2단계 자격 증명 리셋 (Auth Reset): ~/.claude/.credentials.json 및 ~/.codex/auth.json 삭제 후 재로그인;
  3. 3단계 완전 초기화 (Nuclear Reset): rm -rf ~/.claude ~/.codex 실행 후 툴 재설치 (최후의 수단).
