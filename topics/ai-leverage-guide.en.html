Cognition 00

Panorama Map: What AI is Good at and What it isn't

First establish an honest understanding of capability boundaries, then talk about efficiency. By mid-2026, general large models (Claude / GPT / Gemini) are already "stably usable" in the left column of the table below, while the right column still requires human backup—putting tasks in the wrong column is the source of all disappointment.

✅ Good at (safe to delegate)⚠️ Not good at (human must check)
First draft generation: Articles, code, plans, emails—from 0 to 60 points extremely fastThe last 20 points: Perspectives, taste, trade-offs, still human work
Format conversion & structuring: Messy notes→tables, transcripts→minutes, requirements→code skeletonFactual accuracy: Can invent seriously (hallucinations), important facts must be verified
Summary compression: Extract key points from long docs, papers, meeting recordsTimely information: Events after training cutoff are unreliable without web search
Translation & polishing: Near-native level, controllable styleLong-chain unverified tasks: Multi-step tasks without checkpoints, errors compound
Brainstorming: 10 options at once, human picksPrecise calculation & counting: Let it write code to calculate, don't let it do mental math
Cross-domain intro explanations: A "patient tutor" for any subjectResponsibility & decision-making: High-risk medical/legal/investment decisions, AI is just an advisor
Code: Scripts, bug fixes, error explanations—compilers and tests are natural safety nets"Do it all for me": The more vague the full delegation, the higher the failure rate

Three Counter-intuitive Data Points

  • Programming is still the #1 use, but personal life usage is surging. Anthropic Economic Index shows tasks related to "Computer & Math" professions account for ~35% of Claude chats, the highest of all categories; meanwhile, personal usage rose from 35% to 42% (2025-11 → 2026-02).
  • Over half of tasks are "collaboration" not "automation". 57% of tasks are iterative human-AI collaboration, 43% are delegated automation—showing the current best approach remains "AI works, human directs and verifies."
  • Wrong paradigm makes you slower with AI. METR 2025 RCT: 16 senior open-source developers using AI tools on their familiar large codebases were actually 19% slower in completing tasks—but self-reported feeling 20% faster.
Correct Interpretation of METR ResearchIt proves not that "AI is useless," but: In fields where you are "already extremely proficient," AI gains are minimal; the perceived efficiency heavily overestimates the actual efficiency. Inversely—the greatest AI gains are in unfamiliar fields, repetitive manual labor, and first drafts from scratch. Choosing the right scenario + paradigm brings true efficiency. The rest of this page answers "how to choose, how to use."

Scenario × Benefit Matrix: Where Efficiency Gains Are Greatest

Eight major scenarios ranked by "efficiency potential". The potential isn't determined by how cool the tech is, but by three questions: Is there a way to verify? How high is the cost of being wrong? Is it highly repetitive? The easier the verification, higher the fault tolerance, and more repetition, the more it deserves immediate AI adoption.

Scenario Paradigms 02

Programming Scenario Best Paradigms (Claude Code / Codex)

The official best practices of both companies have highly converged in 2026, and can be summarized as a four-step workflow + five core habits. For detailed operations, see the Claude Code Guide and Codex Guide in this repository. Here we only talk about "paradigms".

Official Consensus: Four-Step Workflow

  1. Explore——Enter plan mode (Claude Code's plan mode / Codex's /plan), let AI read code and answer questions first without making changes
  2. Plan——Require specific implementation plans: what files to change, in what order, how to verify; reviewing plans is 10x cheaper than reviewing code
  3. Implement——Exit plan mode to execute, write while running tests; small tasks (where the diff can be explained in one sentence) can skip the first two steps
  4. Commit——Review diffs, run full verification, write clear commit messages; AI's work must also pass human review

Five Core Habits

HabitPractice
Give AI runnable verificationOfficial words: Give it a pass/fail check (test, build, script, screenshot diff), the loop runs automatically; without verification, "looks done" is the only signal, making you a manual QA tester
State completion criteria clearlyCodex recommended task structure: Goal + Context (files/docs) + Constraints + Done when (criteria)—With all four elements, rework drops off a cliff
Iterate in small steps, correct earlyIf it goes off track, interrupt immediately with Esc; if it's still wrong after correcting the same issue twice, stop correcting—restart with /clear, and write a better initial prompt using what you learned
Manage context wellContext window is the primary resource: use /clear between unrelated tasks; delegate broad searches to sub-agents, don't let the main chat fill up with file contents
Solidify project memoryWrite repeatedly explained rules into CLAUDE.md / AGENTS.md, and keep them concise—only keep them if "AI will make a mistake if this line is deleted"
✗ Vague delegation"Fix the login bug"

AI can only guess: Which login? What symptoms? What constitutes fixed?
✓ Verified delegation"Users report login fails after session timeout. Check token refresh logic in src/auth/. Write a failing test to reproduce the issue first, then fix it, and finally run the full auth test suite to ensure it's green."

Non-programmers can play too: vibe coding

"Vibe coding" (coined by Karpathy in Feb 2025, Collins Dictionary Word of the Year 2025), which uses natural language to let AI write and debug code from start to finish, has enabled many zero-foundation users to create personal tools like bookkeeping apps, habit trackers, and cutting calculators. Community stats claim over half of such users have never written code. But recognize the boundaries: Build personal tools freely; for products that charge money or store others' data, security and ops still need professional oversight.

Scenario Paradigms 03

Writing & Documentation Scenario Paradigms

Core division of labor in one sentence: AI provides drafts and structure, human provides viewpoints and facts. Treat AI as a "tireless draft machine + structural editor", not a ghostwriter.

Four Prompt Elements (MIT Sloan Teaching Consensus)

Effective writing prompt = Role/Context (who you are, who you write to) + Task & Format (what to produce, what structure) + Tone & Audience + Constraints (word count, things to include/avoid). Provide all four for the highest first-try success rate; then refine iteratively via chat: "Shorter", "Expand the 2nd paragraph", "Change to a tone for the boss".

Verified High-Return Use Cases

Use CaseHow to do it
3-Version Outline MethodProvide materials, ask for 3 outlines with different focuses → human picks one (or mixes them) → then expands section by section. Much higher quality than asking for the full text upfront
Meeting Recording → MinutesThrow the full transcript to AI: "Extract three lists: decisions, action items (owner + deadline), and leftover issues"
Long Text Compression"Compress into a 200-word summary + 10 bullet points, preserving all numbers and conclusions"—read the summary before reading the doc to decide if close reading is needed
Reverse OutlineThrow your own draft back to AI: "Outline this article in reverse, point out logical gaps and repetitions"—more effective than "help me polish"
De-AI FlavorGive it 2-3 paragraphs of your old writing as a style sample; explicitly ban clichés ("In today's fast-paced era..."); require short sentences, specific nouns, and numbers
Multilingual PolishingChinese thoughts → English email/doc, specify occasion and relationship, output is near-native
  1. Give all raw materials (notes/data/links) to AI at once, ask for an outline first, not full text
  2. Human defines the outline and core viewpoints—this is the soul of the article, do not outsource
  3. Generate drafts section by section, giving specific instructions for each (points, examples, length)
  4. Manually verify all facts, numbers, citations—AI's citations must be clicked and confirmed one by one
  5. Finally, read through and edit it yourself: tweak it until it "sounds like you"
Two Red Lines① Facts and citations must be manually verified—models confidently invent literature and data, fatal in academic and business scenarios. ② Don't paste sensitive info (customer data, unreleased business numbers, others' privacy) into public AI services; use enterprise or local solutions.

Scenario Paradigms 04

Research & Learning Scenario Paradigms

Research: Deep Research Four-Step Method

  1. Clarify problem boundaries first—What to research, what not to research, judgment criteria, expected output format; the clearer the boundaries, the more useful the report
  2. Run deep research—ChatGPT / Gemini / Claude's Deep Research-like features will autonomously retrieve, cross-read, and produce cited reports in 10-30 mins
  3. Follow-up and trace—Follow up on key conclusions one by one: "What's the source for this?", click links to verify; fake citations are a high-risk area
  4. Cross-validation—For important decisions, run the same prompt with a second model and compare differences; differences are usually where human deep-dives are needed

Learning: Treat AI as a tutor, not an answer machine

ParadigmPrompt Template
Custom Baseline"I want to learn X. Give me 5 questions first to test my level, then set a 4-week study plan based on the results"
Socratic"Don't give the answer directly, use questions to guide me to figure it out"—combats the "illusion of understanding"
Feynman Test"I'll explain X in my own words, you point out where I'm wrong or vague"
Difficulty Tuning"Explain it to a 12-year-old first, then the pro version, then give me a minimal hands-on exercise"
Deliberate Practice"Give me 3 progressively harder questions daily; after I answer, grade and explain mistakes"
Research Endorsement: Usability is TrainedAnthropic's "Learning curves" report (2026-03) found: Experienced users have an ~10% higher task success rate than novices, and they use iterative collaboration more than one-shot delegation, matching model capability to task difficulty better. The best way to learn AI is high-frequency use + reviewing which prompts work.

Academic Scenario Tools Quick Glance

Literature discovery: Elicit, Consensus, Semantic Scholar; Paper close reading & Q&A: NotebookLM, Claude (long docs); Review comparison: Elicit's cross-study extraction table. The principle remains: Leave discovery and summaries to AI, keep conclusions and critique for yourself.

Scenario Paradigms 05

Data & Automation Scenario Paradigms

Data Analysis: Three Levels

LevelPracticeSuitable For
L1 Natural Language Table QueriesThrow Excel/CSV directly to a chat model (or Julius etc.), ask in English, request chartsZero foundation; quickly explore unfamiliar data
L2 AI Writes Analysis CodeLet AI write Python/SQL scripts to run analysis—code is reviewable and rerun-able, results verifiable, low hallucination spaceNeed reuse, precision, large data
L3 Coding Agent Full ProcessClaude Code / Codex directly reads files, cleans, analyzes, generates reports; human verifies conclusionsMulti-file, multi-step analysis tasks
Why prioritize letting AI "write code to calculate" instead of "answer directly"?Models' mental math is unreliable, but their code executes deterministically—this changes "trust AI" to "trust code", and you can review code. This is the most important mindset shift in data scenarios.

Automation: Five-Level Ladder, Step by Step

  1. Manual chat—throw repetitive tasks to AI each time, human monitors throughout
  2. Prompt templates—save successful prompts as templates/skills for 1-click reuse
  3. CLI non-interactive—claude -p "prompt" / codex exec in scripts for batch processing
  4. Scheduling & hooks—run daily automatically: organize files, summarize dailies, monitor (Codex scheduled tasks / system cron)
  5. Agent workflows—n8n / Zapier / custom agents linking systems; must have failure alerts and manual spot-checks
Two Iron Rules of Automation① Must run manually 3 times before automating—automating an unstable process scales errors. ② No automation without verification—each level needs verifiable outputs (logs, diffs, reports) and fallbacks (alerts, manual approval points). Official best practices for unattended runs require: checks first, let go later.

Life Decisions: Itineraries / Diets / Purchases / Contract Reading

Self-Sorting: From "Messy Thoughts" to "Decision-Ready List"

This use case consistently ranks high in HBR's annual review (see Section 01 callout), but community discussions often confuse it with "psychological counseling"—let's draw the boundaries first, then provide a skeleton.

Prompt Skeleton: "I have a bunch of messy thoughts about [topic]. Please help me: ① distill them into 3-5 specific Yes/No or A/B questions; ② list current options and their costs for each question; ③ point out which question affects the others most and what I should think about first. Do not decide for me, just help me see the problems clearly."

Boundary Declaration, Read This FirstThe role of the "self-sorting" prompt is to turn messy emotions and thoughts into an actionable list of questions. It is not psychological counseling, and AI is not a licensed therapist. If you are experiencing thoughts of self-harm, suicidal ideation, or long-term, severe depression/anxiety, please contact a psychiatrist, therapist, or local crisis hotline immediately. Do not hand these issues solely to AI. AI can help sort out decision-making confusions like "should I change jobs" or "should I continue this relationship," but it cannot handle mental health issues requiring professional diagnosis and intervention.

Inner Skills 09

Real Cases: One Reproducible Template per Scenario

The following cases instantiate the paradigms on this page; prompts can be copied and modified directly. Those marked "transcript" are from public reports; others are paradigm reproduction templates.

🐛Programming · Fix a bugCODING

Input: "User feedback: Re-login after session timeout shows a white screen. Related code in src/auth/, focus on token refresh. First write a failing test to reproduce it, then fix it, passing the whole auth test suite counts as done."

Iteration: AI submits plan → Human confirms "only touch auth, don't refactor others" → AI writes test (red) → Fixes (green) → Human reviews diff.

Output: A fix commit with a regression test. The key is "failing test first"—this is the minimal implementation of a verification loop.

📝Writing · From materials to weekly report/articleWRITING

Input: Paste all scattered records of the week (chat excerpts, data, to-do completion) + "Write for a non-technical boss, under 300 words, three-part structure: Results / Risks / Next week's plan. Give me 3 outline versions first."

Iteration: Pick outline → Generate paragraph by paragraph → "Risk in paragraph 2 is too vague, quantify it" → Human verifies all numbers.

Output: Produce a weekly report in 10 mins that used to take 40 mins, with stable week-to-week structure.

🔍Research · Large purchase decisionRESEARCH

Input: "Budget X amount for a home NAS. Needs: Photo backup, 2 users, silent priority, no-fuss. Use deep research to compare 3-5 models on sale in 2026, provide a comparison table + concentrated negative reviews for each, with source links."

Iteration: After report, follow up on negative review sources and click to verify → Run the same prompt on another model → Only deep-dive into the differences between the two reports.

Output: Get conclusions in half an hour that used to take two nights of forum scrolling, and it's verifiable.

📊Data · Monthly report analysisDATA

Input: Upload sales CSV + "Summarize sales by category monthly, find categories with >20% MoM fluctuation, analyze possible reasons, output charts. Calculate using code, and give me the code too."

Iteration: Verify total matches original table (validation!) → "Consider holiday factors and rerun" → Have AI parameterize the script for direct reuse next month.

Output: Analysis conclusion + a rerun-able script—analyze once, compound monthly.

⚙️Automation · Auto-categorize downloads folderAUTOMATION

Input: To Claude Code: "Write a script to archive files in ~/Downloads into subfolders by type; move screenshots over 30 days old to a trash candidate list (don't delete directly). Run a dry-run mode first, only print plan, don't touch files."

Iteration: View dry-run output → Fix misclassification rules → Real run → After manually confirming it works 3 times, set up a cron job.

Output: A weekly auto-run cleanup task. Note the paradigm: dry-run mode + no irreversible deletion + run successfully 3 times before automating.

Ordinary Person's Learning Path: From Zero to Proficient

Research conclusion first: AI proficiency is trained usage intuition, not learned theory—pros have ~10% higher success rates, the difference mainly comes from "knowing how to iterate, how to provide context, and how to pick tasks". So the path design has only one principle: Always practice around your real tasks, don't take abstract classes.

🧗 Deepened Version: Capability Boundary Expansion MethodologyIf you want to use AI to expand technical capabilities to full-stack cross-platform (Mobile/Web/Backend) or do indie tech development, this page's methodology has a deepened sister piece: AI Capability Boundary Expansion Guide—5-step expansion engine, cross-domain mapping techniques, with two end-to-end practical cases.

4-Step Ladder

  1. Weeks 1-2 · Build Feel: Use chat models to solve 1 real small task daily (edit email, read medical report, make recipe). Practice only one thing: if unsatisfied, follow up and add info instead of giving up. Goal: Feel that "the first answer is just a start".
  2. Weeks 3-4 · Learn to Feed Context: Practice giving all background materials at once (files, screenshots, old examples); compare quality between "dry asking" and "asking with materials". Goal: Internalize mental models 1 & 4 (Context + Completion criteria).
  3. Month 2 · Scenario Depth: Pick 2 of your most frequent scenarios (e.g., writing + research), run the full process 5 times each using paradigms in Sec 03/04; save successful prompts as a personal template library. Goal: Form reusable assets.
  4. Month 3+ · Agents & Automation: Install a coding agent (Claude Code or Codex), start with "writing a small automation script", level up using Sec 05 ladder; start using deep research for big decisions. Goal: Evolve from "chatting" to "delegating tasks with verification".
