1️⃣ Antigravity Core Concepts & Mental Model

Official Standard Alignment Google Antigravity (code name AGY) is Google's next-generation full-stack infrastructure for the Agentic AI software engineering era. Moving beyond traditional chat completion, it integrates OS-level sandboxing, multi-agent orchestration, MCP (Modular Command Protocol) tool routing, AST semantic code understanding, and context lifecycle governance into a unified foundation.

6 Pillars of the Antigravity Architecture

  • agy CLI: Unified command-line interface driving workspace diagnostics, search, code edits, and subagent dispatch.
  • Agentic IDE: Seamless visual workbench integrating code editors, Planning Mode review panels, live diff checkers, and artifact renderers.
  • Customizations Hub: Cascading configuration hierarchy under .agents/ and ~/.gemini/antigravity/ for Skills, Rules, Plugins, and MCP servers.
  • Subagents Network: Autonomous background agents with distinct conversation IDs, model budgets, and workspace isolation modes.
  • Artifacts Engine: Persistent documentation and deliverable framework preventing messy chat dump and ensuring traceability.
  • Reactive Wakeup: Event-driven asynchronous execution model where parent agents are automatically resumed upon child completion without polling.

Customizations 04

4️⃣ Customizations Architecture: Skills · Rules · MCP · Plugins

Antigravity utilizes a 3-tier cascading configuration hierarchy: Project .agents/ (Highest) > User Global ~/.gemini/antigravity/ > Built-in Defaults. All rules hot-reload without restarting.

4.1 Writing a Production Skill

Declare your skill in .agents/skills/security-guard/SKILL.md:

---
name: security-guard
description: "Production security auditor for API secret leakage and SQL injection"
---
# Security Standards
1. Never hardcode API keys, JWT secrets, or DB credentials in source code.
2. Ensure all external inputs are strictly schema-validated before deserialization.
3. Enforce parameterized prepared queries for all database interactions.
4. Mandate timeout budgets and exponential backoff on all outbound HTTP calls.

4.2 Writing Global Interception Rules

# .agents/rules/safe-terminal.yml
---
severity: critical
description: "Sandbox Guard: Block high-risk commands and unapproved secret exports"
enforce:
  - tool: run_command
    condition: "BypassSandbox == false && CommandLine matches '(rm\\s+-rf\\s+/|mkfs|dd\\s+if=)' => reject"
  - tool: replace_file_content
    condition: "TargetFile matches '\\.(env|pem|key)$' => require_user_approval"

Governance 07

7️⃣ Performance & Sandbox Security Best Practices

  1. Standard Sandbox First: Commands execute in an isolated sandbox with no internet access by default. Explicitly set BypassSandbox: true only when downloading packages or accessing approved endpoints.
  2. Planning Mode Discipline: For multi-file architectural changes, write an implementation_plan.md artifact and obtain user sign-off before modifying source code.
  3. Incremental Block Edits: Avoid full-file overwrites on large codebases; use replace_file_content to conserve context tokens and maintain clean git history.

9️⃣ Practical Case: End-to-End Workflow

A full loop demonstrating subagent research, plan generation, incremental edits, and sandbox regression testing:

# 1. Dispatch research subagent to audit codebase
agy subagent invoke research --prompt "Audit legacy session bottleneck in src/auth/"

# 2. Write structured implementation plan artifact
agy write_to_file --TargetFile .gemini/antigravity/brain/implementation_plan.md \
  --CodeContent "# OAuth2 + PKCE Migration Plan..."

# 3. Perform atomic code edits after user approval
agy edit src/auth/oauth2.py --range 15-60

# 4. Run automated test suite inside isolated sandbox
agy run "pytest tests/test_oauth2.py -v" --wait 5000
