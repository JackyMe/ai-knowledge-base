Antigravity guide

Choose the desktop, CLI, IDE, or SDK for your task, then review permissions and results.

01

Choose a surface

Use desktop for projects, CLI for terminal work, IDE integrations for editing, and SDK for programmatic agents. Settings and shortcuts differ.

www.antigravity.google · home · 2026-09-09

02

Install and sign in

Use the official native installer on macOS/Linux. Start agy to authenticate; SSH users can finish authorization in a local browser. Check the binary and version.

curl -fsSL https://antigravity.google/cli/install.sh | bash
command -v agy
agy --version
agy

www.antigravity.google · install · 2026-09-09

03

Everyday CLI operations

Type / to inspect available session commands: /help, /diff, /resume, /permissions, /context, and /usage. Internal agent tools are not shell subcommands.

www.antigravity.google · reference · 2026-09-09

04

Settings and extensions

Inspect CLI settings with /config and connections with /mcp. Rules, skills, hooks, and plugins have different roles; follow each surface’s documented schema.

www.antigravity.google · settings · 2026-09-09

05

Background and headless work

Specify outputs, writable paths, and acceptance checks. Monitor with /agents and /tasks. For scripts, use -p; internal state names are not CLI APIs.

agy -p "Summarize this repository without changing files" --output-format json

www.antigravity.google · headless · 2026-09-09

06

Permissions, sandbox, and usage

Check enabled sandbox and tool permissions; do not assume networking is disabled by default. Prompt rules do not replace enforcement. /usage and /context measure different limits.

www.antigravity.google · permissions · 2026-09-09

07

Troubleshoot by symptom

Check PATH for missing commands, account/network/time for sign-in errors, and permission explanations for denied tools. Preserve evidence and narrow unreliable tasks before resetting configuration.

www.antigravity.google · troubleshooting · 2026-09-09

08

A verifiable task workflow

Example: inspect authentication code, identify changes and risks, implement the scoped work, run existing tests, and review the diff. Obtain specific authorization for publishing, spending, or messaging others.

Based on the linked official sources. Validate examples in your environment.
