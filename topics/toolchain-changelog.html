用法 00

怎么用这一页

这一页不是官方 changelog 的翻译。官方 changelog 每个版本几十条,大部分是内部修复,读完只会浪费时间。这里做的是筛选和翻译:只留会改变你实际操作的,并且明确写出"你要怎么改"。

三种标记的含义

标记含义你该做什么
🔴 破坏性变更老写法、老命令、老配置会失效或行为反转必看。升级后如果有东西"莫名其妙不好使了",先来这里查
🔄 行为变化命令还在、参数还在,但结果或时机变了知道就行,通常不用改配置,但会影响你对工具的预期
🆕 新增能力新命令、新配置项、新模型挑对自己有用的试,没必要全学

不收录什么

  • 纯内部重构、性能优化(除非影响到可感知的使用体验)
  • 只影响特定平台极小众场景的修复(除非是很多人会踩的,比如 Windows 路径问题)
  • 预览版/实验特性(等 GA 再收录,避免写完就变)
时效声明Claude Code 大约每 1-2 天发一个版本,Codex 每周都有更新。本页核对日期距今超过一个月,就该以官方源为准,别把这里当唯一真相。官方源见本页怎么维护一节。

本页怎么维护

这一页的价值全在"新鲜度"。放着不管,三个月后它比没有还糟——因为读者会当真。所以维护流程本身也写进来。

数据源(按可信度排序)

工具一手源本地自查命令
Claude Codecode.claude.com/docs/en/changelog/release-notes(看你当前版本到最新的差异)
Codexlearn.chatgpt.com/docs/changelogcodex debug models(实际可用型号)、/debug-config(配置为什么不生效)
别用二手源当唯一依据网上有不少第三方 changelog 聚合站,更新快但经常漏掉"破坏性"的标注,也有把预览特性写成已发布的。凡是要写进"破坏性变更"表的,必须在官方源核对过——这一条是这个知识库和"AI 生成的资料合集"的区别所在。

更新作业流程

仓库里已经把这套流程固化成了可复用的 skill(.claude/skills/refresh-toolchain/),在 Claude Code 里说"跑一次工具版本核对"即可触发。流程本身是:

  1. 确认当前日期——这一步不能跳,否则容易基于过时认知判断"新不新"
  2. 拉两个官方 changelog,范围是"上次核对日期 → 今天"
  3. 三分类筛选:破坏性 / 行为变化 / 新增。内部重构、极小众平台修复、预览特性一律不收
  4. 回写四个位置:本页对应月份归档、本页破坏性总索引、Claude Code 指南的「近期重要变化」、Codex 指南的「近期重要变化」
  5. 核对旧内容是否被推翻——这步最容易漏。新版本可能让指南正文里某段描述直接变错(比如命令改名、默认值变更),要顺着变化反查正文
  6. 更新三处日期标记:两份指南的顶栏与 hero 徽章、本页顶栏
  7. 重跑搜索索引 python3 scripts/build-search-index.py,然后提交
提醒机制仓库配了一个 GitHub Action,每月 1 号自动开一个 issue 提醒该核对了,附带上次核对日期与本页链接。不用记日子。

说明:本页为个人整理的版本变化摘要,非官方发布渠道。收录标准是"是否影响实际使用",因此刻意省略了大量内部修复与小众场景改动。任何一条与官方 changelog 冲突时,以官方为准。发现错漏欢迎在 GitHub 仓库提 issue。
