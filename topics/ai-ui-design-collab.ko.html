디자인 시안을 '1등 시민'으로 다루기
Claude Code / Codex 실전 협업

디자이너가 시안을 그리고, 엔지니어가 코드로 옮기며, AI가 결함을 다듬는 워크플로우 — 2026년 이 세 가지는 MCP(Model Context Protocol), 시각적 멀티모달 컨텍스트, 디자인 토큰이라는 3대 통로를 통해 진정으로 통합되었습니다. 본 가이드는 pen.dev, Figma, Material Theme Builder, Jetpack Compose, Paparazzi / Roborazzi를 유기적으로 엮어 가장 효율적인 '디자인 ↔ 코드' 파이프라인을 구축합니다. Android Compose를 주축으로 하되 Web/iOS 확장까지 포괄합니다.

도입 00

전체 개요: 왜 2026년에 이 협업이 필수적인가

디자인과 코드의 간극: 도구가 아닌 구조의 문제

과거 디자이너는 Figma에서 픽셀 단위로 스펙을 명시하고 개발자는 이를 보며 처음부터 코드를 재작성했습니다. 초기 AI 코딩 툴은 웹 전반에서 학습한 일반 패턴을 바탕으로 '그럴듯한' UI를 생성했을 뿐, 팀의 고유한 디자인 시스템을 인식하지 못했습니다. 결과물은 색상이 미묘하게 틀리거나 마진이 몇 픽셀 어긋나 수동으로 고치는 품이 더 들었습니다.

2026년, 3가지 핵심 기술의 성숙으로 이 간극이 획기적으로 좁혀졌습니다:

  1. MCP(Model Context Protocol)가 사실상의 표준으로 안착 — pen.dev, Figma, Google Stitch가 공식 MCP 서버를 제공합니다. Claude Code나 Codex에 연동하기만 하면 디자인의 노드 계층, 오토레이아웃, 토큰을 직접 무손실 구조로 읽어 들입니다.
  2. 디자인 툴의 '비주얼 + 코드' 듀얼 출력 네이티브 지원 — pen.dev의 .pen 파일은 JSON 기반으로 Git diff가 가능하며, Figma의 Variables와 Code Connect는 완벽한 구조화 데이터를 노출합니다.
  3. 자동 스크린샷과 검증은 피드백을 줄일 수 있습니다. 시간은 화면 수, 장치, 환경에 따라 다르며 핵심 작업과 차이는 사람이 검토합니다.

AI 에이전트가 디자인을 인식하는 3가지 경로

입력 경로기술 메커니즘장점단점 / 제약
1. MCP 구조적 읽기
최우선 추천		Figma / pen.dev MCP 서버를 통해 노드 트리, AutoLayout, 패딩, 코너 라디우스, 토큰을 JSON으로 직접 파싱100% 무손실 정확성, CSS/Compose 속성 1:1 매핑, 토큰 참조 완전 유지디자인 시안이 정돈된 AutoLayout과 컴포넌트로 구성되어 있어야 함
2. 스크린샷 시각 분석
폴백 / 보조		PNG/JPG 이미지를 멀티모달 LLM(GPT-5 / Claude Opus)의 비전 입력으로 전달기존 모든 이미지, 화이트보드 스케치, 실기기 캡처 즉시 분석 가능세부 패딩 픽셀 오차 발생 가능, 시각적 환각 존재
3. 디자인 토큰 JSON
시스템 기반		W3C 표준 디자인 토큰 JSON(색상, 타이포그래피, 간격)을 저장소에 직접 마운트브랜드 테마의 완벽한 일관성, 테마 스위칭 자동화단독으로는 컴포넌트의 레이아웃 배치를 규정하지 못함
실전 03

Android 엔드투엔드 5단계 파이프라인

  1. 디자인 토큰 추출: Figma Variables / Material Theme Builder에서 토큰을 추출하여 Color.kt, Theme.kt, Type.kt로 코드화;
  2. 시안 구조 읽기: pen.dev 또는 Figma MCP를 호출하여 컴포넌트의 노드 계층, 패딩, 반응형 제약 조건 파싱;
  3. Compose 컴포넌트 생성: 하드코딩된 값 없이 Material 3 토큰(MaterialTheme.colorScheme.primary, MaterialTheme.typography.titleMedium) 기반으로 코드 생성;
  4. 스냅샷 캡처: Paparazzi / Roborazzi를 실행하여 로컬 JVM에서 렌더링 스냅샷 즉시 생성;
  5. 회귀 비교 및 피드백: 원본 디자인 시안과 생성된 스냅샷의 diff를 대조하여 미세 오차를 AI에게 재지시.

다음은 일부 색상 역할 예제입니다. surfaceContainer 등은 프로젝트 Material 3 버전의 API와 대조하세요.

토큰 04

Figma → Material 3 디자인 토큰 매핑

Material 3 컬러 롤 매핑 원칙

Material 3 Color Role용도Jetpack Compose 사용법
primary / onPrimary주요 액션 버튼, 활성 탭 등 핵심 강조MaterialTheme.colorScheme.primary
surface / onSurface기본 카드 배경 및 기본 텍스트MaterialTheme.colorScheme.surface
surfaceVariant / onSurfaceVariant보조 카드 배경, 구분선, 보조 캡션MaterialTheme.colorScheme.surfaceVariant
error / onError유효성 오류, 결제 실패 등 위험 상태MaterialTheme.colorScheme.error
✅ 올바른 토큰 기반 구현 
Surface(
    color = MaterialTheme.colorScheme.surfaceVariant,
    shape = MaterialTheme.shapes.medium
) {
    Text(
        text = item.title,
        style = MaterialTheme.typography.titleMedium,
        color = MaterialTheme.colorScheme.onSurfaceVariant,
        modifier = Modifier.padding(Spacing.Medium)
    )
}
❌ 잘못된 하드코딩 안티패턴 
Box(
    modifier = Modifier
        .background(Color(0xFFF1F5F9)) // 하드코딩된 색상
        .clip(RoundedCornerShape(8.dp))
        .padding(16.dp)                // 하드코딩된 마진
) {
    Text(item.title, fontSize = 16.sp, color = Color.Black)
}
코드 05

Compose 컴포넌트 생성 및 양방향 쓰기

스켈레톤 및 인터랙션 상태 모델링

AI에게 단순히 '정적 화면'을 그리게 하지 말고, UI의 4대 상태를 완전한 Sealed Interface로 모델링하도록 요구해야 합니다:

// UI 상태 모델링 표준 패턴
sealed interface ProductUiState {
    data object Loading : ProductUiState
    data class Success(val product: Product, val isFavorite: Boolean) : ProductUiState
    data class Error(val message: String) : ProductUiState
}

동기화 07

양방향 동기화와 디자인 시스템 유지보수

코드가 수정되었을 때 디자인 시안으로 다시 반영하는 워크플로우:

  • pen.dev 활용: 코드에서 변경된 Spacing이나 Color를 .pen JSON 파일에 자동 반영하여 디자이너가 IDE 캔버스에서 즉시 확인;
  • Figma Code Connect: 실제 Compose 컴포넌트 선언부를 Figma의 컴포넌트 문서와 링크하여 디자이너가 구현 상태를 실시간 확인;
  • 토큰 자동화 파이프라인: Style Dictionary 또는 토큰 트랜스파일러를 통해 Figma Variables 변경 시 PR 자동 생성.
