pen.dev × Claude Code
모범 사례 실전 가이드

pen.dev는 코드 에디터 내에 상주하는 AI 디자인 캔버스이고, Claude Code는 터미널에서 자율 작동하는 코딩 에이전트입니다. 두 도구를 MCP(Model Context Protocol)로 연결하면 '디자인 맥락 유실 제로'의 직결 파이프라인이 완성됩니다. 공식 문서와 현장 실무 노하우를 통합한 실전 가이드입니다.

9개 이상 1차 출처설치부터 CI/CD까지 총망라실무 프롬프트 템플릿 포함
무손실 연계스크린샷 추측 불필요, 디자인 데이터에서 직접 코드 생성
.pen = JSONGit으로 버전 관리, 브랜치 비교 및 머지 가능
7개 도구 지원Claude Code / Cursor / Codex 등 공식 AI 통합 지원
로컬 완결MCP 서버는 로컬 구동, 디자인 데이터 외부 전송 없음
시작하기 00

왜 pen.dev + Claude Code인가

해결하는 본질적 문제: 디자인과 코드의 단절

기존 개발 플로우에서는 디자이너가 Figma로 만든 시안을 개발자가 눈대중으로 보며 코드로 옮겨 적었습니다. 미세한 마진 오차, 폰트 웨이트 오해, 누락된 hover 상태 등으로 인해 최종 결과물이 "디자인 시안과 미묘하게 다른" 문제가 반복되었습니다.

범용 AI 코딩 도구 역시 이 문제를 완전히 해결하지는 못했습니다. 개별 프로젝트의 고유한 디자인 시스템, 브랜드 컬러, 여백 규약을 알지 못하므로 웹상의 일반적인 패턴을 짜깁기한 '그럴듯한' 코드만 출력했기 때문입니다.

이 조합이 가져온 혁신pen.dev는 디자인 파일을 코드와 동일한 저장소(.pen 파일)에서 관리하고, Claude Code는 MCP를 통해 캔버스 상의 정확한 좌표, 토큰, 계층 구조를 직접 읽어 코드를 생성합니다. 이미지 추정이 아닌 구조화된 데이터 기반 판독입니다. 자연어로 UI를 생성하고 → Git으로 관리하며 → 명령어 한 줄로 코드로 변환하는 이 새로운 경험을 'Vibe Design'이라 부릅니다.

도구별 역할 분담

도구/요소제공 기능 및 역할
pen.dev무한 캔버스, 컴포넌트/변수/슬롯 시스템, Figma 임포트, AI 대화, .pen 형식, 헤드리스 CLI
Claude Code자율형 코딩 에이전트: 다중 파일 읽기/쓰기, 명령어 실행, Plan 모드, Skills, MCP 확장
MCP브리지 프로토콜: execute, get_app_state, get_screenshot, export_nodes, get_guidelines 등 도구 제공 (상세 내용은 pen.dev 공식 가이드 참조)

퀵스타트 01

환경 설정 표준 플로우

공식 문서와 실무 튜토리얼을 바탕으로 가장 안정적인 설정 절차를 정리합니다 (VS Code 기준이나 Cursor 등에서도 동일합니다):

  1. Claude Code 설치 및 로그인: 공식 설치 스크립트 curl -fsSL https://claude.ai/install.sh | bash 실행 후 claude로 브라우저 인증 완료. 오류 발생 시 환경 설정·인증 긴급 매뉴얼 참조.
  2. pen.dev 확장 프로그램 설치: VS Code 확장 탭에서 'pen.dev'(게시자: highagency.pencildev) 검색 후 설치.
  3. pen.dev 실행: 상태 표시줄 왼쪽 하단의 연필 아이콘 클릭 (안 보일 경우 VS Code 재시작).
  4. 이메일 인증: 첫 실행 시 이메일을 입력하고 수신된 인증 코드를 입력하여 활성화.
  5. MCP 연결 확인: Claude Code 터미널에서 /mcp 실행 후 pencil이 connected로 표시되는지 확인 (자동 등록됨).
  6. design.pen 생성: 워크스페이스 루트 디렉터리에 생성하여 코드와 동일한 Git 저장소로 관리.

.claude.json에 자동 생성되는 MCP 설정 예시:

"mcpServers": {
  "pencil": {
    "command": ".../highagency.pencildev-x.y.z/out/mcp-server-darwin-arm64",
    "args": ["--app", "visual_studio_code"],
    "type": "stdio"
  }
}
새 프로젝트 권장 플로우design.pen 생성 → 에디터로 열기 → 활성화 → 코드와 함께 커밋. 초기에는 캔버스 우클릭 후 "Open Welcome File"로 튜토리얼을 체험해 보는 것을 추천합니다.
주의사항 3가지① AI 기능 사용을 위해 claude 로그인이 선행되어야 합니다. ② 자동 저장 기능이 없으므로 수시로 Cmd/Ctrl + S를 누르세요. ③ Codex 사용 시 config.toml 백업을 권장합니다.
퀵스타트 02

4대 핵심 워크플로

실전 경험을 통해 검증된 4가지 재사용 가능한 워크플로입니다:

WORKFLOW A
자연어 프로토타이핑 (Vibe Design)

Claude Code에 몇 줄의 요구사항을 전달하는 것만으로 전체 페이지 디자인을 자동 생성. 캔버스에서 수동 미세 조정을 수행합니다. 여행 사진 앨범, 베이커리 주문 화면, 카페 관리 대시보드, 지역 게시판 등에서 실무 수준의 완성도가 입증되었습니다.

요구사항 입력 → AI가 .pen 생성 → 캔버스 미세 조정 → Git 커밋
WORKFLOW B
디자인 → 코드 생성

캔버스 디자인이 완료되면 "이 디자인을 바탕으로 Next.js 페이지를 작성해 줘"라고 지시합니다. Claude Code가 정확한 구조와 Design Token을 판독하여 코드를 생성합니다. React/Vue/Tailwind/shadcn-ui 등 기술 스택을 명시하면 최고 품질을 얻을 수 있습니다.

캔버스 디자인 → Cmd/Ctrl+K → 스택 지정 코드 생성 → 검토 & 머지
WORKFLOW C
코드 → 디자인 역생성

기존 src/components/Button.tsx 등의 코드를 캔버스 상의 컴포넌트로 역복원합니다. "src/components의 Button 컴포넌트를 재현해 줘"라고 지시하여 레거시 코드에서 디자인 시안을 추출할 수 있습니다.

코드 판독 → 캔버스에 재현 → 비주얼 개선 → 코드 역반영
WORKFLOW D
양방향 동기화 + Git 단일 진실 공급원 (SSOT)

CSS 변수와 pen.dev 변수를 양방향 동기화합니다. "globals.css에서 pen.dev 변수를 생성해 줘". 코드와 .pen 파일을 동일 커밋으로 묶어 관리함으로써 디자인과 구현의 불일치(Drift)를 완전히 방지합니다.

변수 동기화 → 디자인 & 코드 동시 수정 → 단일 커밋 완료

Workflow A 실증 샘플

기존 프로젝트 리뉴얼 실전

  1. 디자인 생성: Claude Code에 "설정 화면 디자인 생성: 화이트 카드 폼, AI 분석 설정, 모델 선택 라디오 버튼..."을 지시하여 .pen 생성.
  2. 디자인 적용: "이 디자인을 프로젝트에 적용해 줘"라고 지시하면 기존 소스 코드에 즉시 스타일이 반영됩니다.

실전 활용 04

디자인 시스템 엔지니어링

단일 페이지 생성을 넘어, pen.dev와 Claude Code를 디자인 시스템 구축 및 유지보수 파이프라인으로 활용하는 실무 방법론입니다.

5단계 접근법 (create-design-system Skill)

단계목적 및 내용주요 작업
① 요구사항 정의대상 사용자, 핵심 워크플로, MVP 범위 명확화플랫폼(Web/Mobile), 톤앤매너, 핵심 5~7개 화면 식별
② 스타일 탐색비주얼 방향성 탐색무드와 키워드를 바탕으로 2~3가지 방향 제안, 레퍼런스 이미지 활용
③ 무드보드.pen 내에 2~3개 무드보드 작성컬러 팔레트, 타이포그래피 스케일, 기본 컴포넌트 후보 선정
④ 컴포넌트 세트확정된 방향성에 따라 컴포넌트 라이브러리 구축Design Tokens 정의 후 Button, Input, Card, Nav 등 제작
⑤ 화면 조합컴포넌트 인스턴스를 조합하여 실제 화면 완성더미 텍스트 대신 실제에 가까운 데이터를 사용하여 화면 완성

엔터프라이즈 실사례: Lullabot 브랜드 라이브러리

Lullabot의 Jerad Bitner는 전체 브랜드 시스템을 1개의 재사용 가능한 디자인 라이브러리(56개 컬러 변수, 폰트 토큰, 4px 그리드 여백, 16개 공통 컴포넌트)로 패키징했습니다. 이후 신규 프로젝트는 항상 이 라이브러리를 임포트하여 시작합니다.

실전 활용 05

고효율 프롬프트 패턴

구체성의 원칙

❌ 모호하고 비효율적"예쁘게 디자인해 줘", "폼 추가해 줘", "페이지 만들어 줘"

점진적 피라미드 (공식 권장 호흡)

  1. 골격 구축 — "대시보드 전체 레이아웃 구성"
  2. 구조 구체화 — "사이드바에 네비게이션 메뉴 항목 추가"
  3. 상태 추가 — "각 메뉴 항목에 hover 상태 추가"
  4. 최종 정렬 — "여백을 8px 그리드 시스템에 맞춰 엄격히 정렬"
심화 응용 06

고급 활용 기법

pen.dev CLI: 헤드리스 자동화

GUI 없이 스크립트나 터미널에서 직접 디자인 생성 및 이미지 추출을 수행할 수 있습니다:

# 명령어 한 줄로 디자인 파일 생성
pen --out login.pen --prompt "Create a modern login page with email, password, social login"

# 기존 디자인 수정 후 2배 해상도 PNG 출력
pen --in dashboard.pen --out dashboard-v2.pen --prompt "Add a sidebar navigation"
pen --in design.pen --export hero.png --export-scale 2

CI/CD 파이프라인 자동화

GitHub Actions에서 .pen 파일의 변경을 감지하여 자동으로 PNG 미리보기를 생성하고 PR에 첨부하는 워크플로를 구축할 수 있습니다:

name: pen.dev Design Preview
on:
  pull_request:
    paths:
      - '**/*.pen'
jobs:
  design-preview:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm install -g @pen.dev/cli
      - name: Export modified .pen to PNG
        env:
          PEN_CLI_KEY: ${{ secrets.PEN_CLI_KEY }}
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          mkdir -p design-previews
          for f in $(git diff --name-only "origin/${{ github.base_ref }}"...HEAD -- '*.pen'); do
            [ -f "$f" ] || continue
            name=$(echo "$f" | tr '/' '_' | sed 's/\.pen$//')
            pen --in "$f" --export "design-previews/${name}.png" --export-scale 2
          done
      - uses: actions/upload-artifact@v4
        with:
          name: design-previews
          path: design-previews/
심화 응용 07

함정 체크리스트

자주 발생하는 실수와 대응법
