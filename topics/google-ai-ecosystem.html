Google AI 生态指南

按用途选择 Gemini API、NotebookLM、Canvas 与 Antigravity。把能力、限制和验证方法放在一起阅读。

01

按任务选工具

程序化调用模型：Gemini API。围绕一组资料阅读和问答：NotebookLM。交互式原型：Canvas。理解和修改代码库：Antigravity。先选一个能完成任务的入口，再考虑组合，避免为了流程复杂而连接所有工具。

02

API 接入与模型选择

AI Studio 用于试验提示词和管理 Gemini API 接入；Vertex AI 面向 Google Cloud 的权限与部署体系。模型名称、上下文长度、地区和额度按对应平台核对，不把不同模型统一写成“2M”。以下为 GenerateContent 接口的最小示例；运行前设置 API Key 与可用模型 ID。

import os
from google import genai

client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])
response = client.models.generate_content(
    model=os.environ["GEMINI_MODEL"],
    contents="Summarize the supplied requirements and list open questions.",
)
print(response.text)

03

缓存：看命中与总成本

隐式缓存依赖可复用前缀；显式缓存需要创建和管理缓存对象。当前 Interactions API 只支持隐式缓存，显式缓存使用 GenerateContent。缓存资源名应传给缓存字段，不能替代 model。收益取决于命中率、输入规模、存储与输出成本，不能承诺总账单固定降低 90%。

04

结构化输出与业务校验

为输出指定支持的 JSON Schema，再用程序验证字段值、数值范围和业务约束。结构合法不代表事实正确；还要处理拒绝、截断、空结果和请求失败。不要把旧版 GenerateContent 的配置示例直接套到 Interactions。

ai.google.dev · structured-output · 2026-09-09

05

NotebookLM：引用与核验

把相关资料放入同一笔记本，明确问题和需要对比的来源。回答后点击引用检查原句、日期和适用条件。引用辅助溯源，不保证无幻觉；来源数量、文件大小和生成次数均有计划限制。不要将它描述为无限资料池或已公开的无损检索架构。

support.google.com · notebooklm · 2026-09-09

06

准备可检索的资料

优先保留目录、标题、出处和版本；排除依赖目录、构建产物、重复副本与凭据。代码库先按问题挑选相关文件，记录路径和行号。上传前检查支持的格式与组织的数据政策；对扫描 PDF 先验证文字识别结果。

07

音频概览与学习闭环

音频概览用于快速建立背景，不替代原文。先指定听众、范围和关注问题，听完列出待核实要点，再回到来源定位。对专有名词、数字和归因逐项检查；不要把生成对话中的推断当作原作者观点。

08

Canvas 与图像原型

先提供页面目标、真实内容、组件约束和目标尺寸，再逐步修改原型。生成图适合讨论视觉方向；正式页面仍需真实文字、语义化结构和交互测试。图像模型与 API 参数以当前目录为准，旧版 Imagen 示例不代表最新能力。

10

一个完整的资料到代码流程

整理可靠资料 → 提取需求与待确认项 → 选择 API 或原型工具 → 在代码库实现 → 运行测试并核对输出。每一步保留输入、产物和验收标准。示例流程不是厂商的固定架构；无需使用全部产品，也不要把模型生成的答案当作已验证事实。
