PART 1 · GOOGLE ANTIGRAVITY (AGY) 深度解构

1.1 什么是 Google Antigravity

✅ 官方确认 Google Antigravity (AGY) 是 Google 推出的一款 AI 原生 Agentic 编程与协同开发平台。它不再是传统编辑器里的“下拉框提示”，而是赋予了 AI 智能体读取项目上下文、规划任务步骤、执行 shell 命令、编写/修改文件以及自我调试验证的完整能力。

📌 Antigravity 核心设计哲学
  • 上下文驱动 (Context-Driven)：项目根目录下的配置文件 (`.agents/` 或 `AGENTS.md`) 拥有最高响应优先级。
  • 安全自主性 (Bounded Autonomy)：智能体在受控的 Terminal Sandbox（终端沙箱）中运行命令，所有文件写入与命令均可随时人工审批。
  • 显式规划优先 (Planning Mode First)：复杂任务先生成 `implementation_plan.md` 供开发者审查，通过后再自动分发至 Subagents 逐步落地。

1.2 四大交互形态详解

✅ 官方确认 Antigravity 针对不同的开发场景，提供了 4 种相互融合的交互形态：

1. Antigravity CLI (`agy`)

轻量化终端 TUI 命令行界面。在终端直接输入 `agy` 启动。适合快捷命令行重构、CI/CD 自动化流水线或无图形化环境。

agy                # 启动交互式 TUI
agy --help         # 查看命令行标志与子命令
# 在 TUI 中使用 Ctrl+D Ctrl+D 或 /exit 退出

2. Antigravity 2.0 Desktop App

基于 Electron 打造的独立桌面级应用程序。提供独立的左侧导航栏（Conversations、Projects、Scheduled Tasks 定时任务、Customizations 管理）以及右侧**HTML 辅助面板 (Auxiliary Pane)**（可实时监控 Subagents 运行状态、查看后台 Task 进度、预览 Artifacts 渲染及 Git 差异 diff）。

3. Antigravity Standalone IDE

基于 VS Code 底座构建的 AI 原生开发环境，深度集成 3 种交互模式：

  • Passive Modal (Antigravity Tab 自动补全)：预测单步意图，支持 Tab 补全代码、Tab to Jump 跳转光标、Tab to Import 自动引入依赖包。
  • Instructive Modal (Inline Command ⌘I / Ctrl+I)：高亮选中局部代码并给出具体修改指令（如“重构此函数”、“添加 JSDoc 注释”）。
  • Collaborative Modal (Sidebar Chat & Agent Mode)：侧边栏协同模式，启动包含任务规划、文件读写、Shell 命令执行与网页浏览的自主智能体。

4. Antigravity Python SDK (`google-antigravity`)

可通过 `pip install google-antigravity` 安装，用于在 Python 脚本或自动化测试框架中编排管理智能体：

pip install google-antigravity

1.3 高效交互：Slash 命令与 @ Mentions 机制

⚡ 实测强共识 在 Antigravity 的 Chat Canvas 与 CLI 中，善用斜杠命令与上下文 `@` 引用是拉开使用效率差距的关键：

斜杠命令 (Slash Command) 触发行为与作用场景
/goal 启动长任务通宵模式，智能体将极度详尽地反复自我迭代验证，直到目标彻底完成。
/schedule 设置一次性定时器或 recurring cron 定时任务，在后台定期监控部署或自动体检。
/browser 启动无头浏览器集成，可自动登录 Web 页面、截屏分析并进行端到端视觉回归。
/grill-me 启动互动问答采访模式，在开始写代码前强迫智能体向你逐项确认关键设计细节。
/learn 记录当前会话中修正的踩坑经验，持久化写入项目 Rules 以便日后自动遵循。
/teamwork-preview 启动多 Agent 自主团队协作预览，分发子任务至并发后台智能体。
💡 `@` Mentions 菜单高频技巧

输入 `@` 即可打开上下文菜单：

  • `@filename` / `@folder/`：快速挂载单个文件或完整目录。
  • `@terminal`：直接将当前终端最近输出的报错日志附带给智能体。
  • `@conversation-id`：引用历史会话上下文，实现跨会话记忆复用。
  • `@mcp-tool`：显式指定调用特定的 MCP 服务器工具。

1.4 自定义扩充系统 (Customizations)

✅ 官方确认 Antigravity 支持两级发现根目录：全局配置根（`~/.gemini/config`）以及项目级根（`/.agents/`）。包含五大核心扩展：

1. Skills (技能)

存放在 `skills//SKILL.md`，使用 YAML frontmatter 描述名称与作用，作为模块化 Workflow 领域指南：

---
name: format-code
description: Custom code formatting style enforcement
---
# Format Code Instructions
When formatting frontend code, always use pre-configured ESLint rules...

2. Rules (规则)

定义在 `rules/*.md` 或根目录的 `AGENTS.md` / `GEMINI.md`，用于约束代码风格、禁止修改特定库或强制遵守规范。

3. Hooks (钩子)

通过 `hooks.json` 配置事件监听（如 `on_subagent_start`、`before_tool_call`），在智能体触发敏感操作时执行拦截脚本。

4. MCP (Model Context Protocol)

在 `mcp_config.json` 中配置第三方 MCP 服务器（如数据库连接、Figma 插件、GitHub API 等），扩展智能体的外部动作空间。

1.5 Planning Mode 与 Subagent 多代理协同

⚡ 实测强共识 面对大型重构或新功能开发时，**严禁直接全自动改代码**。必须启用 Antigravity 的 **Planning Mode**：

🔄 Planning Mode 标准工作流
  1. 调研与调研报告：智能体使用 Read-only 工具通读代码库与依赖链。
  2. 生成 `implementation_plan.md`：明确 User Review Required 审核项、Open Questions、受影响文件列表以及 Verification Plan 验证步骤。
  3. 人工确认 (User Approval)：开发者审阅 Markdown Plan，提出修改或点击 Approve。
  4. 执行落地与多 Agent 派生：主 Agent 调用 `invoke_subagent` 分派子任务至并发后台运行，随时通过 `manage_subagents` 监控与通信。
  5. 验证与 `walkthrough.md` 产出：跑通自动化测试并产出包含改动总结与截屏的 Walkthrough。

1.6 安全沙箱与权限深度把控

✅ 官方确认 智能体执行命令行操作时，默认在独立的 **Terminal Sandbox** 安全沙箱中运行：

  • Standard Sandbox Mode (`BypassSandbox: false`)：自动拥有工作区内的读写权限，无网络且无法越界访问工作区之外的磁盘目录，命令可完全自动静默执行。
  • Bypass Sandbox Mode (`BypassSandbox: true`)：解除沙箱隔离，获得网络请求与系统全盘访问权，**必须经过开发者手动弹窗批准**。
⚠️ 权限控制最佳实践

可在全局或项目级的 Settings 中配置 `Command Allowlist`（如允许 `npm test`, `git status` 自动跑通）与 `Command Denylist`（禁止 `rm -rf /`, `drop database`），平衡效率与系统安全。

1.7 Antigravity Python SDK 编程化实战

✅ 官方确认 使用官方 Python SDK 可以轻松把 Antigravity 智能体集成至自动化脚本或 CI 管道中：

import asyncio
import sys
from google.antigravity import Agent, LocalAgentConfig, CapabilitiesConfig

async def main():
    # 配置智能体：启用读写工具与命令执行能力
    config = LocalAgentConfig(
        system_instructions="你是一个高标准的代码评审与重构专家。",
        capabilities=CapabilitiesConfig()
    )

    async with Agent(config) as agent:
        # 发送 Prompt，获得异步响应句柄
        response = await agent.chat("请检查 src/index.ts 并优化异步异常处理。")

        # 1. 实时监听智能体的思考过程 (Thoughts)
        async for thought in response.thoughts:
            print(f"🧠 [Thinking]: {thought}")

        # 2. 监听调用的工具事件 (Tool Calls)
        async for call in response.tool_calls:
            print(f"🛠️ [Tool Call]: {call.name} -> {call.args}")

        # 3. 打印最终输出 Token
        async for token in response:
            sys.stdout.write(token)
            sys.stdout.flush()

if __name__ == "__main__":
    asyncio.run(main())
PART 2 · NOTEBOOKLM 深度研究与知识基座

2.1 Source Grounding 核心原理

✅ 官方确认 NotebookLM 是基于 Gemini 顶尖模型的个人 AI 研究助手。其最大的技术亮点在于 **Strict Source Grounding (源头绑定)**：只在你主动上传的 Source 文档范围内提取与回答问题，回答时会自动标注角标数字引用（Citation）。如果源文件中找不到证据，它会明确回答“未在资料中找到”，彻底消除了传统 LLM 的凭空幻觉。

2.2 2M 多源材料输入与预处理

⚡ 实测强共识 NotebookLM 支持在一个 Notebook 中混合注入最多 50+ 个 Sources，依靠 Gemini 2M+ 超长上下文轻松消化：

  • 多种类文件格式：支持 PDF、Google Docs/Slides、Markdown、PlainText、HTML 网页 URL、YouTube 视频链接及音频文件（MP3/WAV）。
  • 预处理技巧：上传开源项目代码包或开源 API 文档时，先打成 Markdown 单文件或结构化 PDF 注入，研究检索精准度最高。

2.3 知识二次加工与播客生成

⚡ 实测强共识 NotebookLM 不仅仅能问答，内置的 **Studio (研讨工作台)** 能够一键生成衍生知识资产：

  • Briefing Docs (简报文档)：自动整理数十页长材料的核心观点与决策建议。
  • Audio Overview (播客对话)：自动生成两位 AI 主播用口语化语气对答讨论该研究主题的高清音频，非常适合通勤听读。
  • Study Guides & Mindmaps：自动提取关键概念问题集与思维导图提纲。

2.4 研报 → Antigravity Spec 转换

⚡ 实测强共识 打破工具孤岛的核心步骤：在 NotebookLM 中完成复杂业务逻辑或技术选型研读后，点击生成一份结构化 `System Requirement Spec`。将其复制并直接保存为项目的 `.agents/rules/spec.md` 或 `AGENTS.md`，作为 Antigravity 智能体接力编码的准确依据。

PART 5 · 最佳实践、避坑指南与速查附录

5.1 提效七条黄金法则

  1. 法则 1：能用 NotebookLM 先研读的，绝不要直接丢给 LLM 瞎猜。
  2. 法则 2：复杂任务严格遵守 Planning Mode，先审 Plan 后落盘。
  3. 法则 3：项目级规则写入 `AGENTS.md`，善用 `/learn` 积累经验。
  4. 法则 4：耗时长任务开启 `/goal` 通宵迭代模式。
  5. 法则 5：终端命令敏感操作走 Sandbox 沙箱，配置允许/禁止清单。
  6. 法则 6：大批量文件变更分发给并发 Subagents 执行。
  7. 法则 7：多模态 UI 开发用 Canvas 与 Imagen 3 替换占位图。

5.2 常见坑点与反模式图鉴

⚠️ 必须警惕的 4 大反模式
  • 反模式 1：上下文窗口爆棚不清理
    在单个会话里反复多次对话导致上下文充斥无关历史，应及时开启 New Conversation 或挂载具体的 `@filename`。
  • 反模式 2：绕过沙箱滥用 BypassSandbox
    过度开启 BypassSandbox 容易误跑全局破坏性指令，应优先配置精准的 Allowlist 授权。
  • 反模式 3：直接修改底座，不沉淀为 Custom Skills
    重复性较高的提效流程（如写 Unit Test）应固化为 `.agents/skills/` 下的 `SKILL.md`，避免每次重复粘贴 Prompt。
  • 反模式 4：把 NotebookLM 当通用聊天框
    NotebookLM 的核心是 Source Grounding，如果不传高质量 Sources 就无法发挥其无幻觉优势。
