Methodology 01

5-Layer Diagnosis + 1-Click Health Check Script

The systematic inspection method has only one rule: Check layer by layer from the bottom up, finish one before moving to the next. Each layer has specific checking commands and a definition of "what normal looks like".

L1
Binary Layer —— Which program is actually running?

which -a claude / which -a codex lists all identically named commands in PATH; claude --version confirms the version. Normal: Only one path. Abnormal: Multiple paths → Multiple installations coexist, do subtraction first.

L2
Environment Variable Layer —— Are any variables hijacking behavior?

env | grep -iE 'anthropic|claude|codex|openai|proxy'. Normal: Completely blank (pure subscription user). Abnormal: Any ANTHROPIC_API_KEY / ANTHROPIC_BASE_URL / *_PROXY is worth questioning its origin.

L3
Credential Layer —— Whose credential is currently used?

Claude Code in-session /status check Login method (if there's an API key row, env vars took over); Codex uses codex login status. Confirm the account email and organization are yours.

L4
Configuration Layer —— Which layer of config is taking effect?

Claude Code: claude doctor checkup, /config to see effective value sources; Codex: /debug-config prints configuration cascading. Changes not taking effect = Overridden by a higher layer or the key requires a session restart.

L5
Network Layer —— Can requests really go out and come back?

curl -sI https://downloads.claude.ai/claude-code-releases/latest test connectivity; for corporate networks, check proxy variables and private CAs; if OAuth is stuck, check callback ports (Codex is 1455).

Why this order?The lower layer determines the upper layer: If the wrong program is running (L1), checking credentials is meaningless; Env vars (L2) will tamper with credential selection (L3); Only when credentials are right can we talk about config (L4); If the first four layers are correct and it still doesn't work, then it's the network (L5). Reverse troubleshooting is a waste of time.

1-Click Health Check Script (Read-only, copy & use)

Combine the 5-layer check into one script. Read-only, modifies nothing, safe to run on any machine —— Run this first on an unfamiliar computer to see the full state in 30 seconds:

#!/bin/bash
# ai-env-check.sh —— Claude Code / Codex Environment 1-Click Health Check (Read-only)
# Usage: bash ai-env-check.sh   (macOS / Linux / WSL)
echo "═══ L1 Binary Layer ═══"
for c in claude codex; do
  echo "--- $c ---"
  if command -v "$c" >/dev/null 2>&1; then
    which -a "$c"; "$c" --version 2>/dev/null | head -1
  else echo "(Not installed or not in PATH)"; fi
done
[ -d ~/.claude/local ] && echo "⚠️  Found legacy npm install: ~/.claude/local (recommend deleting)"
npm -g ls @anthropic-ai/claude-code 2>/dev/null | grep -q claude-code && echo "⚠️  Found global npm install (will conflict with native install)"

echo; echo "═══ L2 Environment Variable Layer ═══"
env | grep -iE 'anthropic|claude|codex|openai|https?_proxy|no_proxy|node_extra_ca' \
  || echo "(Clean: No related environment variables)"
echo "--- Leftovers in shell config files (Focus on export left by others) ---"
grep -nE 'ANTHROPIC|CLAUDE_|CODEX|OPENAI' ~/.zshrc ~/.zprofile ~/.bashrc ~/.bash_profile ~/.profile 2>/dev/null \
  || echo "(Clean: No related config in rc files)"

echo; echo "═══ L3 Credential Layer ═══"
codex login status 2>/dev/null || echo "codex: Not logged in or not installed"
[ -f ~/.codex/auth.json ] && echo "codex: auth.json exists (plaintext credentials)"
echo "claude: Enter session and run /status to check Login method and account ownership"

echo; echo "═══ L4 Configuration Layer (File List) ═══"
ls -la ~/.claude/settings.json ~/.claude.json ~/.codex/config.toml 2>/dev/null
ls -la .claude/settings.json .claude/settings.local.json .mcp.json 2>/dev/null \
  || echo "(No project-level config in current directory)"

echo; echo "═══ L5 Network Layer ═══"
curl -sI --max-time 8 https://downloads.claude.ai/claude-code-releases/latest | head -1
curl -sI --max-time 8 https://auth.openai.com | head -1
echo "Health check complete ✅ Verify layer by layer: Multiple installs? Suspicious variables? Account ownership? Config sources? Network connectivity?"
Windows UsersCorresponding commands in PowerShell: where.exe claude for binary check; Get-ChildItem Env: | Where-Object Name -match 'ANTHROPIC|CODEX|OPENAI' for environment variables; Don't forget to check user variables in "System Properties → Environment Variables" and the $PROFILE file —— variables set via GUI won't be in rc files.

Claude Code 02

Claude Code · Credential Mechanism & Priority

Eighty percent of Claude Code's login issues stem from an ignored fact: It supports 7 credential sources simultaneously, with a strict priority order. You think you're using a subscription, but it might be using an environment variable you don't even know exists.

Credential Priority (Official Complete Order, Highest to Lowest)

  1. Cloud Provider Channel: When CLAUDE_CODE_USE_BEDROCK / CLAUDE_CODE_USE_VERTEX / CLAUDE_CODE_USE_FOUNDRY are set, uses AWS/GCP/Azure credentials (Note: logged-in enterprise gateway sessions are even higher)
  2. ANTHROPIC_AUTH_TOKEN: Sent as Bearer header —— LLM gateways/proxies rely on this
  3. ANTHROPIC_API_KEY: Sent as X-Api-Key header. Interactive mode prompts for confirmation the first time; non-interactive mode (-p) uses it directly if it exists, without asking
  4. apiKeyHelper Script: Dynamic key retrieval script configured in settings.json (default refreshes every 5 mins or on 401)
  5. CLAUDE_CODE_OAUTH_TOKEN: 1-year token generated by claude setup-token (for CI)
  6. Subscription OAuth: Credentials from /login browser OAuth —— Ranked last. This is why any environment variable can "hijack" your subscription
Must Read for Members: Why am I paying twice?You are a Pro/Max member, but there is a leftover ANTHROPIC_API_KEY on your machine (from old experiments, former colleagues, or tutorials) —— It takes priority over your subscription, and every conversation is billed via API, or you get This organization has been disabled if the key's org is disabled. Fix: unset ANTHROPIC_API_KEY + remove export lines from shell config + check /status to confirm Login method is back to subscription.

Where are credentials stored (Official Stance)

Credentials are strictly managed by /login / /logout, do not manually edit or copy across machines. When login is within 5 days of expiration, starting up will prompt Your login expires in N days, run /login once to renew (v2.1.203+); after expiration, every request reports Login expired · Please run /login.

Claude Code 03

Claude Code · settings.json Complete Guide: Minimal to Full Dictionary

The previous chapter discussed "whose credential takes effect" (priority); this chapter discusses the file that solidifies it all —— what keys settings.json has, the minimum needed to run, what it looks like fully populated, and exactly how to write "third-party/account combinations" into the file.

I. Where is the file, who overrides whom

LayerLocationImpact ScopeTeam Shared
Enterprise ManagedServer issued / managed-settings.jsonOrganization or all users on machineYes (IT deployment)
CLI Arguments--xxx flags at startupCurrent session only, temporary overrideNo
Project Local.claude/settings.local.jsonOnly you, only this repoNo (auto gitignore)

Priority from highest to lowest follows the table from top to bottom —— Enterprise Managed always wins, CLI arguments next, Project Local over Project, and User layer at the bottom. If a change doesn't take effect, it's 90% likely overridden by a higher layer; the "Setting sources" row in /status shows the actual loaded sources; claude doctor can also report invalid fields.

II. Minimum Runnable Configuration

Claude Code doesn't need any settings.json to run —— it's perfectly fine if the file doesn't exist, it uses built-in defaults after login. If you want to explicitly declare "this is the minimum config" for a team starter template, this is enough:

{
  "$schema": "https://json.schemastore.org/claude-code-settings.json"
}

Adding the schema declaration is the only "necessary" line —— it doesn't affect behavior, just provides autocomplete and validation when editing in VS Code/Cursor. A truly useful but still minimal starter config:

{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": ["Bash(npm run lint)", "Bash(npm run test *)"],
    "deny": ["Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)"]
  }
}

Where Credentials Are Stored & How They Renew

  • Storage Choice of Three: In config.toml, cli_auth_credentials_store = "file" | "keyring" | "auto". file = Plaintext ~/.codex/auth.json; keyring = System keychain; auto prioritizes keychain.
  • Auto-Renewal: When the token expires (becomes stale after ~8 days of inactivity), Codex automatically refreshes it during runtime and writes back to auth.json —— the CI persistence solution is built on this mechanism (see Chapter 10).
  • CLI and IDE Extension Share the Same Credential: If one side logs out, the other goes offline —— "IDE suddenly asking to login" mostly means you logged out from the terminal.
  • Multi-Account: Officially no first-class support yet (upstream issue #4432 in discussion); can be achieved via CODEX_HOME directory isolation (see Chapter 08), and community tools like codex-multi-auth exist.
  • Enterprise Control: forced_login_method / forced_chatgpt_workspace_id can lock the login method and workspace; mismatches will force an immediate logout —— "can't change login method" on company machines is a policy enforcement.

How to tell if it's stale: Only ChatGPT login (tokens non-empty) has renewal behavior —— the deciding factor is the last_refresh field. If it's been more than 8 days, it means the next run will automatically refresh it; for API key logins, this field is always null and this check does not apply.

Playbook A · Shared Computer / Inheriting a Pre-configured Machine

The most frequent failure scene: You are a Claude Pro user, sitting at a computer someone else used, and hitting walls of errors. The root cause is almost always the same: The previous user's credentials and env vars are still alive, and their priority is higher than your login.

The 3 Pre-Checks (Do this before configuring)

  1. Check Env Vars and RC Residue: Run Chapter 01 Health Check script, focusing on L2 output —— export ANTHROPIC_API_KEY / ANTHROPIC_BASE_URL (proxy config) / OPENAI_API_KEY in someone else's rc file are ticking time bombs.

Scenario Playbook 10

Playbook C · SSH / Containers / Headless / CI

In environments without a browser, logging in requires a different approach. The official recommended paths for the two tools differ, so do not mix them up.

Claude Code: Three Paths

  1. SSH/WSL2/Container Interactive Use: Run claude normally, copy the OAuth URL from the terminal into your local browser to complete login, then paste the code back into the terminal (if pasting fails, use claude auth login to read from stdin).
  2. CI / Scripts (Subscription Quota): Run claude setup-token locally to generate a 1-year OAuth token, store it in CI Secrets, and set CLAUDE_CODE_OAUTH_TOKEN in the execution environment. Note that --bare mode ignores this; for bare scenarios, use ANTHROPIC_API_KEY or apiKeyHelper instead.
  3. CI (API Billing): Just use the ANTHROPIC_API_KEY environment variable —— simplest, but uses pay-as-you-go billing.

Codex: Three Official Methods by Priority

  1. Device Code (Preferred): codex login --device-auth, enter the one-time code in any local browser. Workspace admins might need to enable device code permissions first.
  2. Copy auth.json (Official Fallback): Log in on a machine with a browser, then securely copy ~/.codex/auth.json to the target machine (scp / docker cp). If local credentials are in the keychain instead of a file, set cli_auth_credentials_store to file and re-login first.
  3. SSH Port Forwarding: ssh -L 1455:localhost:1455 user@remote then run codex login on the remote machine; the local browser handles the standard flow.

Codex CI Long-term Auth (Official auth.json Renewal Loop)

The official way to run CI using ChatGPT subscription quota —— leveraging Codex's mechanism to automatically refresh the token and write back to auth.json during runtime:

  1. Run codex login (file storage) on a trusted machine, store the generated auth.json into CI Secrets management;
  2. For each task: Restore auth.json → Run Codex (token goes stale if not refreshed for ~8 days, auto-renews during runtime) → Write back the refreshed auth.json to Secrets;
  3. Red lines: Do not share the same auth.json across concurrent tasks; Do not overwrite with the original old file every time; If the refresh chain breaks, go back to a trusted machine to re-login and seed a new one. For self-hosted runners, just providing a persistent CODEX_HOME is easier.
Container / DevContainer Persistent LoginMount the "home directory" as a volume so you don't have to re-login when the container rebuilds: For Claude Code, mount a volume pointed to by CLAUDE_CONFIG_DIR (Linux credentials live in .credentials.json inside it); For Codex, mount the CODEX_HOME volume. Red line: Credentials only go into volumes, never bake them into image layers.

Case Studies 11

Case Studies: From Symptoms to Root Causes

Four high-frequency real-world scenarios, walking through the 5-Layer Diagnostic Method from start to finish. Understand these four, and you can solve most "voodoo problems" yourself —— note how far the error text is from the actual root cause in each case.

Case I · "I'm a Pro subscriber, but it says organization disabled"

SceneTook over a colleague's old PC, installed Claude Code, logged in with subscription successfully. Asked a question and got API Error: 400 "This organization has been disabled". Reinstalled twice, no change.
TriageL1 normal (single install, latest version); L2 hit —— env | grep -i anthropic caught an ANTHROPIC_API_KEY=sk-ant-…, tracing it back to ~/.zshrc left by the previous user. The Console organization for that key was long deleted.
Fixunset the variable + delete the export line in rc file → Restart terminal → /status confirms Login method reverted to subscription. Took 3 minutes total, zero reinstalls needed.
LessonThe error said "organization", you thought "subscription", but the actual culprit was "environment variable" —— Error text describes the result, not the root cause. This is why reinstalling (touching L1) never cures an L2 disease.

Case II · "VS Code extension keeps saying Invalid API key, but terminal is fine"

SceneRunning claude in terminal is perfect; VS Code extension repeatedly pops up Invalid API key · Please run /login, and stays blank even after successful login. Widespread community issue (classic form documented in anthropics/claude-code#12204).
TriageL3 Credential layer hit, but root cause is L2: Three credentials co-exist on the machine —— OAuth login, manual API key, and shell env vars. The environment the terminal reads from rc files is different from what VS Code inherits upon graphical startup. They each picked different credentials; one valid, one invalid.
FixKeep only one credential source: Clear all ANTHROPIC_* vars and manual keys → Clean re-login for both CLI and extension → Both sides show the same subscription account via /status.
Lesson"Terminal good, IDE bad" almost always means the two processes are seeing different environments. When multiple credentials coexist, nobody can guarantee which process grabs which —— always keep exactly one credential source.

Case III · "Woke up and all parallel sessions demand re-login"

SceneLeft three parallel Claude Code sessions open overnight, closed laptop lid. Woke it up in the morning and all three demanded login. Logging into one knocked the other two out —— like a ghost in the machine.
TriageL2/L3 are clean. Counter-intuitively, it lands on L1 Version layer: Checked official changelog, versions before v2.1.211 had a known defect —— upon waking from sleep, multiple sessions concurrently renewed the same token, invalidating each other's logins.
FixUpgrade to ≥ v2.1.211 (renewal changed to single-process coordination), re-login once, never recurred since.
LessonFor collective, weirdly-timed phenomena, check versions and changelogs first, rather than messing with your own config —— you can never diagnose the root cause locally for a bug the vendor has already patched.

Case IV · "Codex ran stable in CI for a week, suddenly 401 across the board"

SceneRunning CI on ChatGPT subscription quota: Saved local auth.json into Secrets, restored before each run. A week later, all pipelines started 401ing. Exported a fresh one locally, lasted a few more days, then repeated.
TriageL3 Credential layer hit: Codex tokens go stale after ~8 days without refresh. During runs, it actually auto-renews and writes back to auth.json —— but the pipeline overwrites it with the "factory original" from Secrets every time, discarding all renewals. Once the refresh chain breaks, everything fails.
FixClose the loop per official CI docs: Restore → Run → Write the refreshed auth.json back to Secrets; Do not share the same credential across concurrent tasks. For self-hosted runners, simply providing a persistent CODEX_HOME fixes it once and for all.
LessonCredentials are alive, not configuration constants. For any issue that "breaks predictably every N days", suspect a time-expiring item missing its renewal channel.

Ultimate Solution 12

The Universal Fix: 3-Tier Reset Plan

If you genuinely can't diagnose it, do a tiered reset. Discipline: Escalate step-by-step from L1, verify after each tier, stop when fixed —— dropping the nuke immediately destroys the "scene of the crime" where the problem could be identified, and most issues are resolved at L1/L2 anyway.

L1 Soft Reset (2 Mins) —— Fixes 70% of issues

# Clear hijacked vars in current shell (only affects this session, zero risk)
unset ANTHROPIC_API_KEY ANTHROPIC_AUTH_TOKEN ANTHROPIC_BASE_URL
unset OPENAI_API_KEY

# Clean re-login
claude   # Inside session: /logout → exit → claude again → /login → /status to verify
codex logout && codex login && codex login status

L2 Credential & Residue Reset (5 Mins) —— Fixes another 20%

# 1. Eradicate residual exports in rc files (open in editor and delete line-by-line, no blind sed)
grep -nE 'ANTHROPIC|CLAUDE_|CODEX|OPENAI' ~/.zshrc ~/.zprofile ~/.bashrc ~/.profile

# 2. Clear credential storage then re-login
#    Claude Code: /logout already cleared it; macOS extreme cases, unlock keychain:
security unlock-keychain ~/Library/Keychains/login.keychain-db
#    Codex: logout and delete credential file
codex logout; rm -f ~/.codex/auth.json

# 3. Calibrate system clock (token validation relies on it) —— macOS:
sudo sntp -sS time.apple.com

# 4. Re-login + Verify
claude   # /login → /status
codex login && codex login status

L3 Nuke Reset (15 Mins) —— Backup → Wipe Clean → Official Reinstall

# ═══ Step 1: Backup Core Assets (Manual configs are yours, the rest can be regenerated) ═══
mkdir -p ~/ai-cli-backup
cp -r ~/.claude/settings.json ~/.claude/CLAUDE.md ~/.claude/skills ~/.claude/agents ~/.claude/commands ~/ai-cli-backup/ 2>/dev/null
cp ~/.claude.json ~/ai-cli-backup/claude.json 2>/dev/null   # Save MCP global states, step 3 will delete it, if not backed up it's gone
cp -r ~/.codex/config.toml ~/.codex/AGENTS.md ~/.codex/prompts ~/ai-cli-backup/ 2>/dev/null

# ═══ Step 2: Uninstall All Co-existing Installations (Claude Code) ═══
npm uninstall -g @anthropic-ai/claude-code 2>/dev/null
rm -rf ~/.claude/local                        # legacy npm install
brew uninstall --cask claude-code 2>/dev/null # if ever installed via brew

# ═══ Step 3: Wipe State Directories (Backed up, safe to delete) ═══
rm -rf ~/.claude ~/.claude.json
rm -rf ~/.codex

# ═══ Step 4: Install fresh from official channels ═══
curl -fsSL https://claude.ai/install.sh | bash
npm install -g @openai/codex

# ═══ Step 5: Restore Configs + Re-login + Full Verification ═══
mkdir -p ~/.claude && cp ~/ai-cli-backup/settings.json ~/ai-cli-backup/CLAUDE.md ~/.claude/ 2>/dev/null
cp -r ~/ai-cli-backup/skills ~/ai-cli-backup/agents ~/ai-cli-backup/commands ~/.claude/ 2>/dev/null
cp ~/ai-cli-backup/claude.json ~/.claude.json 2>/dev/null   # Matching MCP global states backed up in step 1
mkdir -p ~/.codex && cp ~/ai-cli-backup/config.toml ~/ai-cli-backup/AGENTS.md ~/.codex/ 2>/dev/null
cp -r ~/ai-cli-backup/prompts ~/.codex/ 2>/dev/null
claude doctor && claude    # /login → /status confirm subscription active
codex login && codex login status
Three Checks Before the Nuke① Are there any session transcripts you want to keep in ~/.claude/projects/ (once deleted they are gone); ② Do the files actually exist in the backup dir (verify with your own eyes ls ~/ai-cli-backup); ③ Windows users wipe %USERPROFILE%\.claude and %USERPROFILE%\.codex respectively, and check User Environment Variables panel.
Still broken after reset?Then you can be fairly certain it's not on your machine: ① Official service status (status.anthropic.com / status.openai.com); ② Subscription status (claude.ai/settings / ChatGPT settings); ③ Enterprise control policies (ask IT); ④ Take the claude doctor output / codex-login.log to file an issue or contact official support —— this is the only situation where you need to "wait for others".
