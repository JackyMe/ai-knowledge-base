核心基座 01

1️⃣ Antigravity 核心概念与认知模型

官方基准对齐 Google Antigravity (代号 AGY) 是 Google 为 Agentic AI 软件工程时代打造的全新一代全栈基座。它不再将大模型局限于简单的聊天补全，而是将操作系统级沙箱、多智能体协同编排、MCP (Modular Command Protocol) 协议、AST 代码级语义感知与上下文生命周期治理深度融合为一体。

Antigravity 6 大底层核心概念

  • agy CLI：统一的命令行入口，驱动整个工作区诊断、代码搜索、修改提议与子代理分派。
  • Agentic IDE：双栏无缝融合的图形 IDE，原生内置代码编辑器、Planning Mode 计划审阅面板、实时 Diff 追踪器与 Artifacts 可视化预览器。
  • Customizations 定制体系：基于 .agents/ 或全局 ~/.gemini/antigravity/ 的层叠式扩展中心，包含 Skills（能力技能）、Rules（执行规则）、Plugins（插件）与 MCP 服务器。
  • Subagents 智能体网络：具备独立 Conversation ID、上下文状态机与工作区模式的自主背景智能体，支持父子层级协同通信。
  • Artifacts 交付物机制：将复杂方案、架构图（Mermaid）、UI 原型与迁移计划持久化为标准化 Markdown，杜绝在对话中刷屏。
  • Reactive Wakeup 响应式唤醒：全异步任务架构，主代理派发后台子任务或定时调度后无需轮询，任务完成或收到消息时系统会自动唤醒主代理。

# Linux (Debian / Ubuntu / RHEL 一键脚本)

Antigravity Agentic IDE 快捷键矩阵

  • Cmd+L / Ctrl+L —— 聚焦右侧 Agent 交互面板，并自动将当前选中的代码行与文件锚点注入提示词。
  • Cmd+Shift+P —— 打开 Antigravity 命令调色板，快速执行 /goal, /schedule, /grill-me 等高级流程。
  • Ctrl+Alt+R —— 在沙箱内对当前文件或关联测试套件执行静默自验，输出通过证据。
  • Ctrl+Alt+S —— 实时分屏渲染当前会话生成的 Markdown / HTML / UI Artifacts。
扩展体系 04

4️⃣ Customizations 定制体系：Skills · Rules · MCP · Plugins

Antigravity 拥有三级优先级规则查找系统：当前项目 .agents/ (最高) > 用户全局 ~/.gemini/antigravity/ > 内置规范 (Built-in)。所有规则支持热重载（Hot-reload），无需重启。

4.1 编写高可用 Skill（以安全审计 Skill 为例）

在 .agents/skills/security-guard/SKILL.md 中声明能力规则：

---
name: security-guard
description: "生产级敏感信息与 SQL 注入静态安全合规扫描器"
---
# 核心安全审计准则
1. 严禁在代码中硬编码任何 API Key、JWT Secret 或内网数据库密码。
2. 所有对外暴露的 API 请求参数必须经过严格的 schema 校验与反序列化约束。
3. 检查所有数据库查询，强制使用参数化预编译绑定，坚决杜绝字符串直接拼接 SQL。
4. 外部 HTTP 请求必须强制配置超时限制 (Timeout) 与指数退避重试 (Exponential Backoff)。

4.2 编写全局拦截规则 (Rules)

# .agents/rules/safe-terminal.yml
---
severity: critical
description: "沙箱防御：拦截未授权的敏感文件外发与高危终端指令"
enforce:
  - tool: run_command
    condition: "BypassSandbox == false && CommandLine matches '(rm\\s+-rf\\s+/|mkfs|dd\\s+if=)' => reject"
  - tool: replace_file_content
    condition: "TargetFile matches '\\.(env|pem|key)$' => require_user_approval"

工程治理 07

7️⃣ 性能、成本与沙箱安全防御体系

  1. 标准沙箱优先（Standard Sandbox First）：所有终端命令默认在无外网访问、限制文件系统的标准沙箱中运行。只有在确需下载依赖或访问外部网络时，才显式声明 BypassSandbox: true 并等待用户审批。
  2. Planning Mode 纪律性要求：涉及多文件架构改造、跨模块重构的大型任务，必须先生成 implementation_plan.md 架构设计方案，明确用户 review 事项与自验步骤，严禁在未获批准前擅自修改源代码。
  3. 增量精准补丁（Incremental Edits）：坚决杜绝在数千行的大文件中使用全量覆写，强制使用 replace_file_content 定点替换，极大节省上下文 Token 并保证 Git 历史整洁。

8️⃣ 避坑清单与 30 秒急救室

典型报错与症状底层根本原因30 秒对症解决指南
TargetContent not found目标代码块的前后缩进、换行符（CRLF vs LF）或不可见字符与现有文件不匹配先调用 view_file 精确查看目标行号与缩进，再原样传入 TargetContent。
Subagent in waiting_for_input子代理遇到了需要人工交互确认的命令或提示运行 manage_subagents list 确认状态，使用 send_message 向其发送确认指令即可恢复。
Sandbox Network Blocked在标准沙箱内执行了 curl, npm install 或 git pull确认网络合规性后，在调用参数中指定 BypassSandbox: true 进行提权审批。
Context Token Overflow单会话内连续打印超长日志或输出超大 JSON使用 /clear 清空旧历史，或将长日志处理委托给 research 子代理。
工程治理 09

9️⃣ 工业级端到端实战案例：服务重构与并发跑测

演示如何从需求分析、子代理调研、计划拟定，到代码增量修改与沙箱自动化验证的全闭环：

# 第一步：派发只读 research 子代理进行代码库架构分析
agy subagent invoke research --prompt "分析 src/auth/ 模块中原有 Session 机制的瓶颈，梳理依赖关系"

# 第二步：编写结构化 implementation_plan.md 交付物并等待审批
agy write_to_file --TargetFile .gemini/antigravity/brain/implementation_plan.md \
  --CodeContent "# OAuth2 + PKCE 重构实施方案..."

# 第三步：用户确认后，使用原子编辑工具进行代码定点重构
agy edit src/auth/oauth2.py --range 15-60

# 第四步：在标准隔离沙箱中运行全量单元测试与回归套件
agy run "pytest tests/test_oauth2.py -v" --wait 5000

🔟 常用速查表与 Slash 指令手册

  • /goal —— 用于长耗时、无人值守的复杂任务，主代理将穷尽一切手段直至目标彻底达成。
  • /schedule —— 快速唤起定时任务与定时器配置面板。
