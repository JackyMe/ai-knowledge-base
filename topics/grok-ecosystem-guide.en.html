Grok & xAI guide

Choose between chat, Grok Bot, Grok Build, and the API; verify sources and permissions.

01

Four surfaces and their uses

Grok chat handles conversations and media, Bot handles ongoing work, Build handles coding, and APIs power applications. Check access and billing separately.

docs.x.ai · overview · 2026-09-09

02

Choose and evaluate models

Check available models, then compare accuracy, latency, and cost on your own tasks. Model names, limits, and pricing change; avoid unsupported rankings and architecture claims.

docs.x.ai · models · 2026-09-09

03

X search and fact checking

X Search supports keyword, semantic, user, and thread searches. Enable the tool in API requests. Check post URLs, times, and authors against primary sources; popularity is not verification.

docs.x.ai · x-search · 2026-09-09

04

Define and verify research

Specify the question, period, region, evidence, and format. Separate facts, inferences, disputes, and unknowns. Check every consequential citation. This is a suggested workflow, not an internal product architecture.

05

Grok Bot: ongoing roles

Give each persistent Bot a clear role, sources, output standard, and approval boundary. Start with a small task before connecting accounts. Memory does not replace current business data.

docs.x.ai · overview · 2026-09-09

06

Shared computers and authorization

Bots can share a user computer, files, and sign-ins. Roles are not isolation, and deleting a Bot may leave shared state. Authorize messaging, data changes, publishing, and spending explicitly.

docs.x.ai · bots · 2026-09-09

07

Skills and routines

Skills define how; routines define when and who. Validate one complete run before scheduling. Define success, notification, and stop conditions; avoid repetitive non-actionable updates.

docs.x.ai · skills-routines-and-automations · 2026-09-09

08

Grok Build: terminal coding

The official Build entry is an interactive TUI, with headless and ACP support. It is not restricted to a browser cloud sandbox. Start grok in a project and review changes and tests.

grok
grok -p "Explain this codebase without modifying files"

docs.x.ai · overview · 2026-09-09

09

API access, caching, and billing

Keep API keys in environment variables or secret storage. Use documented model IDs and SDK interfaces. Track input, output, cache, and tool costs separately; chat subscriptions are not API balances.

docs.x.ai · pricing · 2026-09-09

10

Tool calls require validation

Define tool schemas and validate parameters, identity, and authorization at execution. Restrict calls to registered tools, handle timeouts and retries, and separate read access from writes and external actions.

11

Example: research and review

Example: one Bot gathers sources, another checks facts, and an owner merges results. Assign one writer per shared artifact. This is an illustrative workflow, not a measured case study or required Swarm SDK.

13

Errors and diagnostic order

Keep status codes, request IDs, and redacted logs. Check credentials, access, quotas, and service health in turn. Use bounded retries; a status code alone does not establish the root cause.

14

Plans and usage

Paid app plans increase limits. Check current eligibility and allowance in your account; old prices, message counts, and reset windows are not permanent promises. Verify API billing separately.

docs.x.ai · overview · 2026-09-09

15

Images and video

Use Grok Imagine for images and video. Specify composition, aspect ratio, and preserved elements; change one issue per iteration. Verify text, branding, identity consistency, and factual details.

docs.x.ai · overview · 2026-09-09

16

Sources and learning order

Complete a chat or local Build task first, then learn tool calls. Add Bots and routines for recurring needs. Verify availability, prices, and APIs against current documentation and your account.
