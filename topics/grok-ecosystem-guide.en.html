2.2 Recruiting Your First Bot & The 5-Step Delegation Formula

Role Architecture Prerequisites include: account eligibility, desktop app (macOS/Windows) or iPhone client, and cloud storage enabled. When recruiting your first Bot, avoid the pitfall of mirroring corporate executive charts; start with a single, repeatable, and verifiably measurable task.

⚠️ The "Hollow Executive" Anti-Pattern

Creating broad positions like "Chief Marketing Officer" or "VP of Growth" produces digital employees with vague mandates who produce generic platitudes. Instead, recruit for specific operational results with crisp accountability.

1. Profile Engineering: Long-Term Mandate vs Immediate Prompt

  • Profile (Job Description): Stores enduring rules—what domain it owns, primary authoritative sources, qualitative criteria, and default output conventions.
  • Chat Message (Single Task): Supplies the day's specific mission. Never alter the Profile for one-off research topics.
Intelligence Lead Role Profile Template 
# Role: Senior Market & Tech Intelligence Lead
You are responsible for monitoring applied AI breakthroughs, trending developer topics, and tooling ecosystem tutorials across global tech circles.

## Authority & Sources
- Primary source: First-hand developer releases, engineer breakdowns, and verified long-form articles on X
- Developer community discussions and GitHub trending initiatives

## Judgment Standards
- Verify original source links; never present uncorroborated rumors as established facts
- Distinguish strictly between official updates, third-party benchmarks, hype, and battle-tested production tools

## Delivery Specifications
- Categorize findings into Long-Form Analyses (X Articles) vs Tutorial Video Posts
- Must include: Author, Publication Timestamp, Public Reach Metrics, Core Highlights, and Canonical URL
- If primary metrics are unavailable, state clearly without fabricating numbers

2. The Golden 5-Step Delegation Formula

Never instruct a Bot with vague directives like "research Grok Bot". Every production delegation must include:

1. Clear Objective State the exact expected outcome (e.g., a curated digest of 5 top-tier practical tutorials).
2. Target Sources Specify discovery channels (e.g., search X posts over the past 7 days with >100k impressions).
3. Constraints & Exclusions Filter spam accounts, exclude outdated posts, and flag incomplete data.
4. Delivery Format Specify structured Markdown tables, JSON payloads, or specific report templates.
5. Human Checkpoint Define intermediate gates where the Bot must pause for supervisor sign-off before downstream action.

2.4 Codifying SOPs into Skills & 7 Rules for Unattended Cron

Standard Operating Procedures A defining trait of a digital employee is the ability to distill successful workflows into standardized Skills and attach them to cloud Cron triggers.

1. Distilling Workflows into Skills

  • Conversational Extraction: After verifying a task twice with different inputs, instruct the Bot: "Extract the objective, execution steps, validation gates, and error fallbacks from this workflow into a permanent Skill."
  • Teach a Task (Browser Demonstration): Launch screen recording (up to 10 minutes) and perform the web workflow manually. Grok Bot analyzes clicks, form fills, and downloads, compiling them into a repeatable Skill.

2. Seven Infallible Rules for Unattended Cron Execution

Rule 1: Timestamp & Source Attribution Every data point must retain exact fetch timestamps and source URLs.
Rule 2: Immediate Circuit-Breaker on Missing Data If target data is unavailable, halt immediately with an explicit warning; never backfill with stale data.
Rule 3: Transparent Partial Delivery Logs If only 80% completes, clearly itemize delivered vs missing items and root causes upfront.
Rule 4: Idempotent Retries Ensure retries append timestamps or unique IDs rather than generating duplicate emails or corrupting existing files.
Rule 5: Zero Auto-Escalation for Destructive Actions Automated Cron runs must freeze at approval gates when encountering publishing, financial payouts, or deletions.
Rule 6: Mandatory Regression Testing on UI Changes Whenever external sites update DOM structures or APIs, run a supervised test run before resuming unattended scheduling.
Rule 7: Periodic Human Spot-Checks Never assume two weeks of uninterrupted green runs guarantees indefinite perfection. Review underlying data regularly.

1. Group Chat Coordination Rules

  • First Message Protocol: The initiating message must outline the overall objective, baton-passing order, and the terminal handoff condition.
  • Single-Owner Baton Passing: Always address a single active agent with @BotName to prevent race conditions and concurrent write corruption.
  • Avoid Blanket @everyone: Restrict universal mentions to emergency alerts or initial brainstorming to conserve compute.

2. Auto-review Approval Safeguards

🚨 Security Warning: Bots Do Not Form Isolation Sandboxes

Bots under the same account share identical Cloud PC virtual machine state and browser sessions. Real security relies on Auto-review policies and Require Approval gates under Settings -> General -> Auto-review.

Customer Email & DMs Mass accidental outreach or customer data leakage Displays recipient list and body summary; requires dual confirmation.
Financial Disbursements Infinite loops triggering unauthorized refunds or charges Always freezes; requires human takeover to enter payment credentials.
File Deletions Accidental rm -rf on /workspace/ source assets Enforces confirmation prompts before destructive filesystem calls.
Infrastructure Mutations Altering database configs or DNS records Permitted only as staged script drafts; execution blocked without human sign-off.

4.5 Project: Automated PR Auditor Bot

import os, requests
from openai import OpenAI

def run_pr_audit():
    gh_token = os.environ.get("GITHUB_TOKEN")
    repo = os.environ.get("GITHUB_REPOSITORY")
    pr_num = os.environ.get("PR_NUMBER")
    
    diff_resp = requests.get(
        f"https://api.github.com/repos/{repo}/pulls/{pr_num}",
        headers={"Authorization": f"token {gh_token}", "Accept": "application/vnd.github.v3.diff"}
    )
    
    client = OpenAI(api_key=os.environ.get("XAI_API_KEY"), base_url="https://api.x.ai/v1")
    
    res = client.chat.completions.create(
        model="grok-3",
        messages=[
            {"role": "system", "content": "You are Grok, an elite Code Security Auditor."},
            {"role": "user", "content": f"Review this PR diff for security, memory leaks, and performance:\n\n{diff_resp.text[:15000]}"}
        ]
    )
    
    requests.post(
        f"https://api.github.com/repos/{repo}/issues/{pr_num}/comments",
        headers={"Authorization": f"token {gh_token}", "Accept": "application/vnd.github.v3+json"},
        json={"body": f"### 🤖 Grok-3 Automated Code Review\n\n{res.choices[0].message.content}"}
    )
