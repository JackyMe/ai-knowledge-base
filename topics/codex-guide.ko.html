  • 장시간 소요 대형 리팩토링/마이그레이션: codex cloud exec --attempts 3에 위임하고 로컬에서는 다른 작업 진행;
  • PR 제출 전 방어선: @codex review를 트리거하여 자동화 이중 검토 수행.
❌ 전형적인 안티패턴 (비효율 및 사고 유발)

4가지 목표 지향 학습 경로

🌱트랙 01: 제로 기초 입문 (안정감과 기본 루프 형성)TRACK 01

대상: Codex를 처음 접하거나 안전한 롤백이 보장된 태스크를 아직 완료해보지 못한 사용자.

  1. 환경 준비: 설치 완료 후 codex login으로 ChatGPT 계정 인증;
  2. 안전 기준선 확립: 독립된 Git 테스트 브랜치에 위치하고 git status로 깨끗한 상태 확인;
  3. 읽기 전용 탐색: codex --sandbox read-only를 실행하여 파일 수정 없이 프로젝트 구조와 README 분석 요청;
  4. 첫 번째 롤백 가능 태스크 완수: 15분 내 검증 가능한 작은 작업(타입 에러 1줄 수정, 주석 보강 등)을 수행하고 /diff로 검토 후 로컬 테스트 통과 확인 뒤 커밋.
⚡트랙 02: 프로 개발자 실전 (고품질 인도와 TDD 완결)TRACK 02

대상: Git과 최소 1개 이상의 백엔드/프런트엔드 언어에 능숙하며 극대화된 개발 생산성을 추구하는 엔지니어.

  1. 프로젝트 메모리 초기화: 저장소 루트에서 /init을 실행하여 빌드 및 테스트 명령이 담긴 간결한 AGENTS.md 생성;
  2. TDD 실패 테스트 우선: 버그 발견 시 Codex에게 문제를 재현하는 자동화 테스트 작성을 먼저 요구한 뒤 Green이 될 때까지 수정;
  3. 장시간 작업 4단계 규율: 토의(Plan) → 실행(Exec) → 검토(Review) → 정리(Closeout) 4단계로 복잡 모듈 추진;
  4. Issue-to-PR 자동화: 클라우드 파이프라인 연동 및 @codex review 자동 코드 리뷰 구축.
🛠️트랙 03: 역량 확장과 자동화 (나만의 AI 툴체인 구축)TRACK 03

대상: 팀의 반복 업무를 자동화 능력으로 자산화하려는 리드 개발자 및 DevOps 엔지니어.

  1. Skill 개발 표준화: SKILL.md, scripts/, references/ 구조를 따르는 커스텀 스킬 패키지 작성;

  4. CI/CD 연동 스크립팅: codex exec --json을 활용하여 정기 작업 및 자동화 테스트 파이프라인 연계.

규율 05

핵심 방법론 & 초보자 함정 탈출

1. 작업 정의 4요소 원칙 (Goal-Context-Constraints-Done)

  • Goal (목표): 달성할 구체적 결과를 명확히 정의 ("이 모듈 좀 봐줘" 지양);
  • Context (컨텍스트): 연관된 핵심 파일 및 관련 Issue/API 문서 지정 (/mention 활용);
  • Constraints (제약조건): 수정 금지 파일, 추가 라이브러리 도입 금지, 하위 호환성 요구 선언;
  • Done-when (완료 기준): 정량적 검증 기준 명시 (특정 단위 테스트 전체 통과, 특정 JSON 반환 등).

2. 초보자가 흔히 저지르는 8대 실수와 해결책

실수 번호대표적 잘못된 행동발생하는 문제올바른 표준 해결책
실수 01계획 요청 없이 무작정 수정 지시무관한 파일을 대규모 수정하여 기존 구조 파괴복잡 작업은 /plan으로 영향 범위 사전 검토
실수 02커밋되지 않은 지저분한 브랜치에서 실행AI 수정분과 내 작업분이 뒤섞여 롤백 불가착수 전 git stash 또는 새 feat/xxx 브랜치 생성
실수 03Ctrl+L을 새 대화로 오인화면만 지워지고 컨텍스트가 남아 환각 발생완전 리셋은 반드시 /new 또는 /clear 사용
실수 04한 세션에서 서로 다른 작업을 연속 수행토큰 낭비, 모델 집중도 저하, 실행력 급락하나의 세션은 하나의 작업에 집중, 완료 시 /new
실수 05네트워크 제한을 무시하고 패키지 설치 요구workspace-write의 네트워크 차단으로 타임아웃외부 네트워크 작업 시 권한 승인 또는 --search 추가
실수 06"완료되었습니다"라는 말만 믿고 diff 미확인예상치 못한 논리 누락이나 구문 결함 방치커밋 전 반드시 /diff로 변경 줄을 직접 검토
실수 07버그 수정 시 감으로 코드를 고치게 함try-catch로 에러만 숨기고 근본 원인 방치TDD 준수: 실패하는 재현 테스트 작성 후 패스 유도
실수 08편의를 위해 메인 머신에서 --yolo 사용시스템 파일 오삭제 및 API Key 유출 위험개인 로컬 머신에서 --yolo 절대 금지
협업 06

장시간 작업 4단계 규율 & 멀티 세션 엔지니어링

30분 이상 소요되는 대형 리팩토링이나 복잡한 모듈 개발 시, 단일 세션으로 끝까지 진행하면 주의력 분산과 환각이 발생합니다. Codex의 전문 워크플로우는 4단계 규율과 세션 분류입니다.

1. 장시간 작업 4단계 규율 (Four-Stage Discipline)

  1. 토의 및 기획 단계 (Discuss / Plan): read-only 샌드박스에서 /plan을 실행하여 코드베이스를 분석하고 구체적 수정 계획, 파일 목록, 리스크 평가 도출. (코드 수정 안 함)
  2. 격리 실행 단계 (Execute): 새 세션을 열고 승인된 Plan을 마운트하여 workspace-write 권한으로 모듈을 단계별 구현하며 최소 단위 검증 실행.
  3. 독립 검토 단계 (Review): 새로운 세션을 열거나 /review를 호출하여 제3자 시각에서 견고성, 경계 조건, 보안성 검토 수행.
  4. 마무리 및 인수인계 단계 (Closeout & Handover): 테스트 통과 증빙과 스크린샷을 추출하고 DECISIONS.md와 AGENTS.md를 업데이트한 뒤 PR 생성.

2. 멀티 세션 및 협업 툴킷

  • 임시 서브 대화 /side (/btw): 궁금한 점(예: "이 라이브러리 버전이 왜 2.1로 고정되어 있지?")이 생겼을 때 서브 대화로 탐색하고 결론만 가지고 복귀하여 메인 세션의 토큰 오염을 방지합니다.
  • 세션 분기 codex fork: 동일한 문제에 대해 A안(리팩토링)과 B안(핫픽스)을 모두 시도해보고 싶을 때 세션을 분기하여 병렬 검증합니다.
  • 원격 제어 (Remote Control): 가벼운 노트북에서 --remote ws://...를 통해 고사양 워크스테이션이나 클라우드 인스턴스의 Codex app-server에 연결하여 연산 파워를 활용합니다.

1. 최강의 Prompt 템플릿: TDD 무환각 포맷 (Zero-Hallucination)

> 【목표】src/auth/jwt.ts에 Refresh Token 슬라이딩 윈도우 갱신 로직을 추가해줘.
  【컨텍스트】docs/auth-flow.md 문서와 현재 jwt.ts 코드를 읽고 분석할 것.
  【제약 사항】
  1. jwt.ts 및 대응하는 테스트 파일만 수정 가능하며, routes 모듈은 절대 건드리지 말 것.
  2. 기존 HMAC-SHA256 서명 알고리즘을 유지하고, 새로운 npm 라이브러리를 추가하지 말 것.
  3. 동시성 환경에서의 락(Lock) 메커니즘을 고려하여 동일 토큰이 중복 갱신되지 않도록 할 것.
  【검수 기준】
  먼저 tests/auth/jwt.test.ts에 3개의 테스트 케이스(동시 갱신 테스트 포함)를 작성할 것.
  테스트를 실행하고 모두 녹색(Pass)으로 통과할 때까지 자가 교정을 수행한 뒤, 최종 /diff 결과를 보여줄 것.

  • 입력이 극도로 정밀하므로 단 한 번에 테스트를 통과하고 Git Commit까지 완료하여, 터미널 쿼터 소모를 최소한으로 억제합니다.

🛡️ 3. 쿼터 방어 및 컨텍스트 최적화 수칙

실전에서 검증된, 사용 한도를 현격히 연장해 주는 핵심 규칙들입니다:

1. '새 메시지 추가' 대신 '직전 메시지 편집' 활용

대다수 사용자가 놓치고 있는 가장 중요한 절약 테크닉입니다. AI의 답변이 의도와 벗어났을 때, 새 메시지로 반박하거나 추가 질문을 보내지 마십시오. 매번 추가할 때마다 이전의 모든 실패 시도가 누적되어 재전송됩니다. 직전 질문의 '편집' 버튼을 눌러 프롬프트를 수정하고 재제출하면, 이전의 잘못된 브랜치가 현재 컨텍스트에 누적되지 않습니다.

2. 명확한 Custom Instructions (사용자 지정 지침) 구축

매 대화마다 "TypeScript로 써줘", "불필요한 인사말은 생략해줘"라고 반복하지 않도록, 설정의 사용자 지정 지침이나 프로젝트 루트의 SKILL.md에 사전 정의해 둡니다.

권장 사용자 지정 지침 템플릿 (설정 -> ChatGPT 맞춤 설정) - 역할: 시니어 풀스택 아키텍트. - 출력 스타일: 간결, 엄격, 엔지니어링 지향. "알겠습니다", "좋은 질문입니다" 등 불필요한 인사말과 맺음말 일체 금지. - 코드 규칙: 변경된 부분만 출력(변경되지 않은 부분은 // ... existing code ...로 표기). TypeScript 타입 선언 필수. - 음성 모드 제약: 요점만 간결하게 답변하며, "더 필요하신 것이 있나요?" 등의 상투적 질문 생략.

3. 모델 등급별 활용 수칙: 사소한 작업에 고사양 모델 낭비 금지

  • Reasoning / 심층 사고 모드 (o3 / 사고 모델): 복잡한 동시성 경합 해결, 알고리즘 증명, 저장소 단위 대규모 리팩터링 등 난제 해결에만 집중 투입.
  • Fast / Mini 모드: 정규식 작성, JSON/YAML 포맷 변환, Git 커밋 메시지 생성, 사소한 스타일 수정 등 일상적 작업에 사용. 속도가 월등히 빠르고 쿼터 소모가 거의 없습니다.
