멘탈 모델 00

모든 것은 컨텍스트를 중심으로 회전한다

Claude Code는 단순한 챗봇이 아니라 에이전틱 코딩 환경(Agentic Coding Environment)입니다. 파일을 읽고, 명령을 실행하며, 코드를 수정하고 자율적으로 문제를 해결합니다. 사용자의 역할은 진행 상황을 관찰하고 방향을 조율하거나 작업을 위임하는 것입니다.

핵심 제약 조건컨텍스트 윈도우에는 대화 전체(주고받은 메시지, 읽은 파일 내용, 실행한 명령어의 stdout 출력)가 담깁니다. 컨텍스트가 가득 차면 모델의 주의력이 분산되고 초기의 지시를 망각하기 시작합니다. 컨텍스트야말로 당신이 가장 엄격하게 관리해야 할 자원입니다.

이 하나의 원칙에서 대부분의 엔지니어링 실무가 도출됩니다:

  • 서브에이전트로 탐색하는 이유 → 방대한 탐색으로 소모되는 것은 서브에이전트의 컨텍스트이며, 내 메인 대화가 오염되지 않기 때문.
  • CLAUDE.md를 짧게 유지하는 이유 → 매 세션마다 로드되므로 길어지면 핵심 규칙이 노이즈에 묻히기 때문.
  • 지식을 CLAUDE.md에 욱여넣는 것보다 Skills가 우수한 이유 → 스킬은 필요한 순간에만 온디맨드로 로드되어 평소에는 컨텍스트를 전혀 차지하지 않기 때문.
  • /clear, /compact, /btw가 필요한 이유 → 모두 컨텍스트 여유 공간을 확보하기 위한 핵심 도구이기 때문.
  • "2회 수정 실패 시 리셋"인 이유 → 실패한 삽질 기록이 컨텍스트에 남아 모델이 같은 함정에 계속 빠지기 때문.

5대 황금 법칙

법칙 1: Claude에게 직접 실행할 수 있는 검증 수단을 제공하라

Claude는 "작업이 겉보기에 끝난 것처럼 보이는" 순간 멈춥니다. 실행 가능한 체크 수단이 없으면 사용자가 모든 오류를 일일이 찾아내야 합니다. 성공/실패(pass/fail)를 판정할 수 있는 시그널(테스트 스위트, 빌드 종료 코드, 린터, 스크린샷 등)을 주면 자율 폐루프가 완성됩니다: 작업 → 검증 실행 → 결과 확인 → 통과할 때까지 자가 개선.

❌ 모호한 지시"이메일 검증 함수 만들어줘" / "빌드 깨졌는데 고쳐줘"
✅ 강력한 지시"validateEmail을 만들고 테스트 케이스(정상 이메일, 빈 문자열, 잘못된 형식)를 작성하여 구현 후 테스트를 실행해줘" / "빌드 에러 전문 첨부 [로그]. 근본 원인을 수정하고 빌드가 통과함을 증명해줘"

법칙 2: 먼저 탐색하고, 계획을 세운 뒤, 마지막에 코딩하라

복잡한 작업의 4단계: Explore(계획 모드에서 파일을 읽고 질문하며 코드는 건드리지 않음) → Plan(수정 계획 수립, Ctrl+G로 직접 편집 가능) → Implement(계획 모드를 나와 구현 착수) → Commit(커밋 메시지 작성 후 PR 생성).

법칙 3: 프롬프트는 구체적으로, 컨텍스트는 풍부하게

전략약한 프롬프트강력한 프롬프트
범위 한정"foo.py에 테스트 추가해줘""foo.py에 로그아웃 상태의 엣지 케이스를 다루는 단위 테스트를 작성해줘. mock은 사용하지 말 것"
기존 패턴 인용"새 캘린더 컴포넌트 추가해줘""홈 화면의 기존 위젯(HotDogWidget.tsx) 구현 패턴을 준수하여 캘린더 컴포넌트를 만들어줘. 외부 라이브러리 추가 금지"
원인 추적 지시"로그인 에러 고쳐줘""세션 만료 후 로그인 실패 버그 발생. src/auth/ 토큰 갱신 로직을 확인하고 실패를 재현하는 테스트를 먼저 작성한 뒤 수정해줘"

법칙 4: 잘게 방향을 틀고, 자주 컨텍스트를 비워라

  • Esc로 언제든 중단 가능. 컨텍스트가 유지된 상태에서 방향을 즉시 바로잡을 수 있습니다.
  • Esc Esc 또는 /rewind로 롤백 메뉴를 열어 코드와 대화를 되돌릴 수 있습니다.
  • 무관한 작업을 시작하기 전에는 반드시 /clear를 실행합니다. 동일한 문제로 2번 시도해서 실패했다면 더 이상 붙잡고 있지 말고 /clear 후 프롬프트를 정제하여 재시작하세요.

법칙 5: 대규모 기능 착수 전 Claude에게 먼저 인터뷰를 시켜라

나는 [기능 요약]을 개발하려 함. AskUserQuestion 도구를 사용하여 나에게 인터뷰를 진행해줘.
기술적 구현, UI/UX, 엣지 케이스, 성능 및 보안 트레이드오프에 대해 질문할 것.
사소한 질문은 피하고 내가 놓쳤을 법한 난제를 파고들어줘.
질문이 끝나면 완전한 명세서를 SPEC.md로 작성해줘.

실전 07

8대 시나리오 실전 Playbook

🌱시나리오 ①: 신규 미지의 저장소 온보딩PLAYBOOK · ONBOARDING

read-only 모드로 진입하여 /init을 실행하고 프로젝트 아키텍처를 탐색합니다. 서브에이전트를 띄워 데이터 흐름을 다이어그램으로 그리게 합니다.

🐛시나리오 ②: TDD 기반 버그 격파PLAYBOOK · TDD DEBUG

먼저 실패를 재현하는 단위 테스트를 작성하게 하고, 테스트가 통과할 때까지 내부 로직을 수정하게 한 뒤 /diff로 검토합니다.

🏗️시나리오 ③: 대규모 다중 파일 리팩토링PLAYBOOK · REFACTORING

/plan 모드에서 파일 변경 목록을 승인한 뒤 모듈별로 쪼개어 단계별 구현 및 테스트를 통과시킵니다.

🚀시나리오 ④: Issue에서 PR까지 자동 완결PLAYBOOK · ISSUE TO PR

Issue 번호를 지정하여 구현 브랜치를 따고, 로컬 테스트를 완벽히 통과시킨 뒤 커밋 및 PR을 생성합니다.

컨텍스트 08

컨텍스트 관리의 극의

컨텍스트 창 최적화 4대 수칙

  1. 2회 실패 시 즉시 /clear: 모델이 실패한 기록에 갇히지 않도록 깨끗한 상태에서 명확해진 프롬프트로 재시작;
  2. 탐색성 질문은 /btw 또는 서브에이전트 활용: 본선 대화의 토큰 낭비를 차단;
  3. 긴 세션은 /compact로 요약 압축: 중요 결론만 남기고 불필요한 중간 stdout 출력을 정리;
  4. @파일 정밀 지정: 전체 폴더를 무작정 읽히지 말고 필요한 파일만 명시.
