멘탈 모델 00

모든 것은 컨텍스트를 중심으로 회전한다

Claude Code는 단순한 챗봇이 아니라 에이전틱 코딩 환경(Agentic Coding Environment)입니다. 파일을 읽고, 명령을 실행하며, 코드를 수정하고 자율적으로 문제를 해결합니다. 사용자의 역할은 진행 상황을 관찰하고 방향을 조율하거나 작업을 위임하는 것입니다.

핵심 제약 조건컨텍스트 윈도우에는 대화 전체(주고받은 메시지, 읽은 파일 내용, 실행한 명령어의 stdout 출력)가 담깁니다. 컨텍스트가 가득 차면 모델의 주의력이 분산되고 초기의 지시를 망각하기 시작합니다. 컨텍스트야말로 당신이 가장 엄격하게 관리해야 할 자원입니다.

이 하나의 원칙에서 대부분의 엔지니어링 실무가 도출됩니다:

  • 서브에이전트로 탐색하는 이유 → 방대한 탐색으로 소모되는 것은 서브에이전트의 컨텍스트이며, 내 메인 대화가 오염되지 않기 때문.
  • CLAUDE.md를 짧게 유지하는 이유 → 매 세션마다 로드되므로 길어지면 핵심 규칙이 노이즈에 묻히기 때문.
  • 지식을 CLAUDE.md에 욱여넣는 것보다 Skills가 우수한 이유 → 스킬은 필요한 순간에만 온디맨드로 로드되어 평소에는 컨텍스트를 전혀 차지하지 않기 때문.
  • /clear, /compact, /btw가 필요한 이유 → 모두 컨텍스트 여유 공간을 확보하기 위한 핵심 도구이기 때문.
  • "2회 수정 실패 시 리셋"인 이유 → 실패한 삽질 기록이 컨텍스트에 남아 모델이 같은 함정에 계속 빠지기 때문.

5대 황금 법칙

법칙 1: Claude에게 직접 실행할 수 있는 검증 수단을 제공하라

Claude는 "작업이 겉보기에 끝난 것처럼 보이는" 순간 멈춥니다. 실행 가능한 체크 수단이 없으면 사용자가 모든 오류를 일일이 찾아내야 합니다. 성공/실패(pass/fail)를 판정할 수 있는 시그널(테스트 스위트, 빌드 종료 코드, 린터, 스크린샷 등)을 주면 자율 폐루프가 완성됩니다: 작업 → 검증 실행 → 결과 확인 → 통과할 때까지 자가 개선.

❌ 모호한 지시"이메일 검증 함수 만들어줘" / "빌드 깨졌는데 고쳐줘"
✅ 강력한 지시"validateEmail을 만들고 테스트 케이스(정상 이메일, 빈 문자열, 잘못된 형식)를 작성하여 구현 후 테스트를 실행해줘" / "빌드 에러 전문 첨부 [로그]. 근본 원인을 수정하고 빌드가 통과함을 증명해줘"

법칙 2: 먼저 탐색하고, 계획을 세운 뒤, 마지막에 코딩하라

복잡한 작업의 4단계: Explore(계획 모드에서 파일을 읽고 질문하며 코드는 건드리지 않음) → Plan(수정 계획 수립, Ctrl+G로 직접 편집 가능) → Implement(계획 모드를 나와 구현 착수) → Commit(커밋 메시지 작성 후 PR 생성).

법칙 3: 프롬프트는 구체적으로, 컨텍스트는 풍부하게

전략약한 프롬프트강력한 프롬프트
범위 한정"foo.py에 테스트 추가해줘""foo.py에 로그아웃 상태의 엣지 케이스를 다루는 단위 테스트를 작성해줘. mock은 사용하지 말 것"
기존 패턴 인용"새 캘린더 컴포넌트 추가해줘""홈 화면의 기존 위젯(HotDogWidget.tsx) 구현 패턴을 준수하여 캘린더 컴포넌트를 만들어줘. 외부 라이브러리 추가 금지"
원인 추적 지시"로그인 에러 고쳐줘""세션 만료 후 로그인 실패 버그 발생. src/auth/ 토큰 갱신 로직을 확인하고 실패를 재현하는 테스트를 먼저 작성한 뒤 수정해줘"

법칙 4: 잘게 방향을 틀고, 자주 컨텍스트를 비워라

  • Esc로 언제든 중단 가능. 컨텍스트가 유지된 상태에서 방향을 즉시 바로잡을 수 있습니다.
  • Esc Esc 또는 /rewind로 롤백 메뉴를 열어 코드와 대화를 되돌릴 수 있습니다.
  • 무관한 작업을 시작하기 전에는 반드시 /clear를 실행합니다. 동일한 문제로 2번 시도해서 실패했다면 더 이상 붙잡고 있지 말고 /clear 후 프롬프트를 정제하여 재시작하세요.

법칙 5: 대규모 기능 착수 전 Claude에게 먼저 인터뷰를 시켜라

나는 [기능 요약]을 개발하려 함. AskUserQuestion 도구를 사용하여 나에게 인터뷰를 진행해줘.
기술적 구현, UI/UX, 엣지 케이스, 성능 및 보안 트레이드오프에 대해 질문할 것.
사소한 질문은 피하고 내가 놓쳤을 법한 난제를 파고들어줘.
질문이 끝나면 완전한 명세서를 SPEC.md로 작성해줘.

새 프로젝트 진입 시 필수 5단계 SOP

  1. /init —— 코드베이스(빌드 시스템, 테스트 프레임워크, 컨벤션)를 분석하여 CLAUDE.md 초안을 자동 생성. 이후 /memory로 상시 고도화
  2. /permissions —— allow/ask/deny 규칙을 정의하여 npm run lint나 git diff 같은 안전한 읽기/검증 명령을 화이트리스트에 등록 (또는 /fewer-permission-prompts로 히스토리 기반 자동 생성)
  3. /mcp —— 프로젝트에 필요한 외부 도구(데이터베이스, Figma, Notion, Sentry 등)를 연결
  4. gh CLI 설치 —— Claude가 이를 통해 이슈 생성, PR 오픈, 리뷰 코멘트 조회를 자동화. 미설치 시 API 직접 호출로 전환되어 레이트 리밋에 걸리기 쉬움
  5. /statusline —— 컨텍스트 소비량을 터미널 상태 표시줄에 항상 노출 (대원칙: 남은 컨텍스트 여유분을 항상 인지할 것)
CLAUDE.md 작성 및 정리 기준 (공식 권장)각 줄에 대해 자문해 보세요: "이 줄을 지우면 Claude가 실수를 저지를까?" 실수를 하지 않는다면 과감히 삭제합니다. 작성해야 할 내용: 추론할 수 없는 독자적 빌드 명령, 표준과 다른 프로젝트 코딩 컨벤션, 테스트 실행법, 브랜치/PR 네이밍 규칙, 프로젝트 고유의 아키텍처 결정사항, 환경별 함정. 작성하지 말아야 할 내용: 코드를 읽어보면 알 수 있는 내용, 언어의 일반적 상식, 방대한 API 문서(링크로 대체), 수시로 변경되는 정보, "좋은 코드를 작성하라" 같은 당연한 훈계. 파일이 너무 길어지면 핵심 규칙이 노이즈에 묻힙니다. @path/to/file 구문으로 외부 파일을 모듈식으로 참조 가능. 배치 우선순위: ~/.claude/CLAUDE.md(글로벌) → 프로젝트 루트(팀 공통, Git 관리) → CLAUDE.local.md(개인용, Git 무시) → 하위 디렉터리(온디맨드 로드).

Skills: 온디맨드로 로드되는 전문가 지식

CLAUDE.md가 전역 공통 규칙이라면, Skills는 필요할 때만 호출되는 도메인별 매뉴얼입니다. 프로젝트의 .claude/skills/<skill-name>/SKILL.md 또는 전역의 ~/.claude/skills/<skill-name>/SKILL.md에 정의합니다.

# .claude/skills/deploy-check/SKILL.md
---
name: deploy-check
description: 프로덕션 배포 전 무중단 검증 체크리스트를 실행. 배포 준비, 릴리즈, 스테이징 검증을 요청할 때 사용.
---
## 배포 전 검증 절차
1. `npm run test:e2e` 실행 결과를 확인
2. `.env.production` 환경 변수 누락 여부 검사
3. 데이터베이스 마이그레이션 롤백 스크립트 존재 여부 확인
4. 모든 항목 통과 시 배포 확인 리포트 출력
Skills 작성 팁description은 라우팅의 핵심입니다. 모델이 언제 이 스킬을 활성화해야 하는지 명확한 트리거 조건을 기술해야 합니다. disable-model-invocation: true를 frontmatter에 추가하면 모델의 자동 판단을 차단하고 /deploy-check와 같이 사용자가 직접 슬래시 명령어로 입력했을 때만 실행되도록 제한할 수 있습니다.

Hooks: 결정론적(Deterministic) 가드레일

CLAUDE.md나 Skills의 지시는 어디까지나 **권고와 제안**입니다. 반드시 지켜져야 하는 강제 규칙은 Hook에 맡겨야 합니다. Hook은 라이프사이클 이벤트에서 셸 스크립트를 실행하며, 종료 코드(exit code) 2를 반환하여 Claude의 작업을 완전히 차단할 수 있습니다. 대표적 이벤트:

이벤트트리거 시점전형적인 용도
PreToolUse도구 실행 직전 (차단 가능).env나 비밀 키 파일에 대한 쓰기 금지, 위험한 명령어 차단
PostToolUse도구 실행 성공 직후파일 수정 후 자동으로 prettier / eslint 포맷터 실행
StopClaude가 턴을 종료하려 할 때테스트를 실행하고 실패 시 턴 종료 거부 (8회 연속 실패 시 패스)
UserPromptSubmit사용자가 프롬프트를 전송하고 처리가 시작되기 전환경 정보 자동 주입, 금지어 검사
SessionStart / SessionEnd세션 시작 / 종료 시개발 환경 초기화 / 리소스 정리 및 리포트 발송
PostToolUseFailure / PreCompact / SubagentStop / FileChanged…더 세분화된 개별 이벤트실패 알림, 압축 전 상태 저장, 파일 변경 감시 등 (30개 이상의 이벤트는 공식 참조)
// .claude/settings.json —— 파일 수정 후 자동 포맷팅 실행 예시
{
  "hooks": {
    "PostToolUse": [
      { "matcher": "Write|Edit",
        "hooks": [ { "type": "command", "command": "npx prettier --write "$FILE"" } ] }
    ]
  }
}
스마트한 Hook 생성법Hook 구현 자체도 Claude에게 맡길 수 있습니다: "파일 수정 후 매번 eslint를 실행하는 hook을 작성해줘", "migrations 디렉터리에 대한 파일 수정을 차단하는 hook을 만들어줘". 설정 내용은 /hooks로 점검할 수 있습니다.
Hook보다 안전한 기밀 보호 방법기밀 파일의 읽기 차단에는 Hook보다 권한 규칙(Permissions)이 권장됩니다: deny 규칙(예: Read(./.env), Read(./secrets/**))을 설정하면 파일이 Claude의 시야에서 완전히 사라집니다. 권한 평가 우선순위: deny → ask → allow.

서브에이전트(Subagents): 독립된 컨텍스트를 가진 분신

.claude/agents/*.md에 정의하며, 고유한 컨텍스트 윈도우, 도구 세트, 시스템 프롬프트를 가집니다. 주요 2대 용도:

  • 조사 작업의 컨텍스트 격리: "서브에이전트를 사용해서 인증 시스템이 토큰 갱신을 어떻게 처리하는지 조사해줘" —— 서브에이전트가 수십 개의 파일을 읽고 메인 대화에는 핵심 요약만 반환하여 내 메인 컨텍스트를 깨끗하게 유지합니다.
  • 선입견 없는 객관적 코드 리뷰: 직전 구현 과정의 사고 편향이 없는 깨끗한 컨텍스트에서 git diff를 검토합니다. 공식 권장 리뷰 지시: "지정된 작업 명세와 계획을 대조하고, 발견된 문제점만 보고하라. 개인적 스타일 선호는 지적하지 말 것".
# .claude/agents/security-reviewer.md
---
name: security-reviewer
description: 코드 보안 리뷰. 코드 변경 후 자율적으로 호출.
tools: Read, Grep, Glob, Bash
model: opus
---
당신은 시니어 보안 엔지니어입니다. 다음 사항을 중점 감사하십시오:
인젝션 취약점(SQL/XSS/Command Injection), 인증 및 인가 결함,
코드 내 하드코딩된 비밀 키/자격증명, 안전하지 않은 데이터 처리.
구체적인 코드 라인 번호를 인용하며 수정안을 제시하세요.
/btw와 서브에이전트 비교/btw는 대화 전체를 파악하지만 도구를 사용할 수 없습니다('이미 알고 있는 사실'을 빠르게 질의); 서브에이전트는 모든 도구를 사용할 수 있지만 빈 컨텍스트에서 출발합니다('미지의 영역'을 신규 조사). 적절히 분기하면 컨텍스트를 크게 아낄 수 있습니다.
리뷰 에이전트의 흔한 함정"문제점을 찾아내라"고만 지시받은 리뷰어는 코드에 문제가 없어도 사소한 꼬투리를 잡으려 합니다. 모든 지적을 맹목적으로 수정하면 과도한 엔지니어링(Over-engineering)에 빠집니다. 리뷰어에게는 "정확성과 요구 명세에 직결되는 중대한 결함만 보고하고, 나머지는 선택적 제안으로 분류하라"는 기준을 부여하십시오.

MCP: 외부 세계와의 연결

MCP(Model Context Protocol)를 통해 Claude Code를 데이터베이스, Figma, Slack, Sentry 등 외부 시스템과 직접 연동할 수 있습니다. MCP 설정은 settings.json에 작성하지 않는다는 점에 유의하세요 (초보자가 가장 많이 실수하는 부분입니다).

추가 및 관리

# 로컬 stdio 서버 추가
claude mcp add my-tool -- npx -y some-mcp-server

# 원격 HTTP 서버 추가
claude mcp add --transport http api-tool https://example.com/mcp

# OAuth 인증이 필요한 서버 개별 로그인
claude mcp login api-tool

# 세션 내부: /mcp로 상태 확인, 인증, 서버 활성화/비활성화

3대 스코프 (--scope)

스코프저장 위치적용 범위
local (기본값)~/.claude.json 내 해당 프로젝트 항목나 개인, 해당 프로젝트에만 적용
project프로젝트 루트 .mcp.json (Git 관리)팀 공통 —— 프로젝트 필수 협업 도구 정의

운영 3대 원칙

  • 도구 정의도 컨텍스트를 소모한다: MCP 서버를 추가할 때마다 각 도구의 스키마가 컨텍스트 윈도우를 차지합니다 —— /context로 소비량을 확인하고, 사용하지 않는 서버는 /mcp에서 비활성화하세요.
  • MCP 반환값은 신뢰할 수 없는 입력으로 취급한다: 외부 도구가 반환하는 텍스트에 프롬프트 인젝션이 포함될 수 있으므로, 검증된 서버만 연결하십시오.
  • JSON을 직접 수정하지 말고 명령어를 사용한다: claude mcp add를 통해 등록해야 올바른 포맷이 보장됩니다. 수동 편집 시 발생하는 JSON 손상은 'MCP 인식 불가' 원인의 1위입니다.

🧭 1. Claude 2계층 레이트 리밋과 컴퓨팅 산정의 기본 메커니즘

타 플랫폼과 달리 Claude의 쿼터 제어 로직은 극도로 "컨텍스트 민감성"이 높은 구조를 지닙니다:

과금 및 제한 메커니즘 내부 동작 원리 전형적인 함정 유발 요인 대응 및 함정 회피 수칙
5시간 단기 롤링 윈도우 (Burst Limit) 직전 5시간 동안의 순간 동시 실행 수와 토큰 처리량을 모니터링. 시간 경과에 따라 윈도우가 완만하게 회복. 동일한 대화창에서 30턴 이상 장시간 대화를 지속하거나, 터미널 실행 시 방대한 프로젝트 코드 전체를 한 번에 마운트. 대화 턴 수를 제한하고 작은 마일스톤 단위로 새 세션을 개설. 터미널에는 현재 작업과 직결된 모듈만 마운트.
주간 지속 사용 상한 (Sustained Cap) 헤비 유저를 위한 글로벌 안전망으로, 스크립트에 의해 계정이 24시간 무중단 자동 호출되는 상황을 방지. 무인 자동화 크롤러나 무한 루프에 가까운 대규모 자동 코드 리팩터링 에이전트를 장시간 구동. 중요 자동화 태스크에 반드시 최대 스텝 수 상한을 설정. 하루 2~3회 집중 스프린트 등 개발 리듬을 합리적으로 배분.
장대 컨텍스트의 복리 페널티 새 지시를 보낼 때마다 모델은 대화 이력의 모든 과거 질문, 시스템 프롬프트, 코드 출력을 처음부터 다시 읽음. 1번째 턴의 질문은 1K 토큰만 소모하지만, 40번째 턴에서는 단 1회 질문에 80K 토큰 이상을 보이지 않게 소모! '마이크로 태스크(Micro-Tasks)' 습관을 형성하여, 단일 세션당 4~6회의 고밀도 상호작용 후 과감히 보관/종료.
Prompt Caching (네이티브 캐시) 요청의 접두사(Prefix)가 시스템 캐시와 완벽히 일치할 때, 해당 접두사 읽기는 최대 90% 할인 및 지연 시간 제로를 향유. 정적 문서 앞단에 동적 타임스탬프나 무작위 세션 ID를 삽입하여 캐시 접두사를 전면 무효화. 불변의 팀 컨벤션과 인터페이스 정의를 항상 최상단에 고정하여 문자열을 완벽 일치시키고 캐시 혜택을 극대화.

🚀 2. 4대 가치 기둥: 초장기 지속 가능한 Claude 개발 루프 구축

Pro 회원의 잠재력을 온전히 이끌어내려면 다음 4가지 연계 도구 조합을 통달해야 합니다:

기둥 1: Projects (프로젝트 작업 공간) 구조화 영속 지식 베이스

Claude 웹 버전에서 Projects는 가장 효율적인 자산 축적 센터입니다:

  • 한 번 업로드로 전원 캐시 공유: 팀의 《코드 스타일 가이드》, 《전체 DB 스키마》, 《핵심 API 명세》를 Project Knowledge에 통합 업로드. Anthropic 백엔드에서 자동으로 글로벌 캐시를 구축하므로, 프로젝트 내 생성되는 수십 개의 대화창이 극소량의 비용으로 방대한 기억을 즉시 공유합니다.
  • 권장 파일 포맷: 잘 구조화된 Markdown(.md)과 TypeScript 인터페이스(.d.ts) 파일은 복잡한 서식의 PDF나 Word 문서보다 파싱 효율과 검색 정확도가 현저히 뛰어납니다.

기둥 2: Artifacts 대화형 샌드박스 (프론트엔드 및 프로토타입의 무손실 실험장)

웹 버전의 Artifacts (우측 미리보기 패널)는 UI 개발과 데이터 시각화의 강력한 무기입니다:

기둥 3: Claude Code CLI 터미널 엔지니어링 군율

로컬 환경에서 Claude Code 명령줄 에이전트를 운용할 때는 다음 엔지니어링 표준을 철저히 준수합니다:

  • `CLAUDE.md` 경량화 유지 (80줄 이내 권장): `CLAUDE.md`는 Claude Code 세션 시작 시 매번 로드되는 행동 지침입니다. 수천 줄의 매뉴얼을 채워 넣으면 매 엔터마다 입력 토큰을 낭비합니다. 3요소 원칙:
    • WHAT: 현재 프로젝트의 기술 스택 및 핵심 모듈의 역할 요약.
    • WHY: 주요 설계 결정의 근거 (예: "lockfile 무결성 검증을 위해 npm 대신 pnpm 사용").
    • HOW: 표준 빌드 명령, 테스트 명령 및 린트 검사 규칙.
  • 부정형 나열 대신 '긍정형 유도' 권장: 수십 개의 "~하지 마라" 대신 "함수형 컴포넌트와 Tailwind 클래스를 우선 사용할 것"과 같은 긍정형 지시문을 작성합니다.
  • Plan-Inspect-Edit (계획-검토-실행) 루프: 복잡한 작업 전에는 즉시 파일을 수정하지 못하도록 강제합니다: "파일을 바로 수정하지 말고, 진행할 3가지 핵심 단계와 대상 파일 목록을 먼저 출력해줘". 계획을 확인한 뒤 실행을 승인합니다.

패러다임 1: 픽셀 정밀도 UI/디자인 시안 역공학 (Screenshot-to-Clean-Code)

디자이너나 기획자로부터 복잡한 Figma 프로토타입이나 경쟁사 스크린샷을 전달받았을 때 맨땅에서 마크업을 짜려면 수 시간이 소요됩니다.
실전 권장 SOP:

  1. 고해상도 스크린샷 업로드: Claude 웹 버전에 스크린샷을 붙여넣고 구조화된 프롬프트를 전달합니다:
    픽셀 단위 UI 역공학 Prompt 수석 프론트엔드 아키텍트로서 첨부된 화면 스크린샷을 픽셀 단위로 복각해줘: 1. 기술 스택: React 19 + Tailwind CSS + Lucide Icons; 2. 엄격한 정렬: 여백(Padding/Margin), 모서리 곡률(rounded-xl/2xl), 폰트 위계, 글래스모피즘 그림자 완벽 재현; 3. 반응형 및 컴포넌트화: 주요 리스트 아이템, 상태 배지, 카드를 독립된 재사용 가능 하위 컴포넌트로 추상화; 4. Artifacts 패널에서 완전한 대화형 인터랙션이 직접 동작하도록 보장할 것이며, 더미 플레이스홀더 사용 금지.
  2. Artifacts 상에서 즉시 인터랙티브 검증: 우측 패널에 동작하는 웹 인터페이스가 즉시 렌더링되며, 버튼 호버/클릭 상태, 다크 테마 적합성을 직접 테스트할 수 있습니다.

패러다임 2: 코드 네이티브 벡터 에셋 파이프라인 (Code-Native SVG & Canvas)

복잡한 시스템 토폴로지 다이어그램이나 세련된 테마 일러스트가 필요할 때 저작권이 불분명한 외부 이미지를 찾을 필요가 없습니다:

  • 복잡한 시스템 아키텍처 다이어그램: 애니메이션 점선(stroke-dasharray 효과)을 포함한 인터랙티브 SVG 토폴로지를 Claude에게 직접 코드로 작성시켜 문서나 모니터링 대시보드에 즉시 임베드.
  • 데이터 시각화 마이크로 컴포넌트: 무거운 서드파티 차트 라이브러리 없이도 HTML5 Canvas나 SVG를 활용하여 경량 꺾은선 차트나 레이더 차트를 다이렉트로 코딩.

패러다임 3: 자동 시각적 회귀 및 레이아웃 검증 (Headless Visual QA)

로컬 터미널에서 Claude Code와 Playwright를 연동하여 E2E 테스트를 실행하고, 캡처된 스크린샷을 비주얼 기능으로 전달해 Claude가 자신의 코드 렌더링 결과를 스스로 검증하게 합니다:

자동 레이아웃 정합성 검증 Prompt 【입력: 디자인 원본 시안 vs 로컬 Playwright 캡처 화면】 두 화면의 레이아웃 차이를 정밀 비교해줘: 1. 모바일 브레이크포인트에서의 줄바꿈 동작; 2. 다국어 확장 시 텍스트 오버플로 여부; 3. 버튼 클릭 영역 대비비가 WCAG AA 기준을 충족하는지 검토. 수정을 위한 CSS 패치 코드를 출력할 것.

🎨 3. 프롬프트 엔지니어링 및 벡터 비주얼 조율 수칙

Claude로부터 군더더기 없는 고품질 비주얼 코드를 도출하기 위한 핵심 원칙:

  • `viewBox`와 반응형 컨테이너 명시: 프롬프트에 "Ensure SVG root uses responsive viewBox='0 0 800 600' with preserveAspectRatio='xMidYMid meet', and width='100%' for fluid scaling"을 명시하여 모바일 환경에서의 화면 잘림을 원천 차단.
  • 시맨틱 컬러 팔레트 바인딩: CSS 변수(fill="currentColor" 또는 var(--primary-color))와 결합하도록 지시하여 시스템의 다크/라이트 테마 전환에 자동 대응.
  • 그라데이션 및 필터 ID 명명 규칙: <defs> 내의 그라데이션 ID에 고유한 접두사를 사용하도록 지시하여 대규모 페이지에서의 ID 중복 충돌을 방지.

🤖 4. Computer Use (데스크톱 및 브라우저 자율 제어) 실전 가이드

Shift+Tab으로 모드를 순차 전환할 수 있습니다. CLI 실행 시에는 --permission-mode로 지정합니다.

3단계 평가 우선순위: deny → ask → allow

// .claude/settings.json —— 실전 초기 권한 설정 예시
{
  "permissions": {
    "allow": [
      "Read", "Glob", "Grep",
      "Bash(npm run lint:*)", "Bash(npm run test:*)",
      "Bash(git status)", "Bash(git diff:*)"
    ],
    "ask":  [ "Bash(git push:*)" ],
    "deny": [
      "Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)"
    ]
  }
}
  • deny가 최우선으로 평가됨: 기밀 파일은 deny에 지정하면 Claude의 시야에서 완전히 은닉됩니다 (Hook으로 차단하는 것보다 근본적으로 안전).
  • 승인 피로(Approval fatigue)는 보안의 최대 적입니다: 10번째 '승인'을 클릭할 때쯤이면 사용자는 내용을 읽지 않습니다. 해결책은 정밀한 화이트리스트 설정(/fewer-permission-prompts로 자동 생성 가능)과 /sandbox를 통한 OS 수준 격리입니다.
  • --dangerously-skip-permissions는 **네트워크가 단절되고 기밀 데이터가 전무한 컨테이너 환경**(CI 내 린트 수정 등)에서만 사용해야 합니다. 기업 환경에서는 disableBypassPermissionsMode로 조직 전체에서 전면 비활성화할 수 있습니다.

3. 우선순위 및 "설정이 반영되지 않을 때" 체크리스트

설정 키가 충돌할 때의 우선순위: 기업 관리 설정 > 명령줄 인수 > .claude/settings.local.json > .claude/settings.json > ~/.claude/settings.json. "수정했는데 반영되지 않는" 전형적인 3대 원인:

  • 편집한 레이어가 상위 레이어에 의해 덮어씌워짐: 프로젝트 설정이 전역 사용자 설정을 오버라이드하고 있는 경우 → /config로 현재 유효한 최종 값을 확인하거나 --setting-sources user로 특정 레이어만 단독 로드하여 확인;
  • 세션 재시작이 필요한 항목인 경우: 대다수 설정은 핫 리로드되지만, model이나 outputStyle 등은 세션 시작 시에만 로드됨 —— 변경 후 세션을 재시작 (임시 모델 변경은 /model 사용);
  • JSON 문법 오류: claude doctor(터미널 진단) 또는 /doctor(세션 내부)로 스키마 에러를 확인; settings.json 상단에 "$schema": "https://json.schemastore.org/claude-code-settings.json"을 명시하면 에디터에서 자동 유효성 검증 제공. 커스텀 설정 문제로 의심될 때는 claude --safe-mode로 순정 상태로 실행하여 원인을 분리.

5. 코드명 플래그 분석 존재 확인·동작 미검증

바이너리 내부에는 CLAUDE_CODE_BASALT_COVE, MARL_CORMORANT, GAULT_KESTREL, NANKEEN_KESTREL, LANTERN_PRISM, PEWTER_OWL, THISTLE_GREBE, WALNUT_SPIRE와 같은 무작위 영단어 조합의 환경 변수들이 확인됩니다. 이는 개발사에서 원격 단계적 배포(Feature flags)를 제어하기 위한 내부 플래그이며, 의도적으로 의미를 알 수 없도록 명명되어 있습니다.
