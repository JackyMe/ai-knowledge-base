コア基盤 01

1️⃣ Antigravity の基本概念とメンタルモデル

公式仕様準拠 Google Antigravity（コードネーム AGY）は、Google が Agentic AI ソフトウェアエンジニアリング時代のために構築した新世代フルスタック基盤です。単なるチャット形式のコード補完にとどまらず、OS レベルのサンドボックス、マルチエージェント協調オーケストレーション、MCP (Modular Command Protocol) プロトコル、AST コードレベルの意味論的理解、コンテキストライフサイクル管理を高度に統合しています。

Antigravity を支える 6 大コア基盤概念

  • agy CLI：ワークスペース診断、コード検索、変更提案、サブエージェントディスパッチを統括する統一コマンドラインインターフェース。
  • Agentic IDE：コードエディタ、Planning Mode 計画レビューパネル、リアルタイム Diff チェッカー、Artifacts ビジュアルプレビューをシームレスに統合した GUI ワークベンチ。
  • Customizations カスタマイズ体系：.agents/ またはユーザーグローバル ~/.gemini/antigravity/ に配置する階層型拡張センター。Skills（スキル機能）、Rules（実行ルール）、Plugins（プラグイン）、MCP サーバーで構成。
  • Subagents エージェントネットワーク：独立した Conversation ID、コンテキスト状態機械、ワークスペースモードを備えた自律型バックグラウンドエージェント。親子エージェント間の協調通信をサポート。
  • Artifacts 成果物メカニズム：複雑なアーキテクチャ設計、Mermaid 図、UI プロトタイプ、移行計画を標準化された Markdown として永続化し、チャットログの肥大化・埋没を防止。
  • Reactive Wakeup（リアクティブ起床）：完全非同期タスクアーキテクチャ。親エージェントがバックグラウンドタスクやスケジュールを発行した後はポーリング待機が不要で、完了時やメッセージ受信時に自動で再起動・通知。

Antigravity Agentic IDE ショートカット一覧

  • Cmd+L / Ctrl+L —— 右側の Agent チャットパネルにフォーカスし、現在選択中のコード行とファイルアンカーを自動でプロンプトコンテキストに注入。
  • Cmd+Shift+P —— Antigravity コマンドパレットを開き、/goal, /schedule, /grill-me などの高度なワークフローを迅速に実行。
  • Ctrl+Alt+R —— サンドボックス内で現在のアクティブファイルまたは関連テストスイートをサイレント自己検証し、実行結果を出力。
  • Ctrl+Alt+S —— 現在のセッションで生成された Markdown / HTML / UI Artifacts をスプリットスクリーンでリアルタイムプレビュー。

4️⃣ Customizations カスタマイズ体系：Skills · Rules · MCP · Plugins

Antigravity は 3 段階の優先順位による設定探索システムを採用しています：プロジェクトローカル .agents/（最優先） > ユーザーグローバル ~/.gemini/antigravity/ > 組み込み仕様 (Built-in)。すべてのルールはホットリロード（Hot-reload）に対応し、再起動なしで即座に反映されます。

4.1 本番向け Skill の作成例（セキュリティ監査 Skill）

.agents/skills/security-guard/SKILL.md で能力ルールを定義：

---
name: security-guard
description: "本番レベルの機密情報漏洩および SQL インジェクション静的セキュリティ監査スキャナー"
---
# コアセキュリティ監査ガイドライン
1. ソースコード内に API Key、JWT Secret、内部 DB パスワード等を直接ハードコードすることを固く禁止する。
2. 外部に公開されるすべての API リクエストパラメータは、厳格なスキーマ検証とデシリアライズ制約を通過させること。
3. すべてのデータベースクエリを検査し、パラメータ化されたプリペアドステートメントの使用を強制し、文字列直接連結による SQL 構築を排除する。
4. 外部 HTTP リクエストには、タイムアウト制限 (Timeout) と指数バックオフによるリトライ (Exponential Backoff) の設定を必須とする。

4.2 グローバルインターセプトルール (Rules) の記述例

# .agents/rules/safe-terminal.yml
---
severity: critical
description: "サンドボックス防御：未承認の機密ファイル外部送信および危険なターミナルコマンドの傍受"
enforce:
  - tool: run_command
    condition: "BypassSandbox == false && CommandLine matches '(rm\\s+-rf\\s+/|mkfs|dd\\s+if=)' => reject"
  - tool: replace_file_content
    condition: "TargetFile matches '\\.(env|pem|key)$' => require_user_approval"

7️⃣ パフォーマンス・コスト最適化とサンドボックス防御体系

  1. 標準サンドボックス優先（Standard Sandbox First）：すべてのターミナルコマンドはデフォルトで外部ネット接続なし・ファイルアクセス制限のある標準サンドボックス内で実行されます。パッケージのダウンロードや外部通信が不可欠な場合にのみ、明示的に BypassSandbox: true を宣言してユーザー承認を求めます。
  2. Planning Mode の規律徹底：複数ファイルにまたがるアーキテクチャ変更や大規模リファクタリングでは、まず implementation_plan.md 設計ドキュメントを生成し、ユーザー確認事項と自己検証手順を明記します。ユーザー承認を得る前のソースコード変更は厳禁です。
  3. 差分ピンポイント編集（Incremental Edits）：数千行におよぶ大規模ファイルでの全量上書きを固く排し、replace_file_content によるピンポイント置換を徹底することで、コンテキスト Token を大幅に節約し Git 履歴の明瞭性を保ちます。

9️⃣ プロダクション実践ケース：サービスリファクタリングと並行テスト

要件定義、サブエージェントによる調査、計画策定から、コードの段階的修正、サンドボックス自動検証までの一連のクローズドループ：

# ステップ 1：読み取り専用 research サブエージェントをディスパッチしてコードベースの構造を分析
agy subagent invoke research --prompt "src/auth/ モジュール内の従来の Session 処理のボトルネックを分析し、依存関係を整理"

# ステップ 2：構造化された implementation_plan.md 成果物を作成し、ユーザー承認を待機
agy write_to_file --TargetFile .gemini/antigravity/brain/implementation_plan.md \
  --CodeContent "# OAuth2 + PKCE リファクタリング実施計画..."

# ステップ 3：ユーザー承認後、アトミック編集ツールを用いてコードを段階的にリファクタリング
agy edit src/auth/oauth2.py --range 15-60

# ステップ 4：標準隔離サンドボックス内で単体テストとリグレッションテストスイートを実行
agy run "pytest tests/test_oauth2.py -v" --wait 5000

🔟 常用クイックリファレンスと Slash コマンドハンドブック

  • /goal —— 長時間実行や完全自律型の複雑タスク用。目標が完全に達成されるまでエージェントがあらゆる手段を尽くして自律遂行。
  • /schedule —— 定期実行タスクやタイマーの設定インターフェースを素早く起動。
  • /browser —— 組み込みヘッドレスブラウザツールを起動し、動的レンダリングページのスクレイピングや Web UI の自動回帰テストを実行。
  • /grill-me —— 詳細インタビューモードを開始し、エージェントがアーキテクチャ設計やエッジケースについて能動的に深掘り質問。
  • /teamwork-preview —— 複数自律エージェントチームを編成・プレビューし、大規模プロジェクトを並行分担で処理。
  • /learn —— セッション中の修正教訓やワークフローパターンを抽出し、ワークスペースの恒久メモリとして永続化。
