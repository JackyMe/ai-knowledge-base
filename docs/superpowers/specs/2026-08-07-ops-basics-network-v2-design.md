## 4. 表达风格守则(7 条硬约束)

### 4.1 类比升级(替代旧版"信封/快递"老套比喻)

| 概念 | 类比 |
|---|---|
| 端口号 | 小区门牌号,6 万多户,知名端口 = 著名商户,临时端口 = 临时租户 |
| loopback | "你跟自己说话",家里喊一声全家人都听不见 |
| DNS | 通讯录/电话簿,114 查号台 |
| HTTPS | 挂号信,只有收件人能拆 |
| 反向代理 | 大楼前台,你只管说"找张三",前台帮你定位 |
| VPN | 公司给你拉了根专线,从你电脑直通内网,OS 以为坐在公司工位 |
| NAT | 小区传达室替你收快递 —— 快递单只写"传达室",传达室记住每件是 18 楼哪户的 |
| TCP 三次握手 | 打电话确认:你响铃→对方接听→你说话(都得先确认"能听到") |
| 公网 vs 私网 IP | 公网 IP 是你家门牌号(全国唯一),私网 IP 是小区内单元号(传达室才知道) |

## 6. 13 节内容要点

### 2.1 一张图看懂 HTTP → TCP → IP → 网卡(原 2.1 加深,~120 行)
- **30 秒结论**:你点开网址的 1 秒里,你的请求过了 4 道关,经历 4 层"信封"包装
- **它到底是个啥**:打开浏览器输网址 → 4 层协议依次包装 → 网卡发出去
- **四层生活类比**:
  - HTTP:你要的文件名
  - TCP:快递公司,保证按顺序送到
  - IP:快递单上的地址
  - 网卡:实际跑的车
- **ASCII 协议栈图**(请求下行 + 回程上行)
- **真实可看**:`curl -v https://example.com` 完整四步握手挥手
- **实战**:`tcpdump -i any port 80` 抓包 1 行
- **记忆口诀**:"H 写啥,T 怎么送,I 给地址,网卡跑腿"

### 2.2 DNS 完整图景(原 2.2 加深,~140 行)
- **30 秒结论**:DNS 就是"互联网通讯录",114 查号台
- **它到底是个啥**:输入 aidoc-zq.netlify.app → 电脑问"这 IP 是多少" → DNS 服务器层层查 → 返回 IP
- **ASCII 递归/迭代查询图**
- **公共 DNS 列表(2026.8 核对)**:8.8.8.8 / 1.1.1.1 / 114.114.114.114 / 119.29.29.29 / 223.5.5.5

- **小剧场**:"改了 DNS 半天不生效"

- **小剧场**:"证书过期全站打不开"

### 2.4 反向代理(原 2.4 加深,~130 行)
- **30 秒结论**:反向代理是大楼前台,你只管说"找张三",前台帮你定位
- **正/反向代理对比 ASCII 图**:
  - 正向代理:替客户端出头(企业翻墙)
  - 反向代理:替服务端接活(Nginx)
- **请求流转步骤 ASCII 图**(用户 → Nginx → Node1/Node2/Node3)
- **5 个作用**:HTTPS 终结 / 多应用共用 80-443 / 静态加速 / 负载均衡 / 缓存压缩

### 2.5 防火墙与端口(原 2.5 加深,~140 行)

- **小剧场**:"80 通了但 3000 不通"

### 2.6 常见攻击面速查(原 2.6 保留速查形态,小幅加深,~110 行)

### 2.7 端口号详解(新增,~140 行)
- **30 秒结论**:端口号是小区门牌号,0-65535 共 6 万多户
- **它到底是个啥**:IP 是小区地址,端口号是门牌号
- **三段划分**:IANA 知名(0-1023)/ 注册(1024-49151)/ 临时(49152-65535)
- **15+ 端口速查表**:22 SSH / 80 HTTP / 443 HTTPS / 3306 MySQL / 5432 PG / 6379 Redis / 8080 备用 HTTP / 27017 Mongo / 53 DNS / 25 SMTP / 110 POP3 / 143 IMAP / 3389 RDP / 5900 VNC / 11211 Memcached
- **端口冲突排查四步法**:`ss -tlnp` / `lsof -i :端口` / `netstat -anp` / `fuser -k 端口/tcp`
- **小剧场**:"两个 Node 都想用 3000"
- **记忆口诀**:"知名 1024 下,注册中段,临时靠后"

### 2.8 本地服务与 loopback(新增,~130 行)
- **30 秒结论**:`localhost` 是"你跟自己说话",家里喊一声全家都听不见
- **三地址区别 ASCII 图**:
  - `127.0.0.1` = loopback 网卡上的 IP(只走本机)
  - `localhost` = 操作系统解析出来的名字(通常 = 127.0.0.1)
  - `0.0.0.0` = 监听所有网卡(接受所有接口的访问)
- **Node 监听实例**:`app.listen(3000, '127.0.0.1')` vs `'0.0.0.0'`
- **内网穿透 3 方案**(独立开发者最常需要):frp / Cloudflare Tunnel / Tailscale
  - frp:开源、自建、需要一台公网机器
  - Cloudflare Tunnel:免费,2026.8 状态(核对)
  - Tailscale:基于 WireGuard,零配置
- **端口转发 ASCII 图**:
  - `ssh -L 8080:remote:80`(本地访问 remote 的 80)
  - `ssh -R 8080:localhost:3000`(把本机暴露到 remote)
- **小剧场**:"我本地跑的服务怎么让同事访问?"
- **记忆口诀**:"本地起服务先看听啥,听 0.0.0.0 才对外"

### 2.9 VPN 与代理 4 种类辨析(新增,~160 行)
- **30 秒结论**:VPN、正向代理、反向代理、应用层代理四者经常被搞混,实际上各管一层
- **它到底是个啥**:用场景引入
  - 公司 VPN:在家能访问公司内网 Git
  - 企业正向代理:公司统一出口上网
  - 反向代理:用户访问公司网站
  - 应用代理:某浏览器插件走 SOCKS5
- **四者对比 ASCII 拓扑图**(四个三角形,标注作用层)
- **作用层一览**:
  - VPN:L3 网络层(整条虚拟专线)
  - 反向代理:L7 应用层(Nginx 替你接 HTTP)
  - 正向代理:L7 应用层(浏览器设代理出公网)
  - 应用层代理(SOCKS5/HTTP Proxy):L7 应用层,看具体协议
- **VPN 协议三档**:
  - IPsec:企业级,1980s 老牌
  - SSL VPN(AnyConnect):轻量,装客户端
  - WireGuard:新锐,代码 4000 行,Linux 5.6 起入主线
- **`ssh -D 1080` 是什么**:动态 SOCKS 代理,SSH 自带
- **小剧场**:"公司 VPN 能访问内网是为什么"(路由表视角)
- **记忆口诀**:"VPN 拉专线,反代替服务端,正代替客户端"

### 2.10 公网 / 私网 / NAT(新增,~140 行)
- **30 秒结论**:公网 IP 是你家门牌号,私网 IP 是小区单元号,小区传达室记住每件快递是 18 楼哪户的
- **三类私网段(RFC 1918)**:
  - `10.0.0.0/8`(1677 万地址)
  - `172.16.0.0/12`(104 万地址)
  - `192.168.0.0/16`(6.5 万地址)
- **NAT 原理 ASCII 图**:
  - 内网 192.168.1.100:5000 → 公网 1.2.3.4:40001 → 目标网站
  - 回来时传达室按端口号分发回 5000
- **端口映射 = 路由器的"反向代理"**
- **IPv4 耗尽历史**(2019.11 IANA 分配完最后 5 个 /8 段)+ NAT 续命
- **IPv6 不需要 NAT**(每台设备公网 IP)
- **小剧场**:"为什么我家 IP 跟邻居一样都是 192.168.1.100"
- **记忆口诀**:"公网全国唯一,私网小区内用,出门靠 NAT"

### 2.11 网络调试命令全家福(新增,~150 行)
- **30 秒结论**:这是你排障的工具箱,按场景查
- **命令分类速查表**:
  - 连通性:`ping` / `traceroute` / `mtr`
  - DNS:`nslookup` / `dig` / `host`
  - HTTP:`curl -v` / `wget -S` / `httpie`
  - 本地端口:`ss` / `netstat` / `lsof -i`
  - 抓包:`tcpdump` / `Wireshark`(简提)
  - 网络配置:`ip addr` / `ip route` / `ip link`
- **5 个实战排查场景**(每个 5-10 行):
  1. 上不了网 → ping 8.8.8.8(测 IP 层)→ ping baidu.com(测 DNS)
  2. 上得了网但打不开网页 → `curl -v http://...` 看具体卡哪
  3. 网页打开慢 → `mtr` 看路由哪一跳卡
  4. SSH 连不上 → `telnet 22` / `ssh -vvv` / `ufw status`
  5. API 调不通 → `curl -X POST -d @body -H 'Content-Type: ...'`
- **`ss` vs `netstat`**:新派 vs 老派,功能差不多,`ss` 快
- **记忆口诀**:"不通先 ping,慢就 mtr,HTTP 用 curl"

### 2.12 HTTP/2 与 HTTP/3 演进(新增,~120 行)
- **30 秒结论**:HTTP/2 解决"一个 TCP 连接一个请求"的浪费,HTTP/3 进一步用 QUIC 干掉 TCP 队头阻塞
- **HTTP/1.1 痛点**:浏览器同域最多 6 个 TCP 连接,队头阻塞
- **HTTP/2 三大招 ASCII 对比**:
  - 多路复用(一个 TCP 连接并发多个请求)
  - 头部压缩 HPACK
  - 二进制分帧
- **HTTP/3 革命**:基于 QUIC(UDP 之上的"TCP-like")
  - 解决 TCP 队头阻塞
  - 0-RTT 握手(第二次连接几乎瞬开)
  - 内置加密
- **2026.8 部署现状**(核对 Cloudflare / 国内 CDN 支持矩阵)
- **"为什么我还在用 HTTP/1.1 也行"**:性能足够时不用追新
- **记忆口诀**:"H2 多路复用,H3 干掉 TCP"

### 2.13 IPv6 扫盲(新增,~110 行)
- **30 秒结论**:128 位地址够给地球每粒沙子一个 IP,2026 年还没普及但你应该知道它是什么
- **它到底是个啥**:为什么 IPv4 不够 + IPv6 怎么解决
- **地址格式**:`2001:0db8:85a3::8a2e:0370:7334`,冒号分 8 段
- **三大优势**:海量地址 / 端到端可达(无 NAT) / 内置 IPsec
- **2026.8 部署现状**(核对 Google IPv6 Statistics / APNIC)
  - 全球部署率 X%(2026-07 数据,核对 2026-08-XX)
  - 国内三大运营商支持现状
- **要不要上**:看目标用户(出口流量可能仍走 v4)
- **启用检测**:`test-ipv6.com` / `curl -6 ifconfig.co`
- **记忆口诀**:"IPv4 32 位不够分,IPv6 128 位随便用"
