## 1. 目标与边界

### 1.1 一句话目标
让一位**只用过 Vercel/Netlify/Cloudflare Pages 等 SaaS 托管**的独立开发者,通过这一页内容,能在不依赖他人的情况下,自己负责一个中小项目的服务器 / 部署 / 网络三件套。

### 1.2 明确**不**覆盖
- 企业级 k8s 运维 / GitOps / Service Mesh —— 与"独立开发者"场景严重不匹配
- 性能调优到极致(epoll、内核参数、网络栈调优)—— 学习曲线长、收益低
- 监控告警体系(Prometheus / Grafana 全家桶)—— 单开主题
- AI/ML 模型部署、GPU 调度 —— 不同心智模型,单开主题
- 桌面/移动端运维 —— 与全栈业余项目正交

### 1.3 读者画像
- 写代码的独立开发者,做过 Next.js/Node/Python 全栈项目
- 只用过 Vercel/Netlify/Cloudflare Pages/Supabase 等 SaaS 托管
- 被"上线后出了问题只能到处求人"困扰
- 想跨过 DevOps 这堵墙,但不打算成为 SRE

### 1.4 成功标准
读者读完并完成路线图里至少 3 个动手项目后,能:
- SSH 到一台陌生 VPS,30 秒内定位"服务挂了"
- 自己申请域名、配置 DNS、签 SSL、跑通 HTTPS
- 用 systemd + 反代把 Node 服务稳定托管
- 用 GitHub Actions 把 `git push` 接上自动部署
- 故障时能查附录 A 的"30 秒对症表"自助止血

## 2. 内容骨架(17 节)

```
# 导读:为什么这份内容存在(替代上 SaaS 托管的"升级路线")
# 路线图:5 个阶段 + 配套动手项目(从 0 到独立部署一个 Node 服务)
├─ 阶段 0 · 现状盘点(你目前在用 SaaS 托管的"隐藏代价")
├─ 阶段 1 · Linux 基座(买 VPS → SSH → 看懂进程)
├─ 阶段 2 · 网络骨干(域名 → DNS → HTTPS → 反向代理)
├─ 阶段 3 · 部署链路(CI/CD + 进程托管 + 日志)
└─ 阶段 4 · 故障排查(常见 5 类故障 + 30 秒对症)

模块 1 · Linux 与服务器基座(5 节)
├─ 1.1  什么是"服务器"(从你的笔记本到云上,发生了什么变化)
├─ 1.2  三大抽级概念:文件系统 / 进程 / 端口
├─ 1.3  SSH 不只是"远程登录":密钥、隧道、跳板
├─ 1.4  包管理器速查(apt/yum/dnf/apk 一图看懂)
└─ 1.5  权限与用户(sudo / 文件 777 / chmod vs chown)

模块 2 · 网络与安全骨干(6 节)
├─ 2.1  一张图看懂 HTTP→TCP→IP→网卡
├─ 2.2  DNS:为什么 ping 不通但 nslookup 行
├─ 2.3  HTTPS / TLS / Let's Encrypt 30 秒讲完
├─ 2.4  反向代理是什么(Nginx 为什么是瑞士军刀)
├─ 2.5  防火墙与端口:为什么 80/443 通了别的还连不上
└─ 2.6  常见攻击面速查(SQL 注入 / XSS / 暴力 SSH / 漏洞未修)

模块 3 · 部署链路(实用为主)(6 节)
├─ 3.1  部署 7 步流水线(从 git push 到线上)
├─ 3.2  systemd 进程托管:让 Node 不再"关 SSH 就挂"
├─ 3.3  Nginx 反代实战配置模板
├─ 3.4  Docker 最小必要集(为什么你不用现在就上 k8s)
├─ 3.5  GitHub Actions 自动部署范例
└─ 3.6  环境变量 / 密钥管理 / .env 的正确打开方式

# 附录
├─ A  5 类故障 30 秒对症表(类比 env-auth-clinic 的急救手册)
├─ B  推荐资源(官方文档 + 经典书 + 实战社区,带分级标签)
└─ C  概念速查表(术语对照)
```
