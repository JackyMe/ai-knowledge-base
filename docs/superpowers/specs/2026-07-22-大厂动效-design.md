# 全站「大厂风格」动效设计规格

日期:2026-07-22
范围:`index.html`(首页)+ `topics/*.html`(9 个主题页),不含搜索/命令面板

## 1. 背景与目标

现状:全站仅有零散的 `transition:.15s~.2s` 悬停反馈,唯一的 `@keyframes` 是主题页切换章节时用的 `pgIn`(`assets/css/site.css:49`)。没有统一的动效语言,也没有"内容浮现"这类入场动效。

目标:引入一套克制、统一的"苹果式呼吸感"动效体系——舒展的入场浮现 + 柔和的交互反馈,让首页与主题页在视觉/交互上呈现"大厂产品"的精致统一感,同时严格控制强度(轻量,不喧宾夺主)。

**非目标(明确不做)**:
- 不引入任何动画库/依赖,纯原生 CSS + 一段极简 `IntersectionObserver`
- 不改变现有的分页切换机制(`pg-anim`/`showPage`),只是与之协调共存,不替换
- 不触碰搜索框、搜索结果列表、`⌘K` 命令面板、侧边栏筛选——这些是功能性/信息密度高的组件,动效应服务内容区,不服务工具区
- 不做弹性回弹(bounce/spring)一类动效,那是 Stripe 风格的标志,和"呼吸感"的克制基调相反

## 2. 关键架构事实(影响设计)

排查代码后发现一个直接影响设计的事实:主题页并不是传统的整页长滚动。`assets/js/site.js` 头部注释写明这是 "v2(分页模式):左侧目录 = Tab,点击切换章节页,不再整页长滚动"——每个顶层 `<section id>` 是独立一"页",同一时间只显示当前页,`showPage()` 切换时整页容器已经用现有的 `pg-anim`(`.28s ease`,透明度 + 10px 位移)做过一次入场动画。

这意味着:如果给每个 `<section>` 的 `<h2>` 标题再单独挂一层滚动浮现动画,会和容器级的 `pg-anim` **在同一时刻叠加**(章节标题通常是切换后第一眼看到的内容,几乎立即触发 `IntersectionObserver`),造成两层动效互相打架、显得卡顿廉价——这正是"过重"的典型表现,必须在设计阶段排除,而不是留到实现后才发现。

**解决方案**:新的滚动浮现动效只施加在 `<h3>`(小节标题,通常需要在当前页内向下滚动才能看到)上,**不施加在 `<h2>`(章节主标题)上** —— `<h2>` 的入场交给已有的 `pg-anim` 负责,两者分工不重叠。

## 3. 动效令牌(CSS 变量,单一数据源)

在 `assets/css/site.css`(供 9 个主题页共享)和 `index.html` 自身的 `<style>` 块中**各自定义、数值保持一致**:

```css
:root{
  --ease-breathe: cubic-bezier(.22,1,.36,1);
  --dur-enter: .7s;    /* 入场浮现时长,硬上限 .8s,不允许更长 */
  --dur-hover: .3s;    /* 悬停反馈时长,硬上限 .4s */
  --rise-enter: 16px;  /* 入场初始位移,硬上限 16px */
  --rise-hover: 3px;   /* 悬停位移,不做 scale */
}
```

后续任何新页面复用这套变量即可保持一致,不会有人"手滑"做过头。

## 4. 触发机制:新增 `assets/js/motion.js`

一个不依赖任何库的极简滚动浮现控制器(预计 30~40 行):

- 选中所有 `[data-reveal]` 元素
- 用 `IntersectionObserver`(`threshold:.15`,`rootMargin:"0px 0px -8% 0px"`)监听;元素首次进入视口时加 `.is-visible` 类触发 CSS 过渡,随后立即 `unobserve`——保证**只播放一次**,反复上下滚动不会重复触发显得廉价
- 页面加载时已经在视口内的 `[data-reveal]` 元素(例如首页 hero 标题),初始化时直接判定为可见并立即加 `.is-visible`,不必等一次假的"滚动进入"
- **无障碍**:若 `matchMedia('(prefers-reduced-motion: reduce)').matches` 为真,跳过所有 observer 逻辑,直接给所有 `[data-reveal]` 元素加 `.is-visible`(内容以最终态瞬间显示,不留空白、不等待)
- 通过 `<script src="assets/js/motion.js" defer></script>` 在 `index.html` 和每个 `topics/*.html` 中引入(主题页里跟在 `site.js` 后面即可,两者互不依赖)

配套 CSS(两处定义,数值来自第 3 节变量):

```css
[data-reveal]{opacity:0;transform:translateY(var(--rise-enter))}
[data-reveal].is-visible{opacity:1;transform:none;
  transition:opacity var(--dur-enter) var(--ease-breathe),
             transform var(--dur-enter) var(--ease-breathe)}
```

**初始化时机**:首页的主题卡片是由内联脚本 `TOPICS.forEach(...)` 在解析阶段同步渲染进 `#grid` 的。`motion.js` 必须在这段渲染脚本**之后**执行(用 `defer` 或直接放在渲染脚本下方的 `<script>` 标签),否则 `querySelectorAll('[data-reveal]')` 会在卡片插入 DOM 之前跑一遍,永远查不到卡片元素。

## 5. 应用清单

### 首页 `index.html`

| 元素 | 处理方式 |
|---|---|
| `.hero h1` / `.hero .tagline` | `data-reveal`,首屏立即播放(无需滚动) |
| `#quickref` 内的 pill(常用速查) | `data-reveal`,滚动进入时浮现,同批次内按序错开约 40ms(用内联 `transition-delay` 或 nth-child,封顶 5 个不再增加延迟) |
| `#grid` 内每张 `.topic` 卡片 | 卡片由 JS 动态渲染(`TOPICS.forEach`),渲染时加 `data-reveal`,按行错落 60ms 递增,封顶 5 张 |
| `.resume`(继续阅读卡片) | `data-reveal`,滚动浮现 |
| `#hot`(热门标签行)、`.results`(搜索结果)、`.searchbar` | **不动**——搜索相关,已排除在范围外 |

### 主题页 `topics/*.html`(9 个页面)

| 元素 | 处理方式 |
|---|---|
| 每个 `<section id>` 内的 `<h3>` | `data-reveal`,滚动进入当前页面内视口时浮现一次 |
| 每个 `<section id>` 的 `<h2>` | **不加**——已由 `pg-anim` 覆盖(见第 2 节) |
| 章节正文(`<p>`/`<ul>`/表格等) | **不加**——只提示"进入新小节",正文逐段动画会拖慢阅读,是明确要避免的"过重" |
| `#sidebar`、`#prog` 进度条、`#topBtn` 返回顶部、`.copy-btn`、灯箱、`.pager`(上一章/下一章) | **不动**——功能性 UI,不做入场动效 |

## 6. 交互态(hover),仅调整过渡曲线,不改变现有位移量

| 选择器 | 现状 | 改动 |
|---|---|---|
| `.topic:hover`(首页主题卡) | `transition:.2s`,`translateY(-3px)` | 过渡改为 `var(--dur-hover) var(--ease-breathe)`,新增轻微阴影扩散;**不加 scale**(网格内会挤压邻居) |
| `.learn:hover`(学习路径卡) | `transition:.18s`,`translateY(-2px)` | 同上,过渡曲线统一 |
| `.quickref a:hover` / 其它 pill/按钮/链接 | `transition:.15s` | 过渡改为 `var(--dur-hover) var(--ease-breathe)`,幅度不变 |
| 主题页内 `.tbl tr:hover`、`.hotcmd` 等既有悬停态 | 各自现有 `transition` | 统一换成 `var(--dur-hover) var(--ease-breathe)` |

不引入任何新的位移/缩放幅度,只统一"手感"(曲线),这是本次改动里最低风险的部分。

## 7. 无障碍与性能护栏

1. **`prefers-reduced-motion` 补缺口**:`index.html` 已有 `@media (prefers-reduced-motion:reduce){*{animation:none!important;transition:none!important}}`,但 `assets/css/site.css`(9 个主题页共享)**目前完全没有这条规则**——这是本次顺带修复的一个既有无障碍缺口,直接在 `site.css` 补上同款媒体查询。
2. 动画属性仅限 `opacity` / `transform`,不使用会触发重排的属性(`width`/`height`/`top`/`left`)。
3. 所有时长/位移数值封顶在第 3 节的 CSS 变量里,新页面照抄变量即符合规范。
4. `IntersectionObserver` 触发后立即 `unobserve`,每个元素动画只播放一次。

## 8. 涉及文件清单

| 文件 | 改动类型 |
|---|---|
| `assets/js/motion.js` | 新建 |
| `assets/css/site.css` | 新增动效令牌变量、`[data-reveal]` 基础样式、`prefers-reduced-motion` 规则、悬停过渡曲线统一 |
| `index.html` | 新增令牌变量(`<style>` 内)、引入 `motion.js`、hero 标题/quickref/resume 卡加 `data-reveal`、卡片渲染 JS 里加 `data-reveal` 与错落延迟、`.topic`/`.learn`/pill 悬停过渡曲线统一 |
| `topics/*.html`(9 个页面) | 引入 `motion.js`;为每个 `<h3>` 加 `data-reveal`(可脚本化批量处理,模式统一) |

## 9. 验收标准

- 首页刷新:hero 标题立即浮现,向下滚动时主题卡片按行错落浮现一次,再滚回顶部/来回滚动不重复播放
- 任意主题页:切换章节(点侧栏)时章节标题动效与现有 `pg-anim` 无叠加感;页内向下滚动到小节标题时,标题浮现一次
- 系统开启"减弱动态效果"(`prefers-reduced-motion: reduce`)时,首页与全部主题页内容均瞬间以最终态显示,无空白、无延迟
- 悬停任意卡片/按钮:反馈干脆,无弹性回弹,无因 scale 导致的网格错位
