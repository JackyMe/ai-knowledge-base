622:<h3 data-reveal>Roborazzi(Robolectric 路线,可集成 Hilt)</h3>
623:<p>由 takahirom 出品,基于 Robolectric 在 JVM 渲染 Compose,支持 <code>@Preview</code> 自动生成测试、与 Hilt 等 DI 框架无冲突。<strong>优势:可以测有依赖注入的真组件</strong>。</p>
624:<p>关键能力:</p>
626:  <li><code>captureRoboImage()</code> 给定节点截图</li>
627:  <li><code>generateComposePreviewRobolectricTests</code> Gradle 任务:扫所有 <code>@Preview</code> 注解,自动生成截图测试</li>
628:  <li>(实验)<code>roborazzi-ai-gemini</code> / <code>roborazzi-ai-openai</code>:用 AI 做"截图差异语义判定",能区分"故意改"和"误改"</li>
630:<p>关键 Gradle 任务:</p>
631:<pre><code>./gradlew :app:recordRoborazziDebug           # 录基线
632:./gradlew :app:verifyRoborazziDebug           # diff 模式
633:./gradlew :app:verifyAndRecordRoborazziDebug  # 边验证边更新基线(本地用)
634:./gradlew :app:compareRoborazziDebug          # 三个对比图叠看</code></pre>
636:<p>最妙的是它发了一个 <strong>Claude Code / Codex 可安装的 skill</strong>:</p>
638:<p>装上后,AI 编码代理遇到"加截图测试""调基线""看 Roborazzi 失败"这类问题会自动加载正确知识,不用你手把手教。</p>
1024:<h3 data-reveal>X2. Web 落地(Tailwind v4 × shadcn)</h3>
1025:<p>Web 侧"设计 Token 一等公民"过去三年的演进:<strong>Tailwind v3 config.js → Tailwind v4 <code>@theme</code> CSS 变量 → shadcn 语义 CSS 变量</strong>。v4 的意义在于 Tailwind 直接吃 CSS variables,不用 <code>tailwind.config.js</code> 那条路径。</p>
1027:<h4>① Tailwind v4 <code>@theme</code> 指令</h4>
1032:  /* 颜色(走 OKLCH 色彩空间更准) */
1037:  /* 字体 / 间距 / 圆角 */
1042:<p>关键变化:v4 的 <code>@theme</code> <strong>直接生成 utility class</strong>——<code>bg-brand-500</code> / <code>font-display</code> / <code>rounded-card</code> 都是它来的,不用再写 <code>tailwind.config.js</code>。三个进阶指令(对应 Compose Token 体系):</p>
1044:  <tr><th>指令</th><th>干什么</th><th>类比 Compose</th></tr>
1045:  <tr><td><code>@theme inline { ... }</code></td><td>Token 直接展开成 utility,不生成 CSS variable</td><td>(类似) <code>colorScheme.primary</code> 的"展开"模式</td></tr>
1046:  <tr><td><code>@theme static { ... }</code></td><td><strong>不允许覆盖</strong>,真正的"硬编码"</td><td>(类似) MaterialTheme 不可在运行时改</td></tr>
1047:  <tr><td><code>--*: initial</code></td><td>重置 Tailwind 默认 spacing / radius,把命名权交给你</td><td>全局重置到自家设计基线</td></tr>
1050:<h4>② shadcn 的"代码即设计"哲学</h4>
1051:<p>shadcn 不发 npm 包,你装的是<strong>组件源码</strong>(贴进 <code>components/ui/</code>),所以"改设计 Token" = 改源里的 <code>bg-primary</code> 那几个 CSS 变量。<strong>它和 Figma Variables 一一对应</strong>:</p>
1053:  <tr><th>shadcn CSS 变量</th><th>对位 Figma Variable</th><th>用途</th></tr>
1054:  <tr><td><code>--background</code> / <code>--foreground</code></td><td>surface / onSurface</td><td>容器底色 + 文字</td></tr>
1055:  <tr><td><code>--primary</code> / <code>--primary-foreground</code></td><td>primary / onPrimary</td><td>按钮、链接主色</td></tr>
1056:  <tr><td><code>--secondary</code> / <code>--muted</code> / <code>--accent</code></td><td>secondaryContainer / surfaceVariant / tertiary</td><td>次级容器 / 弱化 / 强调</td></tr>
1057:  <tr><td><code>--destructive</code></td><td>error</td><td>危险动作(删除、报错)</td></tr>
1058:  <tr><td><code>--border</code> / <code>--input</code> / <code>--ring</code></td><td>outline / outlineVariant / focus</td><td>边 / 输入框边 / 焦点环</td></tr>
1059:  <tr><td><code>--radius</code></td><td>shape.cornerMedium</td><td>全局圆角基准</td></tr>
1061:<p><strong>小心坑</strong>:shadcn 默认中性灰色调,<strong>品牌色直接覆盖 <code>--primary</code> 即可</strong>。不要去改组件源码里的硬编码颜色——下次 <code>shadcn add</code> 加新组件又会拉回默认。</p>
1063:<h4>③ Claude Code × Next.js / Vite 流水线</h4>
1064:<pre><code># 在项目根跑,Claude Code 就在这个 Next.js 项目里跑
1067:# 让它一次性把 Figma 转成 shadcn 组件:
1068:claude&gt; 用 Figma MCP 读这个 Frame:{URL},把 Frame 转成等价的
1069:       shadcn 组件(Button / Card / Dialog),不准硬编码颜色,
1070:       所有色走 :root 下的 --primary / --background 这套变量。
1071:       同时:1) 写 component.test.tsx(用 testing-library)
1072:            2) 写 visual.spec.ts(Playwright 自动截图)</code></pre>
1073:<p><strong>MCP 现状</strong>:shadcn 没发布官方 MCP,<strong>但其 CLI + Registry 本身就具备 MCP 般的"AI 友好"特性</strong>(每个组件都有可独立 import 的源码)。社区有零星 MCP 包装,质量未知。</p>
